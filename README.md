# AI 试手游戏

一个用 **Godot 4.7.2 / GDScript** 做的俯视角肉鸽地牢射击原型，由 AI 协作开发，用来试手玩法系统设计与工程流程。游戏内命名体系（见痕 / 残响 / 游魂 / 往生脉等）的世界观设定取自《六道卷》系列（自有）。

## 项目概况

- 引擎：Godot 4.7.2，单场景 `scene/game.tscn`，GDScript，**34 个脚本**
- 战斗与构筑：11 种房型（含抉择圣所）、9 枚地窖印记、7 种敌人编队、8 条反应词缀、4 件主动遗物、8 种楼层主题、3 位主题 Boss
- 局内变数：灾祸层、挑战因子、每日挑战、图鉴发现度被动
- 信息层：层签（主题 + 灾祸 + 本层房型概况 + 主题手记）、地窖低语、上局誓约回顾、圣所熟客手记
- 长线目标：通关后解锁**深渊难度档**（逐档解锁，t1..t10）
- 详细玩法见 [玩法说明.md](玩法说明.md)
- 各批规划、交付与核验文档见 `production/sprint-10` ～ `production/sprint-26`；主理人核验报告在 `production/` 根目录

## 工程约定

- 计时统一走 `Game.FIXED_DT`（1/60），核心循环不新增 `Game.rng` 消费
- 每批走「实施 → 四门控 → 冻结重定 → 交付文档 → 单独提交 → 读码核验」
- `meta.gd UNLOCKS` 属冻结规格 v2.11，不可改（升档经 S36 T-A 已裁条目授权）；局外内容一律平行只读派生
- 新资源走 `Assets.g()` 必须同步登记 `GEN_NAMES`（漏登记会得到静默空图标）
- **E1 确定性校验方法（两问两答，缺一不算答）**：`SMOKE_META_FINGERPRINT=1`，跑 12345/777/42 三档。①**漂移问**＝每档 `[SMOKE-META] fingerprint` 的 `rooms=`/`kinds=`（rooms 坐标 + kinds）**逐字等于 `production/sprint-32/SPR32_验证口径.md` §5.4 它自己那一行**（机检 `_tools/spr38_fp_vs_5_4.py` → `VERDICT=ALL_MATCH`）；②**种子生效问**＝三档指纹**互不相同**（distinct=3；地图走 `run_seed` 派生）。⛔ 断言「三档彼此逐字相等」＝恒不成立的判据；也 ⛔ 只拿 distinct=3 单独当 E1 通过依据。同 seed 只比对 `[SMOKE-META] fingerprint` 行，**不要拿整体日志 `cmp`** —— 日志含逐帧玩家坐标、敌人数量等实时抖动，必然不一致
- **E1 跨批对照禁用 `SMOKE_DAILY`**：daily 模式会用当日日期派生 seed 并**覆盖 `SMOKE_SEED`**，跨零点跑不可比
- **敌人数值缩放走隔离乘子**：`enemy_hp_mult`/`enemy_speed_mult` 会被挑战因子与楼层主题在运行时直接赋值覆盖，新批次若要叠加全局难度须另开乘子，不要复用

## 已知限制

- **冻结清单是工作树字节快照**，不是仓库归一化字节。`scripts/` 下 8 个文件为 CRLF（`assets` / `bullet` / `data` / `prop` / `secret_wall` / `slug` / `upgrade_panel` / `upgrades`）、26 个为 LF，无单文件内部混排。在 `core.autocrlf` 配置不同的环境 clone 后，这 8 行 md5 会对不上，属预期行为，不是文件被篡改
- **Boss 血量只接深渊档、刻意不接 `enemy_hp_mult`**：三位 Boss（`boss.gd` / `boss2.gd` / `boss3.gd`，同出 `PrismWarden` 骨架）走独立血量公式，**已折入** `abyss_hp_mult`——t=10 时血量 ×2.0，`SMOKE_ABYSS` 探针守着这条（`t=10（hp=2.00）warden/boss2 ×2.0`，`[ERR]`=0 即通过）。但**刻意不接** `enemy_hp_mult`：那是普通敌人的缩放（`slug.gd:86` 两者都接），接进 Boss 会动 E1 基线，属 P1 红线，`player.gd` 另有 `enemy_hp_mult=5.0` 的负对照断言把它锁死。所以在带 `enemy_hp_mult` 修正的局（如软弱 0.85）里 Boss 血量不受影响——这是刻意设计，不是遗漏，也不是「高难度档 Boss 偏易」
- 全量日志偶现 `Lambda capture at index 0 was freed`（0–4 条随机）。已用同 env 同 seed 交叉对照确认 **HEAD 基线同样出现**，属既有缺陷，与本批改动无因果
- 层签第二行的**主题手记**按 8 个楼层主题循环，第 9 层起文案会重复 —— 属文案量限制，不是逻辑缺陷。同一行的**本层房型概况**不受影响，房间数随楼层增长持续变化
