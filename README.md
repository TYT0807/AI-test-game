# AI 试手游戏

一个用 **Godot 4.7.2 / GDScript** 做的俯视角肉鸽地牢射击原型，由 AI 协作开发，用来试手玩法系统设计与工程流程。

## 项目概况

- 引擎：Godot 4.7.2，单场景 `scene/game.tscn`，GDScript，**34 个脚本**
- 战斗与构筑：11 种房型（含抉择圣所）、9 枚地窖印记、7 种敌人编队、8 条反应词缀、4 件主动遗物、8 种楼层主题、3 位主题 Boss
- 局内变数：灾祸层、挑战因子、每日挑战、图鉴发现度被动
- 信息层：层签（主题 + 灾祸 + 本层房型概况 + 主题手记）、地窖低语、上局誓约回顾、圣所熟客手记
- 详细玩法见 [玩法说明.md](玩法说明.md)
- 各批规划、交付与核验文档见 `production/sprint-10` ～ `production/sprint-18`

## 工程约定

- 计时统一走 `Game.FIXED_DT`（1/60），核心循环不新增 `Game.rng` 消费
- 每批走「实施 → 四门控 → 冻结重定 → 交付文档 → 单独提交 → 读码核验」
- `meta.gd UNLOCKS` 属冻结规格 v2.10，不可改；局外内容一律平行只读派生
- 新资源走 `Assets.g()` 必须同步登记 `GEN_NAMES`（漏登记会得到静默空图标）
- **E1 确定性校验方法**：同 seed 只比对 `[SMOKE-META] fingerprint` 行（rooms 坐标 + kinds）。**不要拿整体日志 `cmp`** —— 日志含逐帧玩家坐标、敌人数量等实时抖动，必然不一致
- **E1 跨批对照禁用 `SMOKE_DAILY`**：daily 模式会用当日日期派生 seed 并**覆盖 `SMOKE_SEED`**，跨零点跑不可比

## 已知限制

- **冻结清单是工作树字节快照**，不是仓库归一化字节。`scripts/` 下 8 个文件为 CRLF（`assets` / `bullet` / `data` / `prop` / `secret_wall` / `slug` / `upgrade_panel` / `upgrades`）、26 个为 LF。在 `core.autocrlf` 配置不同的环境 clone 后，这 8 行 md5 会对不上，属预期行为，不是文件被篡改
- 全量日志偶现 `Lambda capture at index 0 was freed`（0–4 条随机）。已用同 env 同 seed 交叉对照确认 **HEAD 基线同样出现**，属既有缺陷，与本批改动无因果
- 层签「本层形势」在 8 层以后不再有新信息（`SQUADS` 最大 `min_floor` 为 7 留下的同类问题已由房型计数绕开，此项仅指主题手记 8 层一循环）
