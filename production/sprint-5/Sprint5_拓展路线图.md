# Sprint 5 拓展路线图 · 《源石虫清剿战》还能往哪扩

> 日期：2026-11-05
> 评估方式：**主理人只读分析**。原计划的设计侧 / 技术侧两条评估线因 429 配额限流未跑成，本报告由主理人直接完成，所有结论均基于实读代码与本项目实跑数据，未代成员发言。
> 基线版本：SPR4-FROZEN-1

## 一、诊断结论

游戏的**内容量已达"完整小品"水位，但还停在"单局体验"阶段**：横向的房 / 怪 / 词缀 / 因子已经很厚，**纵向的"成长曲线"和"构筑深度"只有一层**。

再堆同类内容（再加 10 种怪）边际收益很低；真正的下一段增长来自三件事：**让升级之间产生协同**、**让 4 层以上不再重复**、**给局外留一条 meta 线**。

## 二、内容密度盘点与对标

| 维度 | 当前 | 以撒（Repentance） | 元气骑士 | 挺进地牢 | 定位 |
|-|-|-|-|-|-|
| 房间类型 | 10 | ~15 | ~10 | ~10 | 达标 |
| 敌人种类 | 28 | ~90 | 60+ | ~40 | 约 1/3 |
| 敌人行为（AI） | 8 | 数十种 | 十余种 | 十余种 | **偏少** |
| 道具 / 升级 | 14 升级 + 10 遗物 | 719 | 数百武器 + 配件 | 200+ 枪 | 约 1/5 |
| 武器 | 4 | 34 角色 × 数百 | 数百 + 可合成 | 200+ | 约 1/10（但可合成＝质变） |
| Boss | 4（3 层 + 兜底） | 100+ | 每章数个 | ~30 | 约 1/10 |
| 楼层变化 | 3 层后完全重复 | 每层独立池 | 每主题独立 | 每层独立 | **最弱项** |
| 局外 meta | 无 | 解锁树 | 角色 / 武器蓝图 | 永久升级 | 无 |

素材：generated 47 张 + monsters 21 张 = 68 张；代码 5365 行（`game_main.gd` 1281 行为最大单文件，占 24%）。

**结论**：横向内容约为头部作品的 1/3～1/5，纵向（层数变化、meta、构筑协同）接近空白。继续堆"同类内容"性价比最低。

## 三、结构性缺口（不是"再加一种怪"）

1. **构筑没有协同**：14 升级 / 10 遗物全是独立加数值（伤害 +30%、移速 +12%…），拿 5 件也只是 5 个数字变大。以撒的核心是"形态 + 修饰"叠出质变（激光 × 分裂 × 追踪 = 会拐弯的多道激光）。本项目已有现成载体：**源石共鸣**（Sprint 4）已是"层数 → 爆发"的雏形，把它长成"标签 + 套装"是自然延伸。
2. **4 层之后内容完全重复**：`FLOOR_POOLS` 只到 3 层、4 层起走 `FLOOR_POOL_FALLBACK`；`ELITE_BY_FLOOR` / `BOSS_BY_FLOOR` 同样只到 3 层，4 层起固定 beholder + dragon。层数无上限，但玩家打到第 4 层就再没有新东西了。
3. **没有局外 meta**：单局结束源石、升级、遗物全清零，没有解锁树 / 蓝图 / 永久强化。肉鸽"下局更有劲"的动机链是断的。
4. **敌人 28 种只有 8 种 AI**（chase / spitter / bomber / boss / leap / summon / erratic / turret）：多数是换皮 + 数值差异，玩家辨识不出"这只和那只不一样"。缺"组合行为"（护盾怪配召唤怪成组出现）。
5. **4 个 Boss 机制趋同**：都是冲锋 + 弹幕 + 召唤，缺机制型 Boss（分阶段换场地、必须打弱点、半场地出怪）。
6. **没有事件 / 叙事 / NPC 交互**：商人只有买卖，缺事件房（二选一抉择）、雕像 / 祭坛。
7. **没有难度选择 / 挑战模式 / 每日种子**：因子是"每局一条规则"，但没有难度档（密度 / 血量曲线 / 资源）与每日同种子榜。
8. **武器没有形态分化**：4 把枪参数差异清晰，但没有配件 / 铭刻，也没有合成。参数表已经做得很干净，加配件几乎零成本。

## 四、技术瓶颈（扩展成本实测）

本轮亲手改过这些文件，以下数字是实打实的：

| 新增内容 | 改动点 | 静默失效点 |
|-|-|-|
| 1 种敌人 | 3 处：`data.gd` 条目 + 贴图 + `assets.gd:MONSTER_NAMES` 登记 | 忘登记 → `Assets.monster()` 返回 null → 怪不显示且**不报错** |
| 1 种 AI | 3 处：`slug.gd` `_ai_xxx` + `_physics_process` match 分支 + `validate.KNOWN_AI` | 忘加 validate 白名单 → 自检不报；match 漏分支 → 行为静默不生效 |
| 1 种升级 | 2 处：`upgrades.gd` POOL + `apply()` match 分支 | **忘 apply 分支 ＝ 抽到卡没效果**（本轮已用 default 分支堵住） |
| 1 种房间 kind | **10 处契约** | 大部分静默：看不见 / 炸不开 / 不进房（本轮刚踩过） |
| 1 种武器 | 4 处：`weapons.gd` 条目 + 贴图 + `GEN_NAMES` + validate | 忘 GEN_NAMES → 白图（本轮踩过） |
| 1 个 Boss 机制 | 3 处：`slug.gd` `_ai_boss` + `game_main` boss 房 + `data.gd` 分配表 | Boss 机制差异不会报错 |

**四个架构瓶颈**：

1. **`match` 硬编码泛滥**：房间 kind / 升级 apply / AI / 词缀 / 因子全是 `match` 分支。房间 kind 要 10 处契约，根因就在这里 → 可抽象为"数据表 + 策略表"。
2. **资源清单硬编码**：`assets.gd` 的 `GEN_NAMES` / `MONSTER_NAMES` / `ICON_RECTS` 三张手写表，新增资源必须手动登记（本轮两次踩坑）→ 可改为目录扫描。
3. **没有存档层**：`game_state.gd` 只存局内状态，没有序列化能力。这是 meta 进度、每日挑战、成就三者的**共同前置**。
4. **`game_main.gd` 1281 行**：地牢流转 + 刷怪 + 爆炸 + 结算 + SMOKE 挂具全塞在一起，继续加功能会失控 → 至少拆出 `floor_manager` / `spawner` / `reward`。

**重构依赖链**（文字版）：

```
meta 进度      → 需要存档层（Game 序列化）→ 需要玩家状态快照（升级/遗物/源石清单）
武器配件/铭刻  → 需要「形态 + 修饰」数据模型 → 需要升级/遗物标签体系
楼层主题       → 需要关卡生成支持主题参数 → 需要把 Data 的层配置外置
事件房         → 需要抉择式 UI → 需要新面板组件（可参考 upgrade_panel.gd）
资源自动登记   → 需要目录扫描 → 需要 assets.gd 改为运行时枚举
```

## 六、明确「不建议做」

1. **联机**：单机肉鸽没有确定性同步基础，投入产出比极低。
2. **继续按数量堆敌人 / 武器**：28 种敌人只有 8 种 AI，再加 20 种仍是换皮，玩家感知不到差别——先补 AI 与组合行为比加数量值划算。
3. **装备耐久 / 背包管理**：俯视角即时射击没有背包概念，做了反而拖节奏。
4. **多层大地图**：9 宫格一层的结构已验证好用，扩大到 20×20 会让"找隐藏房"变成苦差。

## 七、如果只再做 3 件

| 顺位 | 项 | 一句话理由 |
|-|-|-|
| 1 | **A1 升级标签 + 套装** | 直接补上"构筑无协同"这个最大结构缺口；载体（共鸣）已铺好，边际成本最低、玩家感知最强 |
| 2 | **A2 楼层主题（4 层起）** | 修掉"3 层后完全重复"，把无限层数从数值爬坡变成每层有新东西 |
| 3 | **B1 局外 meta 进度** | 唯一能同时解掉"没解锁动力"和"重复刷"的系统级改动；但需先有存档层，建议拆成「存档层」与「解锁内容」两步 |

**建议节奏**：下轮做 A1 + A2（设计侧素材够、不需要重构、可在 1 轮内跑完并自测），同一轮顺带摸好存档层的地基（只做序列化接口、不做 UI），下一轮做 B1。

## 八、验证前提

任何一项落地都必须自己跑游戏验证到 0 报错（六种子 × 9000 帧 + 死亡链路 + RG-6 / RG-7 + 窗口截图），否则一律视为不通过。路线图里标 M / L 的项建议单独立项、各自冻结版本与哈希。
