## 0. 结论先行（六条，先给判断再给证据）

1. **S40 已经把「骨架」落地了，S41 只做「肉」**。现读盘上事实：`RAISE/PARRY/BLOCK` 三层谓词在 `player.gd:813-825`，完美窗是**整型帧计数** `const PARRY_FRAMES := 12`（`:128`）、冷却闸 `const PARRY_HIT_CD := 6`（`:129`）三态承载 C2 归属；`_settle_parry()`（`:868`）**只数不加伤害**，注释明文「返还表…**不在本批**」；`_swing()`（`:730`）的第二条扫描已经会扫弹并记 `bullets_swept`／`last_sweep_count`（`:799-800`）。⇒ **S41 的增量恰好落在三个空位上**：①盾反的**回报与惩罚**（今天成功和失败都只是「不受伤」，没有正向收益、也没有代价分档）；②**清扫的手感反馈与连携**（今天扫掉了弹，玩家只知道 hp 没掉）；③**剩余武器族的去火药化收尾**（`th_kunai`／`wd_whisper` 两条仍走弹道语义）。
2. **盾反的分档不做「按敌人种类」，做「按弹的物理属性」**。理由不是省事：项目里敌弹的唯一生成入口 `spawn_enemy_bullet()`（`game_main.gd:3953`）只有 `speed/dmg/tint` 三个可变参数，**没有任何「来源类型」字段**，而 §4.1 那张 T_* 表要区分的是「直射／扇形／环形／重弹」——那四种在代码里的可观测差别就是**同帧到达的颗数**与**这颗弹的 dmg**。⇒ 分档判据一律取 `(同帧盾内到达颗数, b.dmg)` 两个现读量，⛔ 新增「弹的类型」字段（`bullet.gd` 参位红线，S40 §0.1 同源）。这条同时给出一个强机检：**返还档位＝f(颗数, dmg) 的纯函数，可用一条断言表逐一钉死**。
3. 🔴 **返还弹一律零主流抽取**，并把这条从「口头纪律」升级成**门控**：S40 §4.2 末已经裁定「盾反返还弹一律 `crit=false`、零抽取」，但今天没有任何东西守着它。S41 立一条运行期探针判据：**整次盾反（含返还弹生成）前后 `Game.rng.seed` 与 `Game.rng.state` 逐字相等**。这是本批最重要的一条防退化——因为返还弹走的是 `spawn_player_bullet()`，一旦有人图省事在里面顺手抽 crit，主流位置就漂，E1 指纹全红，而且**静态门抓不到**（那是运行期行为）。
4. **返还物用「朱砂笔痕迹」这一个模板起步，⛔ 一上来铺满六格**。S40 §4.2 给了七行表，其中 `T_RING`／`T_HEAVY`／`T_MELEE` 三行的实现分别要额外消费 `explode()`、`apply_slow`、`apply_stun`，而**拼刀那一行是我超出作者原话的推演**（S40 §7 C4 至今未裁）。⇒ S41 只落 `T_DIRECT`＋`T_FAN` 两档（同一套返还物、只差颗数），其余档位**登记为欠件**，等 E1/E2 答复。这样做的真正好处：先把「返还弹不吃主流、不进存档、不改指纹」这三件事用最小面积证一遍，再扩表。
5. **清扫连携不引入新键、不引入新资源**。作者要的是「近战清扫漂浮弹幕」这件事**被感知到**，不是多一套系统。⇒ 连携只做两件事：①**刃风余韵**＝一次挥击扫到的颗数决定这一刀之后的**极短**准头加成（纯表现层乘区，⛔ 进存档、⛔ 抽主流）；②**归因显示**＝HUD 常驻行加一格「本次刃风扫落 N」（只在有扫落的 0.6s 内出现）。两者都挂在已有的 `last_sweep_count` 上，零新持久状态。
6. **去火药化的收尾是「语义收尾」而不是「机制改造」**。`th_kunai`（三枚锥）／`wd_whisper`（低语法杖）今天在 DEFS 里保留弹道参位是**有意的**（`weapons.gd:262-263` 注释：它们是参数变体，不是新命中真身）。⇒ ⛔ 把它们改成 melee（那是方向级变更，牵 `[S38-A3]` 的六个禁参位与全部 dps 门）；✅ 只改**名字／desc／图标语义**与文案里的「掷／射／膛」类动词，让它们读作「御物」「符纸」而非「暗器枪械」。这条要不要走到机制层＝**E4 待裁**。

## 3. (A) 盾反分档：回报与代价

### 3.1 档位判据（🔴 纯函数，两个现读输入，⛔ 新字段）

```
档 ⟺ (k, b.dmg)，其中 k ＝ 本次 RAISE 期间【同一物理拍内】进入盾内判定范围的敌弹颗数
                 b.dmg ＝ 那颗弹自己的伤害值（float，现读 bullet.gd:10）

档位表（口径；数值列全部标「待裁 E1/E2」）：
  G1 轻档   k == 1 ∧ b.dmg <  HEAVY_DMG_MIN        → 返还 1 发「还一手」
  G2 扇档   k >= 2 ∧ b.dmg <  HEAVY_DMG_MIN        → 返还 min(k, RETURN_COUNT_CAP) 发，角度均分自来弹扇
  G3 重档   b.dmg >= HEAVY_DMG_MIN                  → 返还 1 发 + 对命中者 apply_stun(STUN_PARRY_SHORT)
  G4 环档   k >= RING_K_MIN ∧ 同帧                  → 本批不做（欠件，等 E1）
```

- 🔴 `HEAVY_DMG_MIN` 必须是**一个常数**、单一真源，⛔ 两处各写一个数。现读参照：敌弹实际 dmg 取值集合目前只有 `{1.0, 2.0}`（`slug.gd:180/277/426` 三处调用），所以**任何 >1.0 且 ≤2.0 的阈值都能把今天的内容正确二分**；这正是需要作者点头的地方（E1）——阈值定在哪，决定了将来加 1.5 伤弹时它算轻还是算重。
- `k` 的算法必须与 H3 的既有优先级共存：`_parry_hit_cd>0` 时后续弹走 BLOCK（不当 k 的一部分），否则「八向环」会把 k 撑成 8 并触发扇档返还＝白嫖。⇒ **k ＝ 本次 RAISE 内实际走了 PARRY 分支的颗数**，在 `_settle_parry()` 里就地累加，⛔ 另起一个「同帧计数」的全局统计。
- ⛔ 用「敌人 variant」或「武器 id」当档位输入：H8 说明敌弹没有来源身份，硬造就要么加持久字段（违反 S40 §3.2 的「⛔ 标记位」）要么维护一张来源表（双账）。

### 3.2 返还弹的构造（🔴 逐字口径，含四条硬约束）

- 模板＝`zhushan` 的 DEFS 现值（`weapons.gd:31-38`：`speed 250.0 / tint Color(1.0,0.62,0.25) / icon wpn_zhushan`），⛔ 为盾反新造一套伤害常量（S40 §4.2 原文照守）。
- 方向＝`-b.vel.normalized()`（回指来路），与 `_shield_spark()`（`player.gd:890-893`）的 flip 取号口径同源；起点＝`b.global_position`（在弹原来的位置冒出来，⛔ 从玩家身上发射——那会让玩家看到「盾口吐弹」的错误归因）。
- 伤害＝`float(b.dmg) * RETURN_MULT * damage_mult * bullet_dmg_mult`，取整口径**照 `_settle_block()` 的 `int(float(raw)*BLOCK_MULT)`**（H5），允许截断到 0，⛔ `maxi(1,…)`。
- 🔴 四条硬约束：①`crit=false, crit_boom=false`，整条路径**零 `Game.rng` 消费**（视觉走确定性算术或 `fx_rng`）；②⛔ 修改 `Bullet.setup()` 的参数位；③返还弹**不进任何计数以外的持久状态**；④返还弹是 `friendly=true` ⇒ 它天然不满足 `is_sweepable()`（该函数第一条件就是 `not friendly`），⛔ 在探针里再抄那七个条件（M-5 唯一豁免＝函数本体）。
- 上限保护：`RETURN_COUNT_CAP`（推荐 3）——防止极端同帧（理论上可达 8+）一次吐出八发把 dps 门打穿。这条本身就是 §8 E1 的一个子项。

### 3.3 失败惩罚「贪手」（皆代价的落点，数值＝E1/E2）

设计意图：今天的盾反是**纯收益零风险**——完美窗内成功＝免伤，失败＝退化成 BLOCK 也只是减伤。这不符合母题，也让「按早按晚」没有区别。裁定加一档**可感知的代价**，但严格限制在三条之内：

```
P-a 硬格（BLOCK）本身已是代价：受伤 ×BLOCK_MULT（H5，现值 0.5 占位）→ 本批不动
P-b 贪手：一次 RAISE 内【盾反成功后又在同一次架式里挨了一发未格的弹】
          → 该次受伤 ×GREED_MULT（>1，候选 1.5／2.0），并记 parry_greed_count += 1
P-c ⛔ 任何形式的「缴械／切枪／丢弹匣」：那改变资源模型，属方向级（同 S40 C5 的量级）
```

- 🔴 P-b 的实现**只能读已有的 `_parry_hit_cd` 三态**（H2）：`>0` 表示刚盾反成功、此窗内后续弹走 BLOCK。所以 P-b ＝「`_parry_hit_cd>0` 期间那次 BLOCK 结算」乘 GREED_MULT，**零新状态**。这是我最满意的一点：惩罚不需要新变量。
- ⛔ 让贪手影响 `shield_absorbed_dmg` 的记账口径（那是「挡下来多少」的账，乘上去会让 auditor 的对账面自己跟自己打架）。
- 边界态必测：同一次 RAISE 里「PARRY→BLOCK→PARRY」序列是否可能？答案是不能（`_parry_hit_cd>0` 期间一律 BLOCK，直到冷却走完），写成断言。

## 4. (B) 清扫的手感与连携

### 4.1 现状缺的是什么（一句话）

H7 说明**机制已经成立**（扫得到、有计数、有迸星），缺的只有**反馈**与**为什么我要主动用它**。当前玩家的最优解仍然是「一直开枪」，因为挥刀扫弹除了安全之外不给任何东西。

### 4.2 刃风余韵 `sweep_flow`（我裁结构，数值待裁 E3）

```
触发 ⟺ 一次 _swing() 的清扫段 swept >= SWEEP_FLOW_MIN（候选 1／2）
效果 ：此后第一次玩家开火的散布乘 ×SPREAD_MULT（候选 0.5／0.0）
       ——×0.0 ＝「这一发完全干净」，是最爽的读法；×0.5 保守
存续 ：一次开火即消耗；⛔ 跨房间残留；⛔ 换武器不清（同一次挥击的因果不该被切枪打断）
      超时 ：SWEEP_FLOW_T（候选 0.6s／1.2s）后自然失效，⛔ 无限期挂着
```

- 🔴 载体是一个**非持久**计时位（`var _sweep_flow_t := 0.0`，实例级、⛔ `static`、⛔ 进存档、⛔ 进 E1 指纹串，与 H6 同一把尺）。递减走 `FIXED_DT`（S40 §3.1 原文：⛔ raw delta、⛔ `Engine.time_scale`、⛔ `create_timer()`）。
- 🔴 生效点在**散布**不在伤害：`_fire()` 的抖动是 `offset_deg += Game.rng.randf_range(-1.5, 1.5)`（现读 `player.gd:708`，且它只在 `n == 1 and not autopilot` 那一支里发生），余韵把它乘下去 ⇒ **抽取次数一字不变**，只改取值范围。这条很关键：如果做成「暴击率加成」就必须再抽一次主流（同函数 `:710` 那次 `randf() < crit_chance` 已经是唯一真源），当场破 §0.3 的门控。
- ⛔ 让近战自身吃这个加成：余韵**只对 `_fire()` 那条弹道路生效**（projectile/throw/wand），⛔ 给 `_swing()` 的伤害或扇形加任何乘区。理由有两条：①近战没有散布，"准头变好"对它无可观测内容；②如果做成近战伤害加成，就等于把 S38 `[S38-A3]` 那张 dps 门基线重新掀开（数值口径变更＝作者保留权）。⇒ 验收侧的反向断言写成「有余韵时挥一刀，`_ml_stats()` 那套乘区读数与无余韵时逐字相等」，而不是含糊的"不受影响"。
- 反馈面：扫落瞬间 HUD 常驻行显示「刃风扫落 N」（N 取 `last_sweep_count`，H6 已有），0.6s 后消失；余韵生效那一发，迸星颜色比平时亮一格（纯 `modulate`，⛔ 新贴图）。⚠️ 视觉硬指标（字号/时长/颜色）＝**E6**，我不替作者定像素。
