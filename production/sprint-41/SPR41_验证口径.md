## §1 A 组（🟢 本轮验收就看这一段）

**V-A1 盾反路径零主流抽取**
- 判据：`[SMOKE-PARRY]` 新增面里，每次 PARRY／BLOCK 结算之后各有一行 measured 形如 `rng=(<seed>,<state>)`，其值与该面开头的基线值**逐字相等**。
- 基准值：起手基线 = `_PD_STATE0 := 20261119` 对应的 seed/state 对（现读 `game_main.gd:5768`）。⛔ 用"看起来没变"代替逐字比对。
- 覆盖度：至少 ①单次 PARRY ②同一次 RAISE 内连续 3 次 PARRY ③一次 BLOCK 三种姿势各一条。
- 边界态：返还弹已落地时（🟡），同一面须额外覆盖「`spawn_player_bullet` 被调用那一拍后仍逐字相等」。
- 🔴 **自证要求（不是绿就行）**：临时在 `_settle_parry()` 里加一行消费主流抽取的语句，重跑，**必须出现 ok=false 的行**；随后精确还原并给出字节级比对结论。缺这一红一还原的证据 ⇒ V-A1 记 UNVERIFIED，不算过。

**V-A2 探针自校验数一致**
- 判据：末行 `[SMOKE-PARRY] done checked=N declared=M`，N == M，且 M 是改动后的实数（不是旧值 70）。
- 基准值：改前 N=M=70；改后 N=M=<新实数>。**报告里必须写出这个新数**，我不接受"+9"这类推算值——我自己会再数一遍展开后的行数。
- 边界态：若某前置不成立（例如 player 为 null），首行必须是 `UNEXECUTED done checked=0 declared=M` 而非静默通过（现读 `game_main.gd:5797` 已有该形状，⛔ 改掉它）。

**V-A3 A-2 的零行为变化**
- 判据：把签名改成 `_settle_parry(b, k)` 之后单独跑一趟，`[SMOKE-PARRY]` **存量各行**（P1~P7 那批）的 measured 列与改前基线**逐字相同**；差异只允许出现在新增面上。
- 基准值：`parry_count`/`block_count`/`shield_absorbed_dmg` 三个 static 计数器的差值与改前一致；`hp` 终值一致。
- ⚪ 反向：生产码里 `grep -n "func _settle_parry"` 的函数体仍是四行语义（计数、置冷却、迸星、free），⛔ 提前出现任何生成弹的动作。

**V-A4 档位输入的定义唯一**
- 判据：新增注释包（可 `grep -a` 取到）里必须出现这句的关键片段：**「k ＝ 本次 RAISE 内实际走了 PARRY 分支的颗数」**；且 ⛔ 同时存在第二处对 k 的不同定义。
- ⚪ 反向（关键的一条）：摆一个八向环（8 颗同帧入盾）⇒ 同拍真形＝**1 颗走 PARRY＋1 颗走 BLOCK（`_parry_hit_cd>0`）＋6 颗本拍不处理（`_parry_hit_cd<0` 冷却未就绪）**，因此 k 只能等于 1（S41 P-K8 #82 实测 `measured=1/2/6`，凭据 `_tools/spr41_a2/s41_k8_face_lines_t4.txt`；旧表述「其后 7 颗全部走 BLOCK」由 R76 §E 作废）。这条如果测出 k==8，说明档位输入被写成"同帧敌弹总数"，白嫖扇档，直接判不合格。

**V-A5 全局门不退化**
- validate `problems=0`；每条探针 `done checked=N declared=N`；`[ERR]` 行数 0；`ok=false` 行数 0；E1 指纹（`SMOKE_META_FINGERPRINT=1`）逐字不漂移；churn 只比断言行且钉种子。
- 基准值：与 `_tools/spr41_baseline_pre.txt`（P-2 那次现算）对照。

## §2 B 组（🟡 E1/E2 答复并落地后才跑）

**V-B1 档位是纯函数**
- 判据：一张实测表，每行 `(k, b.dmg) → 档位 → 返还颗数 → 返还伤害整数`。给定同样输入两次，输出必须完全相同（⛔ 任何随机参与）。
- 基准值（以 E1 答值回填，本件先给形状）：
  - `(1, 1.0)` → G1 → 1 发 → `int(1.0 × RETURN_MULT × damage_mult × bullet_dmg_mult)`
  - `(3, 1.0)` → G2 → `min(3, RETURN_COUNT_CAP)` 发
  - `(1, 2.0)` → G3 → 1 发 ＋ 一次 stun
  - `(8, 1.0)` 同帧 → 依 V-A4，k 恒 1 → G1（这是回归闸，不是新档）
- ⚪ 反向：乘区测试须在 `_ml_stats()` 归零态（damage_mult=1.0/bullet_dmg_mult=1.0，现读 `game_main.gd:4852-4853`）跑，⛔ 拿 SMOKE 默认 dev 火力钩子（`bullet_dmg_mult` 被拍到 10.0/50.0，`game_main.gd:249/254`）下的读数当基准。历史上这坑踩过（`game_main.gd:4848` 的原注释就在守它）。

**V-B2 返还弹的构造可核对**
- 判据：返还弹生成瞬间抓一条 `RETURN pos=(x,y) dir=(dx,dy) speed=S tint=T dmg=D crit=false`。
  - `dir` 必须与被盾反那颗的 `vel` 反向（逐字：`dir == -b.vel.normalized()`，容差 1e-6）。
  - `pos` 必须等于被盾反那颗的 `global_position`，⛔ 等于玩家位置。
  - `speed`/`tint` 必须等于 `zhushan` DEFS 现值（250.0 / Color(1.0,0.62,0.25)），⛔ 出现新常数。
- 边界态：来弹 `dmg < 1/RETURN_MULT` 时 `int(...)` 截断为 **0** 是**正确**结果，⛔ 报"返还无伤害"为缺陷，⛔ 用 `maxi(1,…)` 掩盖。

**V-B3 Boss 免控是真的免疫**
- 判据：对 Boss 打一次 G3 盾反，前后读 Boss 的 `_stun_t`（或等价观察面）⇒ **不变**；同时 `apply_stun` 调用点确实被走到（用日志或计数器证明"调用了但无效"，⛔ 用"没调用"来解释现象）。
- ⚪ 反向：`boss.gd` 的空 `apply_stun`（现读 `:331`）未被"修好"；相关源级断言仍绿。

**V-B4 免伤表达方式不变**
- ⚪ 判据：全仓 ⛔ 出现 `take_damage(0` 作为盾反免伤手段（`player.gd:867` 原注释的理由）。静态面 grep 命中即红。

## §3 C 组（🟡 贪手，等 E2）

**V-C1 惩罚零新状态**
- 判据：`GREED_MULT` 生效的那次 BLOCK，受伤量 == `int(float(raw) * BLOCK_MULT * GREED_MULT)`（或与实稿 §3.3 最终裁定的复合式逐字一致），且实现里 ⛔ 新增任何 `var`（只准读已有的 `_parry_hit_cd` 三态）。
- 基准值：E2 答 1.5 ⇒ raw=3 时 after 由 1 变 2（含既有深渊倍率链路的读数要单列，⛔ 混在一条 measured 里）。

**V-C2 记账面不被污染**
- ⚪ 判据：`shield_absorbed_dmg` 的增量 == `raw - int(raw*BLOCK_MULT)`（**不含** GREED_MULT），与贪手是否触发无关。
- 理由写在这里供未来的人核：那是"挡下来多少"的账，乘惩罚倍率会让 auditor 对账面自相矛盾（实稿 §3.3）。

**V-C3 序列不可能性**
- 判据：一次 RAISE 内构造 `PARRY → (冷却期内) BLOCK → 想要再一次 PARRY` ⇒ 第三次结算必须落 BLOCK 或正常受伤，⛔ 落 PARRY。测得第二次 PARRY 即判不合格（说明 C2 三态被我理解错，需回炉裁定）。

## §4 D 组（🟡 余韵，等 E3）

**V-D1 抽取次数守恒（最重要）**
- 判据：同一种开火姿势（`count==1`、非 autopilot），**有余韵**与**无余韵**两种状态下，`Game.rng.state` 的前进量相同（即消耗同一次抽取），只有取值范围不同。
- 基准值：现读散布抖动是 `randf_range(-1.5, 1.5)`（`player.gd:708`）。E3 答 `SPREAD_MULT=0.0` ⇒ 有余韵时 offset_deg 恒等于扇形基准值（±1e-9）；答 0.5 ⇒ 绝对值 ≤ 0.75。
- ⚪ 反向：`count>=2` 那一支本来就不抖（`:707` 的条件），⛔ 让余韵给它引入新的抽取或新的偏移。

**V-D2 一次开火即消耗**
- 判据：扫到 ≥`SWEEP_FLOW_MIN` 颗 → 开第一枪（干净）→ 开第二枪（恢复正常散布）。用两枪的 offset 实测值证明"只有第一枪受益"。
- 边界态：超时失效（`SWEEP_FLOW_T`）与消耗失效两条路各自独立测；⛔ 只测其中一条就宣称另一条也对。

**V-D3 近战不吃余韵**
- ⚪ 判据：有余韵时挥近战一刀，`_ml_stats()` 返回的各乘区读数与无余韵时逐字相等；`_swing()` 内不出现对 `_sweep_flow_t` 的读写（静态 grep 判据）。

**V-D4 不跨房残留**
- 判据：拿到余韵后不射击、直接切房 → 新房内第一枪恢复正常散布；`_sweep_flow_t` 读数为 0。
- ⚪ 反向：复位点必须与既有过房复位同处，静态判据＝全仓对 `_sweep_flow_t` 赋 0 的位置 ≤ 2 处（消耗＋过房），第 3 处即"另起一套复位"，判不合格。

**V-D5 非持久**
- ⚪ 判据：存档序列化面、图鉴面、E1 指纹串三处均 ⛔ 出现 `_sweep_flow_t`／`parry_greed_count`／`_borrow_*`。判法＝保存→读档→E1 指纹逐字不漂移（这条一旦漂就是踩了作者保留权④，须停下呈报而不是接受新指纹）。

## §6 通用卫生条款（每一车都适用）

1. **锚句存活**：任何靠字符串锚住实现的探针/变异刀，起手须对每个锚句断言 `count(anchor)==1`，否则打印 `S41-ANCHOR-DEAD` 并非零退出。理由：md5 靶管得住宿主字节，管不住锚句语义（S40 R70 §D-2 的教训）。
2. **失败态证据不得被覆盖**：造错的 stdout 追加保存；临时件删除前在台账点名删了什么、留下哪几段。
3. **不许改断言凑绿**：门控与实现冲突时，报给我裁（改口径/改断言/改实现三选一），⛔ 自行降级判据或复制 oracle 副本（S40 净化门槛那行今天已有 3 份拷贝，再加就是 4 份假绿风险）。
4. **数值必须现算**：文档里引用的任何 checks 数、行数、md5 前 8，必须由当场执行得出；⛔ 从上一份文档抄。附带永久条款（R70 §B）：**任何绝对行数结论必须同时给出加数清单**。
5. **停等不等于漏做**：§2~§5 的 🟡 条目在未获作者答复前"不存在"是合规状态，⛔ 为了报告好看而提前实现。
6. **文档指纹的两条硬规矩**（V-F0）：①交付件落盘后 CR 字节数必须为 0（纯 LF），报告里附现场跑出的 `CR=/LF=` 两个数；②⛔ 在任何文档正文里写「本件自身的 md5／行数」——现值只准出现在终端回显与台账 append 行（台账在被引用件之外，不构成自指）。判法＝对成品抽出全部 `` `([0-9a-f]{8})` `` 串与本件现算 md5 比对，命中即红。
