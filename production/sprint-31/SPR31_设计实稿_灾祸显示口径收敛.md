## 2 口径总则：三种来源，只准用第三种

| 来源 | 例子 | 判定 |
|---|---|---|
| A live 字段 | `Game.calamity_speed_mult` / `player.mag_cap_mult` / `diamond_mult` | ❌ 现行 bug；会被 clear、toxic tick、主题重建污染 |
| B 名义比例 | `_calamity_frail_ratio` / 公式里的硬编码 0.7 | ❌ S28 已弃用；与钳制后实际值脱节 |
| C 施加时快照的实际值 | `_calamity_frail_cut` / `_calamity_saved_*` / 新增快照字段 | ✅ 唯一合法来源；S28 立下、S31 补齐 |

| 判定句 | 内容 |
|---|---|
| 一句话 | 玩家看到的百分比，必须等于**施加那一刻真正写进效果通道的数**（或其相对施加前基线的实际变化量） |
| 推论 1 | 之后任何 live 漂移（clear / tick / 主题重建）都不许改写这句话 |
| 推论 2 | 快照必须随灾祸同生共死：施加点写、clear 条件块清，不跨层、不跨局 |
| 推论 3 | 首词是历史断言锚点，收敛只动括号里的取值与措辞，不动族名一个字 |

## 3 交付一：frenzy / scarce_ammo 各读什么

| 方案 | 新增字段 | 抗 live 污染 | 抗映射漂移 | 改动面 |
|---|---|---|---|---|
| A 内联现算（读 `_calamity_theme_rule` 再抄一遍 match） | 0 | 强（rule 是快照） | 弱：三路映射存两份，S27 变体一改就分叉 | 只改 `_calamity_name` |
| A′ 共享纯函数（`_applied_mult(id, rule)`，apply 与 name 同调） | 0 | 强 | 强：单一真源 | 需把 `_apply_calamity` 三路赋值改为调函数 |
| **B 施加点快照字段（推荐）** | **2** | **最强**：快照的就是写下去那个数，连钳制与未来分支都包含 | **强**：赋值处即真源 | apply 加 2 行赋值 + clear 条件块加 2 行复位 + name 改读 |

| 项 | 推荐落点（供实施方参考，非本文改码） |
|---|---|
| frenzy | `_calamity_speed_mult_applied`（float，施加支内 `= Game.calamity_speed_mult`）→ 文案 `(快照 − 1.0) × 100` |
| scarce_ammo | `_calamity_ammo_mult_applied`（float，施加支内 `= player.mag_cap_mult`）→ 文案 `(1.0 − 快照) × 100` |
| 复位 | 两字段都进 `:652-658` 的 `if _calamity != ""` 块，与 `_calamity_saved_*` 同生命周期；**不可**无条件复位（沿用 B6 空灾祸层口径） |
| 为什么不复用 `_calamity_saved_mag_cap_mult` | 它存**施加前**值（还原用），默认局=1.0，读它只会得到 `-0%`；frenzy 连 saved 字段都不存在 |
| 为什么不全用 A′ | A′ 是合理回退，也贴合 `_frail_ratio()` 既有范式；但它要改 apply 赋值路径，超出"只改文案取值来源"的最小面。若主理人坚持零新增字段则选 A′，**禁止选 A** |
| 取舍结论 | 主推 B：S31 修的正是"显示与施加脱钩"，快照那个被写下的数是最短证据链；2 字段 + 同处复位是可审计的小改动 |

## 4 交付二：0 值措辞

| 灾祸 | 常规 | 增量为 0 / 削减为 0（逐字建议） | 禁止出现 |
|---|---|---|---|
| frenzy | `狂乱（敌人加速 %d%%）` | **`狂乱（敌人不再加速）`** | `狂乱（敌人加速 0%）` |
| scarce_ammo | `弹药荒（弹匣 -%d%%）` | **`弹药荒（弹匣不再削减）`** | `弹药荒（弹匣 -0%）` |
| 既有对照 frail | `虚弱（生命上限 -%d%%）` | `虚弱（生命上限不再削减）` | `虚弱（生命上限 -0%）` |
| 既有对照 scarce_ore | `残响枯竭（残响掉落 -%d%%）` | `残响枯竭（残响不再削减）` | `残响枯竭（残响掉落 -0%）` |

| 措辞规则 | 说明 |
|---|---|
| 句式 | 与 S28 对齐：`族名（对象 + 不再 + 动词）`，首词逐字不动 |
| 动词选择 | frenzy 用"加速"的否定"不再加速"（不是"不再增量"），与常规句共用同一动词，读起来才像同一条文案的两个分支 |
| 判零条件 | ammo：`快照 >= 1.0`；frenzy：`快照 <= 1.0`；ore：`cut <= 0.0`（S28 现行）；frail：`cut <= 0`（S28 现行） |
| 不许糊弄 | 禁止用 `maxf(0.0, cut)` 把 -0% 抹成 0% 后照常显示——S28 交付已点名此为反模式 |

## 5 交付三：压力层 scarce_ore 分母

| base 口径 | 压力层取值 | 算出 | 显示 | 判定 |
|---|---|---|---|---|
| **施加前快照** `_calamity_saved_diamond_mult` | 1.5（主题 maxf 后的真实基线） | `1 − 0.7/1.5 = 53.3%` | `残响枯竭（残响掉落 -53%）` | ✅ 推荐，且是**现行行为**，S27 13 号格已验 |
| 当前 live `diamond_mult` | 0.7（施加后） | `1 − 0.7/0.7 = 0` | `残响枯竭（残响不再削减）` | ❌ 明明砍掉 0.8 却说没砍 |
| 名义 `_mod_diamond_mult` | 1.0（未计主题合法抬升） | `1 − 0.7/1.0 = 30%` | `残响枯竭（残响掉落 -30%）` | ❌ 退回名义比例，低报实际 |

| 为什么快照符合"报实际" | 说明 |
|---|---|
| 因果链 | 施加前玩家**实际**拿 1.5 倍（主题合法承诺），施加后**实际**拿 0.7；灾祸真实拿走 0.8/1.5 = 53%。快照正好记录这两个端点 |
| maxf 不是缺陷 | 主题当层抬升是合法杠杆（S27 批三 C1 已修跨层残留）；文案应如实反映它，而不是把它约掉 |
| barren 同规矩 | base=0.7 → `minf(0.7,0.7)` 没削 → 落 S28 已定的"不再削减"；同一 `cut<=0` 分支，无需特判 |
| ~~建议顺手收口~~ **不采用（D3 已拍）** | 原式 `1.0 − 0.7/base` 一个字不动；`cut = base − minf(base, 0.7)` 会改 `base < 0.7` 的边界语义，属另一件事，不并入本批 |

## 8 交付六：交给 QA 的验证方向

1. 核心命题：证明文案数字**等于施加时写入的值**而非任意时刻的 live 值——**以 QA 口径的手工 live 差分构造为准**（apply 后只改 live、不碰快照），同一构造读两次，中间制造 live 漂移。
2. ammo 正向：施加后经 toxic tick 把 `mag_cap_mult` 从 0.5 推到 0.3，`弹药荒` 仍报 -50%（现行会变 -70%）。
3. ~~frenzy 正向（调 clear、暂不清 id）~~ **已撤销（主理人裁定，生产不可达）**：D1 规定快照在 `_clear_calamity_effects()` 的 `if _calamity != "":` 块复位，id 未清时 clear 会连快照一起清，文案必报「不再加速」，与本条原期望互斥。实读 `game_main.gd:1061-1063`：真实顺序是 clear → `_calamity = ""` → `update_floor_sign()`，clear 与清 id 之间没有任何读文案窗口；清完 id 后层签走「无」分支，根本不读快照。快照随灾祸在 clear 时失效是**正确的生产语义**，不为纸面中间态延后。frenzy 的差分验证**以 QA 口径的手工 live 差分构造为准**（apply 后手工改 live、不碰快照，只验 live vs 快照单一变量）。
4. ore 双负对照：pressure 构造 base=1.5 必须报 -53%；并证明换成 live 会得"不再削减"、换成 `_mod_*` 会得 -30%——负对照红才算覆盖。
5. 0 分支：构造/强制中性值，四条都走"不再…"，全串不得出现 `0%` 或 `-0%`；标注为前提守卫，不计有效覆盖。
6. 回归守卫：H07 四首词 + ⑦四条 + H01/H02/H04/H05 全绿；E1 三 seed 指纹逐字一致、rng count 不变。
7. 人眼验收：toast / banner / HUD 三处渲染读起来自然（headless 测不了语感），由主理人看。
