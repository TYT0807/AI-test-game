## 1. 一句话

**圣所三张卡，第一张永远讲本层地形（S32 不动），第二、三张开始讲本层灾祸——被灾祸打空的那种货币，圣所少卖；能补缺口的，抬进候选。净化不再一刀切作废本局 ×1.5，而是「回来过一个」：每赎一层，代价就赎回一层，赎满才复原。**

两条改动都只动「玩家可感知的因果」，不新增随机、不新增状态机、不碰池子构造。

## 2. 为什么是现在、为什么是这个形状

### 2.1 前置实测事实（编程侧交来，日志 `D:/Create/Game/_tools/sp_logs/s33_prefacts.log`，采集条件 run_seed=12345、八坐标固定）

| 编号 | 事实 | 设计含义 |
|---|---|---|
| A | 圣所今天只读「有没有灾祸」一处（净化入池门槛），但这一处副作用半径是**全层**：有灾祸 vs 无灾祸对比，出卡变了的坐标 7/8～8/8（池子 +1 使全部 `stable_hash % size()` 错位）；含净化房比例 2/8～8/8 悬殊 | 「有没有灾祸」已经是全层开关，只是玩家读不出原因——抽出来的，不是设计的 |
| B | 四种灾祸（frail/frenzy/scarce_ammo/scarce_ore）对圣所**完全不可分**，逐层逐字相同 | 「什么灾祸」是一个全新自由度，今天一分钱没花 |
| C | 出卡路径**零 rng 消费**（1681 次调用后 `rng.seed`/`rng.state` 逐字不动） | 加灾祸项可以零新 rng、零新状态（`_calamity` 已是现成字段） |
| D | 未开房的卡在净化后被改写（同一未开房 `[heal,blood_relic,ward_boon] →（净化后）[heal,relic_suffix,greed_pact]`）——卡是开房瞬间才算的 | 「锁进层瞬间的卡」需要写新代码，本批**不做**（见 §8） |

### 2.2 为什么选方案β（分工两槽）而不是别的

作者给的候选里，重排池子、按灾祸换整套卡、给灾祸单独开池等做法共同的问题是：**动了 pool 的规模或顺序，`stable_hash % size()` 全线错位**，S32 刚立的 M1/M4–M7 断言和 FROZEN 串会整片报废，而且玩家看到的是「换了个游戏」而不是「圣所懂我的处境」。

方案β的形状恰好把成本压到最小：

- **首槽恒归主题**：S32 的 `_shrine_theme_pref` 与其三段式 p0 路径逐字保留 ⇒ M1/M4/M5/M6/M7 五条断言原封不动地继续为真。
- **灾祸只进第二/三槽的候选收窄**：实现上就是把「灾祸压低名单」并进既有的 `dn`（主题压低名单），在 c1/c2 两个候选段各多排除几个 id。**pool 的构造与顺序一个字节都不动** ⇒ 规模恒定 ⇒ 无级联洗牌。
- **代价的表达方式是「少卖」而不是「禁卖」**：被灾祸打空的货币对应的卡，仍可能出现，但权重从「约 1/3」降到「只在兜底时出现」。设计上这是克制——圣所不是不知道你在挨饿，它是在你挨饿时不那么劝你走那条路。

### 2.3 为什么净化要改成部分赎回

S28 批一的净化是一刀切：用过净化，本局 ×1.5 永久作废。这个设计当时成立，是因为「代价必须有一次是真的疼」。但 S32 之后回看，它有一个玩家读不出的断裂：

- 灾祸是按层掷的（`_roll_calamity`，`game_main.gd:545-560`），`calamity_floors` 是一个**逐层的账**；
- 而「作废 ×1.5」是**整局的刑**。第 9 层净化了第 3 层欠下的债，第 12 层的灾祸却还在替第 3 层受罚。

部分赎回把刑罚改回账目：**你赎了几层，加成恢复几分；赎满，才回到从未欠过债的状态**。这不是软化——「回来过一个」（《铁活家》母题）的原意就是：日子不是赦免回来的，是一层一层赎回来的。

- **未取**：任何具体情节事件、章节顺序、台词原文、章名。小说剧情尚未敲定，游戏不落未定稿。
- `D:\大纲\库\05_代价与污染\` 为他人原作全文，本批**零引用**。
- 游戏内命名走项目既有原创口径（同拾痕者／游魂聚合体／残响悬铃先例）：新术语定为**「赎回层」**（redeemed floor），不复用任何他作专名。

## 4. 机制本体 · 一：灾祸分槽（方案β）

### 4.1 玩家可感知到什么

1. **同一个坐标、同一个种子，换一个灾祸，第二/三张卡会变；四灾祸不再逐字相同**（直接回应事实 B）。
2. **正在被灾祸抽干的那种货币相关的卡，明显变稀**：例如 scarce_ammo（弹药稀缺）当层，靠钻石滚经济的那类卡少卖；frail（体弱）当层，血契类少卖。
3. **第一张卡不变**：它仍然只讲本层地形（S32 的承诺原样保留）。玩家的直觉读法是：「圣所的主菜看地，配菜看年景。」
4. **没有灾祸的层完全无变化**：S32 行为逐字复现（回归面为零的来源）。

### 4.2 灾祸→压低名单（cal_down）

映射原则：每种灾祸打空一种「经济支柱」，圣所就对**依赖该支柱的卡**降权。四种灾祸各自对应唯一一张「卖点就是那个支柱」的卡：

| 灾祸 | 打空的经济支柱 | cal_down（压低名单，恰一张） | 理由 |
|---|---|---|---|
| `frail` | 生命上限经济（max_hp） | `[blood_relic]` | 体弱当层卖血契 = 劝人拿最薄的本钱去赌 |
| `frenzy` | 防护/收益的安全边际 | `[ward_boon]` | 狂乱当层护佑类承诺的是它给不了的东西 |
| `scarce_ammo` | 钻石→弹药补给链 | `[shard_pact]` | 弹药稀缺当层，契约类钻石承诺兑现不了 |
| `scarce_ore` | 矿石升级链 | `[ore_upgrade]` | 缺矿当层，升级类是画饼 |

> ⚠ 本表**作者 2026-11-17 已裁（U4 = 默认表，每灾祸恰 1 张）**：压低名单即下表四行，不再扩为每灾祸 2 张、不再手工另配。

### 4.3 机制层规格（描述，不是代码）

沿用 S32 案C 的三段式定向池，只改一处输入、**零处后缀**（订正 C-2：原「两处后缀」表述作废；订正 C-4：原「两处输入」中的 c2 排除已撤销，实际只改 dn 一处）：

- **输入改**：`dn = 主题压低名单 ∪ (cal_down(当前灾祸) ∩ pool)`。无灾祸时 `cal_down` 为空集，`dn` 与 S32 逐字相同。
- **候选段改（订正 C-4：本批只改 c1 一侧）**：p1 从 `pool − p0 − dn` 抽（同 S32，但 dn 变宽）；**c2 逐字不动**——仍按 S32「只排 p0/p1」（S32 原注释逐字：`# 三段定向池：… p2 只排 p0/p1（down 靠不进第二槽结构性压低，非永不出现）`）。灾祸对第二/三槽的改写经 **c1→p1→c2→p2 级联**达成：dn 变宽 ⇒ c1 少一张 ⇒ p1 取模落点变 ⇒ c2 = pool−p0−p1 随之变 ⇒ p2 变。首稿曾要求「p2 从 pool−p0−p1−dn 抽」，实测（日志 `D:/Create/Game/_tools/sp_logs/s33_a4_s32.log`）使 S2/S3/S4/M6/M9 五条 down 频率断言全红（`power=0.0000`、`distinct=9`＝那张卡彻底绝迹），即「禁卖」，与本节 §2.2 的承诺互相否证，故撤销（订正 C-4）。
- **哈希后缀（订正 C-2：二选一已选定 = (a) 不加新后缀）**：实码 `game_main.gd` `_shrine_offers_for` 有偏好分支的三处抽取后缀逐字为 `#0` / `#1` / `#2`（**不存在旧稿误写的 `key#1c` / `key#p2c` 一类后缀，也不存在 `key#p2`**）。本批裁定：**不引入任何新字符串常量**。理由：`dn` 变宽后 `c1.size()` 随之改变，p1 落点变 ⇒ `c2 = pool − p0 − p1` 的成员随之变 ⇒ p2 落点亦变——级联已足够改写第二/三槽，零新键即零新面（订正 C-4）。无灾祸时 `dn` 与 S32 逐字相同、`c1`/`c2` 规模不变 ⇒ **有/无灾祸两态都无需后缀开关**：无灾祸侧由「网格逐字复现」断言守（验证口径 V-C5），有灾祸侧由「四灾祸两两可分」断言锁（V-C6）。
- 抽取仍是 `stable_hash(...) % size()`，**零新增 `Game.rng` 调用**（事实 C 的延续）。

### 4.4 边界态（设计层已定，验证口径里有对应判据）

| 场景 | 行为 |
|---|---|
| 本层无灾祸 | 与 S32 逐字一致（含净化入池与否的旧门禁） |
| 净化门禁 | 规则不变。**订正 C-1**：实码 `:3660` 是 `if String(id) == "purify" and _calamity == "": continue`——即 purify **仅在 `_calamity != ""`（本层有灾祸）时入池**，无灾祸时被剔除（此前初稿写反，若流进验收会把 M7/M8 期望系统性写反）。灾祸压低名单**不得**影响这条门禁的判断本身 |
| cal_down 命中主题抬高名单 pr | 不特殊处理：pr 段照旧抽 p0（首槽恒归主题），被压低的这张若同时是主题主推，它进不了第二/三槽但仍可在首槽出现——「主菜保留、配菜撤下」 |
| cal_down 与主题压低重合 | 并集自然吸收，无优先级问题 |
| 候选段被 dn 掏空（size==0） | **算术上不可达（pool≥5、dn≤2），不设兜底**。依据：pool 最小规模实测 5（3–4 层无灾祸 = blood_relic/ore_upgrade/purify/ward_boon/heal/greed_pact 六项去 purify）；dn 上限 2（主题 1 ∪ 灾祸 1，U4 已裁每灾祸恰 1 张）⇒ \|c1\| ≥ 5−1−2 = 2、\|c2\| ≥ 5−2−2 = 1。**订正 C-4**：此前写的「走既有回退路径（实码既有守卫）」是假事实——实码只有 `if pool.size() < 3: return []` 一道护栏，c1/c2 空集时 `stable_hash(...) % 0` 直接运行时报错，不存在所谓回退守卫 |
| 净化当层（`_calamity` 置空） | 后续未开房按「无灾祸」出卡——即净化本身就是「年景转好」的信号，机制自洽 |

## 5. 机制本体 · 二：部分赎回

### 5.1 玩家可感知到什么

1. 净化卡文案从「本局 ×1.5 结算加成作废」改为**按账目说话**：本局已历灾祸几层、赎回几层、结算时加成还剩几分。
   ⚠ **本批边界（C-7 订正，防实稿过度承诺）**：今天玩家可从卡面读到的只有「**结算加成按未赎回的层数保留**」这一句**无条件真话**——它说对了机制方向，但**具体债账读数（欠几层／赎了几层）本批不提供**。盘上事实：`update_floor_sign()` 在 `_calamity == ""` 时报「灾祸：无」，于是刚净化的层与从未有灾祸的层在 HUD 上逐字相同；结算界面也不显示乘数。⇒ 这是**表层缺口，不是机制缺陷**（账本身是对的，由 B04/B05/B06/C03/A07 五条实值断言坐实）。
   ✅ **收口已裁（C-7 K-4）：第 1 条承诺的三读数「显示」，实现随 S34+ 表层件《净化卡的债账读数》落地（核验 K-3 / 实施单 U6）。** 本节因此恢复为**有效设计意图**而非过度承诺——只是它的交付批次不是 S33。S33 盘上仍按上面那句无条件真话交付，⛔ 编程侧不因本改裁提前动代码。
2. 结算界面的 ×1.5 不再是「有/无」两档，而是**随赎回进度回升**：赎一半，加成的一半回来；赎满，全额回来且与从未欠债者逐字同值。
3. 「回来过一个」的体验结构：债是逐层欠的，就要逐层赎的。想清爽收场，就得把每一层灾祸都回去净化一次——这本身就是玩法目标。

### 5.2 赎回什么、多少、怎么选（确定性规格，无「视情况」）

- **赎回对象**：一层灾祸的历史记录，即 `calamity_floors` 中的一个层号。
- **选择规则（纯确定性）**：净化发生时，把**当前层**记入赎回账（`erase(当前层)` 的既有动作保留为记录语义，同时把该层追加进 `redeemed_floors`）。**一次净化恰赎回一层，永远是你站着的那一层**——不存在「选哪层」的界面、不存在抽签、不存在策略歧义。
- **多重记录的处理（订正 C-3）**：「同一层被再次登记」**不可能发生**，不是边角而是确定事实：`_roll_calamity` 登记处（`game_main.gd:555-556`）有 `if not Game.calamity_floors.has(Game.floor_num): append(...)` 去重守卫（注释注明「同层不重复登记，Array.erase 只删首个」），且 `floor_num` 在 `next_floor()`（`:2975-2995`）内单调递增 ⇒ **本局内 `calamity_floors` 层号互异、`redeemed_floors` 层号互异、二者交集至多当次净化的那一层**。此条升格为负向靶（验证口径 V-D4）：任一层号同时出现在两账、或同账出现重复层号 = 红。
- **可见性（购前可见）**：打开圣所面板时，净化卡的代价行显示**当前账目**（已历 N 层 / 本次后赎至 M 层），数字来自当场计算，非静态文案。玩家买之前就知道这次净化买到的是什么。

### 5.3 结算公式（替换 game_state.gd:420 的判定式）

设：
- `N = calamity_floors.size()`（本局至今欠下的灾祸层数，净化后的 erase 保留现状 ⇒ 注意：`N` 是**未赎回的余债数**）
- `R = redeemed_floors.size()`（本局已赎回层数）

裁定模型（**U1 线性按层、U2 恒为本层，作者 2026-11-17 已裁**）：

```
if R > 0 and R < N + R:      # 部分赎回
    bonus_multiplier = 1.0 + 0.5 * R / (N + R)
elif N > 0:                  # 欠债未赎（purified_run 从未为真的旧语义的近亲）
    bonus_multiplier = 1.5   # 维持现行 ×1.5 —— 注意：×1.5 是惩罚还是奖励？见下
else:
    bonus_multiplier = 1.0
```

> **×1.5 的语义澄清（重要，作者需知）**：S28 原文案「净化 → ×1.5 作废」意味着 ×1.5 是**持有灾祸带来的结算加成**（风险补偿），净化是放弃它换安宁。部分赎回沿同一读法：**赎回一层，就放弃那一层对应的加成份额**。所以正确的单调性是——赎得越多，加成越**低**，赎满归 1.0（与 S28 一刀切终态一致）；不赎则保持 ×1.5（与「有灾祸吃加成」的现状一致）。修订公式：
>
> ```
> D_total = N + R            # 本局灾祸总层数（欠+已赎）
> if D_total > 0 and R < D_total:
>     bonus_multiplier = 1.0 + 0.5 * (D_total - R) / D_total   # 未赎份额按比例计
> else:
>     bonus_multiplier = 1.0
> ```
>
> 边界自检：R=0 ⇒ ×1.5（=现状）；R=D_total ⇒ ×1.0（=S28 一刀切终态）；S28 时代只有「全废」一档，故其观测值在新公式下仅当 R∈{0, D_total} 时可复现——这正是 S28 B 靶（B04/B05/B06）断言冲突的根源。**订正留痕**：此前本节及 §6 把「欠 2 赎 1」标成 ×1.25（正解 1.3333→26；×1.25→25 对应「历 2 赎 1」即 N=1,R=1），且据此推过一个磁盘上不存在的 fixture 形态。验证口径 E6 已裁定 B 靶按真 play 重构并给出三条最终期望（20/25/26）。
