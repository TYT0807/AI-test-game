## 1. 一句话

**把 21 只 CC0「Tiny Creatures」通用奇幻怪，从名字到剪影整体换成《六道卷》世界观里的「异常」：每一只的新显示名必须替玩家读出它的机制（脆/厚/绕后/扑/扎根/分裂/召崽），贴图靠剪影与明度层级说话、绝不靠绝对色相（因为 tint 会乘色）。内部 id、数值、AI、掉落一个字节不动。**

同批表态：Boss 双线走**分层**（主题三杰＝终局，骷髅王/炎魔/黑龙降格为「层关执令」），并预留 3–5 只纯原创生物作为游戏→小说的反哺样本。

## 3. 裁定：Boss 双线 = 分层，不合并

**裁定：分层。**

- **终局位**：棱镜守望者／熔潮主宰／玄渊之主（`boss.gd/boss2.gd/boss3.gd`，`shardbearer.png` 原创图集）——不动、不重画、不改名，仍是 README 宣传的那三位。
- **层关位**：`skeleton_king / demon / dragon` 三只换皮改名，定位话术统一为 **「执令」**——六道轮转每转一层，留下一道「执令」看住关口；它们是**层关大头目**，不是主题终局 Boss。图鉴措辞、手记措辞都按「执令 < 三杰」的位阶写，不得出现「最强」「最终」字样。
- `echo`（回响）不属任何一线，它是悬铃系特殊敌，自成一档（§5.3）。

**为什么不合并**（若作者改裁合并，爆炸半径如下，逐条都是机制面，违反本批「换皮不换机制」纪律）：

| 牵动项 | 后果 |
|---|---|
| `BOSS_BY_FLOOR` | 值要重写，floor1 现指 `"boss"`（8 虫轨的巨岩虫之王），三条映射全变 |
| `SQUADS` | 两支编队的 `"boss"` 槽位指向变，出怪组合全线错位，E1 指纹/churn 大面积漂移 |
| `CODEX_BOSS_NAMES` | 图鉴登记与冻结串冲突，19 条断言之外的 Boss 名断言须重采 |
| `SMOKE_FORCE_SOVEREIGN` / `SMOKE_FORCE_THIRD_BOSS` / `SMOKE_ABYSS` | 三个探针的强制入口语义失效或需重定义 |
| `shardbearer.png` 图集 | 160×288 原创格图集要扩容，回到美术批而非换皮批 |

分层的代价只有一个：**玩家会问「为什么层关也有大头目、它和三杰什么关系」**——这正好用「执令」话术回答（§5.3），成本为零。

## 4. 换皮规格

### 4.1 四条落地通道（白名单，超出即违规）

| 通道 | 内容 | 载体 |
|---|---|---|
| T1 | 同名覆盖 PNG：`resources/texture/monsters/<id>.png`，**32×32、索引色含透明 ≤10 色、硬边无抗锯齿、纯透明底**，走 spr25 范式自检 | 文件替换，路径不变 |
| T2 | `ENEMIES[*].name` 显示名 | `data.gd`（冻结文件，改后如实上报变 md5） |
| T3 | `ENEMIES[*].desc` 一句话 | 同上 |
| T4 | `FLAVOR["enemies/<id>"]` 手记文本 | 同上 |

⛔ 禁动清单：`id` 键名、`ai`、`hp/spd/dmg`、`float/armor/drain/split/summon/scale`、`tex` 字符串本身、`MONSTER_NAMES` 数组成员顺序、`SQUADS`、`BOSS_BY_FLOOR`、一切 `.gd` 逻辑行。

### 4.2 视觉语言三件套（替代表达「绝对色相」）

1. **剪影**：一帧缩到 8×8 灰块后仍可辨认的姿态特征（驼背持械 / 圆墩单眼 / 兜帽空脸 / 四足低伏 / 浮球垂链）。这是第一识别层。
2. **明度层级五档**：杂兵中明度、精英高对比 + 亮记号、Boss 级满对比 + 全身多阶。玩家的直觉读法：**越亮越硬，越花越疼**。
3. **图形记号**（每个记号绑一个机制字段，全表通用、不许一只占用无关记号）：

| 记号 | 绑定机制 | 读法 |
|---|---|---|
| 甲片/壳纹/蒙布 | `armor` | 有甲 ⇒ 正面不吃刀，绕后 |
| 前倾姿态＋后蹬腿 | `leap` | 会扑 ⇒ 留位移 |
| 扎根底座/锚/藤缠足 | `turret` | 不追人 ⇒ 可以先拆 |
| 脐带/囊/引线 | `drain` | 碰它就回血 ⇒ 别站桩 |
| 裂纹/接缝 | `split` | 死了还会动 ⇒ 别用大招换它 |
| 腹下幼芽/肩侧小首 | `summon` | 会放仔 ⇒ 先杀本体 |
| 空瞳/雾面 | `float` | 无视地形 ⇒ 箱子拦不住 |
| 顶饰（角/冠/幡/铃/髻/烛） | Boss 级专属 | 一眼知道这不是杂鱼 |

### 4.3 tint 鲁棒性硬判据（🔴 可机检，验证口径将据此立条）

- **D-A（灰度判据）**：任一张新贴图转灰度后，其剪影与明度层级仍足以区分「这只 vs 同家族其余只」。做法：与同族并排去色比对，认不出即返工。
- **D-B（双 tint 试色）**：入库前以 `Color(0.95,0.85,0.6)`（暖金）与 `Color(0.72,0.86,1.0)`（冷蓝）各乘一次截图，两态下剪影与记号都读得出、且不与同屏他敌混形。**任一态读不出 = 不合格**。
- **D-C（色数与色板）**：≤10 色含透明；主色不超过 3 个色相族；禁止依赖「红色＝危险」这类绝对色相语义（危险由记号与前倾姿态表达）。
- **D-D（Boss 糊化防线）**：`scale ≥ 2.0` 的三只（skeleton_king/demon/dragon）贴图必须按「目标尺寸 ÷ scale ≈ 64–74px 视高」来设计细节密度：轮廓占满 32×32 网格、内部分区 ≥ 6 块、顶饰独立可读。目标是放大后读到的是「结构」而不是「糊」。

### 4.4 「大」的正面处理（回应事实 B）

不改 scale、不改渲染层。用三招把「大」从倍率变成信息量：①**轮廓占格**——杂兵留边 2–3px，执令级顶满 32×32；②**内部分区数**——杂兵 2–3 个明暗区，精英 4–5，执令 ≥ 6；③**顶饰**——每只执令一款专属顶饰（骨幡／烛冠／盘脊），这也是 §7 反哺小说的具体钩子。三者叠加后，玩家在任何 tint 下都能凭「密度」判断威胁档位。

### 4.5 生图工作流（SDXL 仅作中间态）

`SDXL 概念稿（单体、纯色底、指定视角）→ 人工重绘清理 → 降采样至 32×32 → 索引色量化 ≤10 色含透明 → 硬边化（无抗锯齿/羽化）→ 纯透明底 → spr25 范式 verify() 自检（IHDR 逐字段）→ 同名覆盖入库`。

🔴 **原创性口径（入库闸）**：
1. SDXL 产物**永不直接入库**；每张必须经人工重绘/清理，压到不可溯源单一模型风格的程度（判据：与生成原稿并排比对，笔触、噪点、渐变、细丝状伪影全部消失，只剩剪影与色块意图）。
2. prompt **不含任何他人作品专名、角色特征、徽章制服**；只用机制描述词 + 氛围词。
3. 先例一致：本批延续 S26「原创覆盖第三方图集」路线——`monsters/*.png` 文件名与路径不变，内容与版权整体置换，仓库内不再残留 CC0 素材。
4. 生成物与对应人工重绘稿的对照留档于 `production/sprint-34/_artgen/`（本批新建，gitignored 与否由编程侧定，文档不假设）。

## 6. 保留 / 淘汰 / 合并视觉家族

**功能重复是事实**：goblin/orc/skeleton/zombie 四只全是 chase 杂兵，只差数值档。硬造 4 个互不相干的剪影是浪费设计预算，也给玩家增加无效记忆负担。

**提案（默认值，作者可改裁）：五个视觉家族 + 六只独立设计。**

| 家族 | 成员 | 共同剪影基底 | 家族内区分手段 |
|---|---|---|---|
| 拾荒家系 | goblin(抢剩) / orc(夯户) | 佝偻人形+杂物随身 | 体型档（小抱罐 vs 大方肩持棍）+ 武器剪影 |
| 骨架家系 | skeleton(骨役) / knight(铁面) / skeleton_king(提骨) | 绳索捆扎的骨/甲结构 | 覆盖率：裸骨 → 半身甲+盾 → 全身+骨幡 |
| 圆墩家系 | zombie(沉疴) / slime(分瘴) / mush(孢子侏) | 低重心团块 | 表面质感剪影：拖布 / 釉面裂缝 / 伞裙幼芽 |
| 飞扰家系 | imp(灯蛾) / faerie(纸钱蝶) / wraith(湿袖) / beholder(百目胎) | 无脚悬浮 | 悬浮附件形态：翅 / 纸角 / 垂袖 / 眼窝囊 |
| 甲壳家系 | ogre(裹城) / minotaur(拱墙) | 厚块体 | 缠裹叠纹 vs 角铲前势 |
| 独立设计 | flameskull / plant / vampire / wolf / demon / dragon / echo(若U5裁跟画) | —— | 各自一款专属记号（炉口/泥座/蛭囊/蹬腿/烛冠/脊鳞；echo 沿用抱铃剪影） |

### 5.5 覆盖清点（21 = 21，无占位无遗漏）

| 组 | 只数 | 成员 |
|---|---|---|
| 家族·拾荒 | 2 | goblin, orc |
| 家族·骨架 | 3 | skeleton, knight, skeleton_king |
| 家族·圆墩 | 3 | zombie, slime, mush |
| 家族·飞扰 | 4 | imp, faerie, wraith, beholder |
| 家族·甲壳 | 2 | ogre, minotaur |
| 独立 | 6 | flameskull, plant, vampire, wolf, demon, dragon |
| 特殊档 | 1 | echo（默认不重画，见 U5） |
| **合计** | **21** | 与 §1 的 21 只换皮对象逐一对应 |

⛔ `rusher / brute / spitter / bomber / elite / boss(巨岩虫之王) / splitter / mini` 这 8 只在 slug 原创轨上，**不在本批范围**（§10.3）。

**合并家族的代价（如实报给作者）**：
1. 玩家区分度下降——同家族靠体型与配件分辨，初见误认率上升，尤其拾荒家系两只同为 chase 时手感几乎一样（机制本就一样，视觉再像，玩家会以为「刷重复了」）。
2. 图鉴观感单调——21 格里实际只有 5 种设计语言，翻页惊喜少。
3. 反哺价值降低——小说能回收的「形象点子」变少。
4. 对冲手段：家族内至少一处**专属记号**不同（上表第四列），保证 D-A 灰度判据可过；名字全部差异化（不做「骨役一号/二号」这类偷懒命名）。
