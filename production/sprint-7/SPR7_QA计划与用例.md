### 0.2 D1 + D5 合起来会造成**永久死循环**（最高优先级）

当前实现默认档（新档、一个都没解锁）实际可用内容：

| 类别 | 基础总数 | 被节点锁住 | **默认可用** | `MIN_USABLE`（`meta.gd:69`） | 结果 |
|-|-|-|-|-|-|
| 升级 | 14 | `venom` `guard` `chain` = 3 | **11** | 3 | ✅ 够抽 |
| 遗物 | 10 | `drone` `bigbullet` = 2 | **8** | 2 | ✅ 够抽 |
| **武器** | 4 | `shotgun` `railgun`/`launcher` = 3 | **1（只剩 rifle）** | **1** | ⚠️ **卡在阈值上** |

推演死循环（规格 §4.3 已定为「硬伤，不可回调」）：

1. 新档玩家只有 `rifle` → `weapons.gd:55-62` `random_unlocked()` 里 DROP_POOL 三把全被 gate → `ids` 为空 → **永远返回 `"rifle"`**（商店货架与所有掉落也只剩 rifle）。
2. 玩家死在第 1 层 → `meta.gd:147` `floor_num < min_floor(2)` → **payout = 0** → 拿不到第一笔结晶。
3. 没有结晶 → 解锁不了任何节点 → **永远只有 rifle**。
4. 永远只有 rifle → 打不过第 2 层 → 永远死在第 1 层 → **回到第 2 步**。

→ **弱玩家永久无法爬出第 1 层**，且**自检完全不会报错**（`validate.gd:222-226` 的 `MIN_USABLE` 检查恰好卡在阈值上通过）。

**必须同时修 D1（换回增量模型）与 D5（`min_floor=1`）**；只修其一不足以解开循环。

> **team-lead 追加要求**：自检要能抓「**某类内容默认可用数退化到 1**」这类退化 → 已落成 **M5-14**（P0）。

### 0.3 D8 不修的后果：解锁 = 没买

`upgrades.gd:74-77` 权重 = `(max - taken) × rarity_weight`，**无 boost**。按规格 §10.1 的实测口径，单张新卡一局可见度约 **21%**（`P ≈ 5/446`，一局约 7 次升级选择）；玩家花 40 结晶买的卡 **5 局才见一次** → 「解锁等于没买」，meta 动机链断裂。规格 §10.2 的补偿（永久 ×1.5 + 前 3 局 ×6，乘性 = ×9）能把可见度提到约 **76%**，**必须实现**。

**E8′ 的三个退化点（QA 实读；注意 `relics.gd` 那处**没有 `maxi` 包裹**，别只按 `maxi(...)` 兜底那种写法 grep）**

| 抽卡入口 | 退化条件 | 正常 | 退化后 |
|---|---|---|---|
| `Weapons.random_unlocked()` | **`ids.size() <= 1`** → `randi_range(0, 0)` | 1 次 | **0 次** |
| **`Relics.roll(n)`** | **`pool.size() == 1`**（**末轮，每次都会发生**：抽走一件后池剩 1 件）／或空池 → `for` 循环 `break` | n 次 | **0 次**／整轮 0 次 |
| `Upgrades.roll(n)` | **`total == 1`** → `randi_range(1, 1)` | n 次 | **0 次** |

> **静态判据形式**：① 三个入口里 `randi_range` 的**两个参数不得可能相等**；② **空池不得 `break` 跳过消耗**；③ 消耗个数**不得依赖池大小 / 门控状态**。
> **统一修法（工程侧已同步）**：`randi_range` 参数不得相等；空池不得 `break`。最省事写法：索引换成 `Game.rng.randi() % maxi(n, 1)`（`randi()` 恒消耗 1 次，避开 `randi_range(a,a)` 退化）。
> **运行时计数探针（E8″）→ team-lead 最终裁定「恢复为门禁」**：实装 `[SMOKE-META-EXTRA] rng count upgrades=%d relics=%d weapons=%d`；默认档与全解锁档逐字相同（实测 60/40/20）。**静态 E8′ 不能替代运行时 E8″**：静态只证明写法，计数器才证明未来新增抽卡入口仍守恒。

**因果链（为什么 E5/E6 是根因层、E7 只是可观测量）**
```
E6 违规（time += 真实 delta）
 → 累积到同一 Game.time 所需的帧数每次运行都不同
 → 表现层每帧消耗的随机数总数不同（E5）
 → 同一游戏时刻的随机流位置不同
 → 地图指纹与全日志都不可复现
 → E7 / V16 必然非空
```
→ **E5 / E6 是「可修且静态可判定」的根因层，E7 只是它的可观测量。**

> ⚠️ **E4 已收回（team-lead 裁定）** —— 原「同 seed 两档 `use_door` 次数相同」**错在拿终态量当判据**：解锁**真的会**改变玩法（多 3 把武器可掉落 → 战斗过程不同 → 走的门数自然不同）→ **必然 FAIL，而那不是缺陷**。
> （QA 侧曾经的推理也已被吸收：SMOKE 默认无敌只消除「死得早」，**不消除「推进快」** → 后者才是主因。）
> → **「解锁不改变随机数消耗个数」的真门禁 = E8′（三个抽卡入口的消耗计数，静态可判定）**；E1（fingerprint 逐字相同）是它在运行时的对应表现。

**0 SCRIPT ERROR** + **0 条 `[ERR] meta:`** + **余额回默认** + **空解锁集** + **有效升级池 ≥ 3** —— 缺一即 FAIL。

## 九、易踩坑清单：静默失效 + **可自动检测**判据

| # | 静默失效 | 表现 | 可自动检测的判据 |
|-|-|-|-|
| 1 | **解锁项没真进池** | 解锁了但池里没有，玩起来没区别 | `SMOKE_META_POOL=1` 打印有效池 → 断言目标 id ∈ pool（**枚举断言，不靠概率**） |
| 2 | **池被过滤空** | 三选一变 1 张甚至 0 张 | 自检 MIN_USABLE + 运行期 `Dev.err("meta", "可用升级不足…")` + 回退全量池 |
| 3 | **存档路径写错 → 每局重置** | 解锁后重开就没了 | **跨进程**往返（`SMOKE_META_PATH` 固定路径 → 写 → 新进程读 → 比对）。**进程内往返不算数** |
| 4 | **自检没发现空池 / 退化** | 上面第 2 条没被拦 | 自检必须有 MIN_USABLE + **B5 退化检测**；报告贴自检输出行 |
| 5 | **结算触发两次** | 余额翻倍 | `_run_settled` 闸 + 探针 `settle count` == 局数 |

**三条执行纪律（踩过就白跑）**

1. 🔴 **跨进程往返必须用 `SMOKE_META_PATH` 指向一个 ≠ `user://_smoke_meta.cfg` 的路径**。

2. 🔴 **坏档 4 种模式各用独立路径**（`SMOKE_META_PATH=<每次不同>`），避免「首读删除」与上一模式残留互相污染；**每种一个独立进程**。

4. 🔴 **六种子基线每个种子跑 3 次**（高危种子如 seed2 跑 4 次）→ 取**分布**，**不拿单次值当期望值**。

5. 🔴 **不用逐行 diff 日志当回归判据**（R15）—— delta 驱动下连 SPR6 自己都 diff 不出；回归看分布。

### 14.6 本轮新增坑（承接交接稿 §五 29–49）

50. **自定义 `SMOKE_META_PATH` 不自动删档**：`load_meta()` 只在默认 `META_SMOKE_PATH` 时 `_remove_file()`；自定义档被反复结算写成 `crystals=140 / runs_played=5`，后续进程读到残留 → 跨进程假分叉。每轮独立验证前必须清；Windows 下 `$APPDATA` 反斜杠会被安全删除策略拦（`SAFE_DELETE_INVALID_PATH`），**必须转 POSIX 路径** `rm -f /c/Users/TangUser/AppData/Roaming/Godot/app_userdata/test_1/<档名>{,.bak}`。
51. **`ConfirmationDialog` 截图挂具组合**：只给 `SMOKE_MENU=1 SMOKE_UI_CONFIRM=1` 而不给 `SMOKE_MENU_PAGE=unlocks` 时，自动弹框分支在 `_build_unlocks()` 内、根本不执行 → 主菜单空白页。曾据此误判「确认框是独立 Window、截图捕获不到」并下发返工，实看正确截图后撤回。**没看到 UI 先查挂具，别先怪控件。**
52. **并行 worker 的「完成报告」不等于磁盘状态**：本轮两次出现「报告说改了/截图已生成，但实读那一刻文件还没落盘或已被还原」。主理人必须自己 `cmp` / `md5sum` / `ls -l` 定版，不能采信报告。
53. **补丁按 `\n` 匹配函数签名会静默失败**：项目里 `game_main.gd` 是 LF、`player.gd` 是 CRLF，混用换行；`assert` 失败后若后续验证命令用换行分隔而非 `&&` 串联，**实验会在「什么都没改」的状态下照跑并产出看似有效的基线数据**。补丁必须 `re.search(sig + rb'(\r?\n)')` 保留原 EOL，且验证命令与补丁用 `&&` 绑定退出码。
54. **`0 SCRIPT ERROR` 只证明没抛异常**：本轮 4 类「日志全绿但结论错」——布局回归、静默白框、确认框空白页、最小实验没落地。截图实看 + `cmp` 自证 + 补丁断言缺一不可。
