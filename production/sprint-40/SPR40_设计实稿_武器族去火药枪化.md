## 0. 结论先行

1. **作者的批评成立，而且比「画风」更准**。今天这四把的**名字本身**就是工业符号：`贯穿磁轨`（电磁轨道炮）、`爆破榴弹`（高爆弹）、`爆裂霰弹`（独头/鹿弹）、`标准步枪`。而 `D:\大纲` 的世界观是**平行现代**（科技＝当下现实，🔴 不是末世、不是热兵器时代，修行者仍是「画符、御物、布阵、隔空摄物」的道士路子）。所以这不是「图不够中式」，是**语义层就长错了地方**——图修得再好，HUD 上写着「贯穿磁轨」照样出戏。⇒ **改名与改 id 是主修，返修概念稿是辅修**。
2. **裁定走「同槽换定义」（甲路），不走「新增一把留着旧的」**。四把基础枪在 DEFS / DROP_POOL / 可用集基线 / 掉落与商店里各占一个语义槽，槽本身（单体直射／扇形霰射／高速穿透／抛物爆炸）是好的、玩家认的；要换的是**填槽的那件东西**。甲路的代价是必须重登一次冻结基线串（§4.2），这是流程成本不是设计风险；乙路（新增＋保留旧枪）会让「火药枪」这个被点名的符号继续留在起始槽和印记文案里，等于没答作者的问。
3. **候选池分三档，本批只投第一档**（§2.2）：A 档＝器物型（一件法器干一件事，与现有参数**一一对应**，⛔ 重新配平）；B 档＝符箓型（作者点名，但它是 A 档的 tint/life 参数变体，形态上不是新槽，且需要新图标族 ⇒ B 档只做 `launcher` 一支的对照候选）；C 档＝剑丸／飞剑（**最咬合世界观**，但要动 `_fire()` 的抽取结构 ＋ 新增滞空实体 ＋ 新计时，那是 S41 的方向级工程 ⇒ C 档整体挂账，本批不碰）。
4. **落地后的四把（我裁）**：`zhushan` 朱砂笔（直射）／`liechi` 裂髓杵（扇形霰射）／`guanglei` 光雷尺（高速穿透）／`fushe` 焚舍符匣（抛物爆炸）。全部**原创命名**，无一取自他作专有名词（自查见 §6）。
5. **⛔ 顺手整族重跑概念稿**。作者这次只点了「枪那个」。返修清单严格限定 3 张（§7）：`wpn_rifle`/`wpn_shotgun`/`wpn_railgun`。`wpn_launcher` 在 S34 审查表上是「原句保留、没跑偏」的一条，它的问题随**改名**解决而不是随重跑解决。这条约束同时保护了 S34 R2 那条还没点头的待办——两件事不能被我这一轮混成一锅。

### 1.2 为什么「磁轨」「榴弹」比「步枪」更该死

F1 里 `railgun` 的中文名叫「贯穿磁轨」——轨道炮是需要工业电力与导轨的**未来兵器**，它连「平行现代的民间土造」这条路都走不通；`launcher` 的「爆破榴弹」同理。作者说「看起来怪怪的」，图只是一半，名字是另一半，而且名字那一半**不需要重跑图就能修**。

### 1.3 对 S34 既有 prompt 表的处置裁定

S34 追加件一 §6/§7 给这四张写的英文 `<SUBJECT>` 是 `shoulder gun` / `breaker gun` / `twin-railed magnetic lance` / `shoulder mortar`。裁定：**其中三条作废**（rifle/shotgun/railgun 随本文换器型重写 prompt），`wpn_launcher` 一条**保留但降级**（它不再进本批返修队列，见 §7）。这不与 S34 R2 待办冲突：R2 谈的是「一族一句框架 prompt」的常量落盘与整族重跑，本文只动**词汇槽内容**，⛔ 改框架句。
