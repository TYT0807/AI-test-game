## 0. 先立标尺（作者的类比拆开看是什么）

| 参照 | 表面 | 底下真正成立的条件 |
|---|---|---|
| 重生细胞＝下坠爽感 | 一个**移动动作**被做成了进攻手段 | 关卡几何为它服务（竖井、深坑），失败有代价，成功有奖励链 |
| 元气骑士＝空手手刀 | 一个**默认状态**（没拿武器）被做成了可用打法 | 判据极简单（贴脸就触发），老玩家能用它秀，新玩家不会误踩 |

抽出三条筛选标准（后面每个候选都要过）：
1. **它是动词不是名词**——「有一把新武器」不算特色创新，「玩游戏的动作本身变了一种」才算。
2. **它只能长在我们的题材上**——换一个项目就说不通，才叫咬合；换个皮还成立的，那是通用机制。
3. **它能被一句话教会、被一条断言检验**——教学成本低 ＋ 可机检（本项目全部机制都要求后者）。

外部经验佐证（只取设计结论，⛔ 抄素材/专名/原文文本，链接见文末）：
- 《只狼》的革新点被普遍解读为「把防御做成进攻」＋「用『危』这类不可格挡动作打破纯弹刀的肌肉记忆节奏」⇒ 好机制的标志之一是**它给玩家一个必须重新学习的例外**，而不只是加一个按钮。
- 《死亡细胞》开发者访谈反复强调手感与「让玩家自己组合出解法」的方向（roguelite 的 build 自由度优先于数值精细度）⇒ 特色创新应当**放大既有系统的组合面**，而不是新开一条平行系统。
- 《元气骑士》新手分析指出其战斗就两类武器（近战/远程），近战的通用价值之一是**消解弹幕**（玩家社区的共识用法）⇒ 我们的 S40-a 近战清扫已经在这条线上；「特色创新」要往前再走一步，不能停在借鉴。

🔴 由此得出一条自我约束：**新候选⛔ 引入新的输入 action**（`ACTION_DEFS` 现值 18 条是硬红线），⛔ 新增持久存档结构（除非该候选被判为招牌并愿意付冻结重定的代价）。凡是「必须加键才能玩」的候选，我在代价栏明说它撞哪条线。

## 1. 候选池（6 个，按推荐度倒序展示，排序结论在 §4）

### K1 · 「留痕」——你打死的东西会在地上留一笔，下一层它会来找你

**一句话体验**：你在这一层烧掉的木桶、斩落的剑、放空的弹坑，到了下一层会以「残响」的形式挡在你面前——而你可以**选择再次打散它换取资源**，或者绕开。

**为什么只能长在我们这里**：项目正典里已经有「拾痕者／残响悬铃／回响（词缀）」这条以**痕迹与回响**为核心的语汇层（`data.gd:450-452` 的 `s_echoheal`「回响（词缀）。环盾碎弹回一血」，以及 `icon_resonance` 图标族）。世界观侧同样咬合：`D:\大纲\统一大纲\角色资料库\19_漏洞体质与至高意志（天道）谱系.txt` 讲「世界规则自愈会产生漏洞体质者」——**世界会记住被打碎的缺口并把它长回来**。这不是外挂主题，这是本作母题「皆代价」的直接机制化：你此刻的每一次破坏，都是下一层的负债。换成别的项目（科幻/奇幻通用皮）这套说法立刻塌掉。

**实现代价：中**
- 要动：`dungeon.gd`（房间生成时读入上一层的「痕迹表」）、`game_main.gd`（一层结束时的采集钩子，已有 `cleared_floors` 结算路径可挂）、`prop.gd`/`crate.gd`（销毁时登记位置与类型）。
- 关键约束：**必须零新 rng 消费**——痕迹的复用选取走既有的 `stable_hash % size()` 口径（S33 已实测：出卡路径零 rng 消费，`rng.seed/state` 逐字不动，所以只要沿用 stable_hash 就能保住这条）。⚠️ 同时注意 S33 那条教训：**改动池规模会让全部 `stable_hash % size()` 错位**，痕迹若进任何抽取池，等于全层洗牌 ⇒ 痕迹必须是**独立通道**，⛔ 混进出卡池/掉落池。
- 新状态：一份 per-run 的痕迹数组（不进存档 = 只在局内存在，避开冻结串风险）。

**可机检验收口径**
1. 同一 `SMOKE_SEED` 下跑两遍：第 N 层的痕迹集合（数量＋坐标量化到整数＋类型序列）**逐字相同**。
2. 痕迹产生数 == 上一层「被破坏物」事件计数（探针自己复算，不与实现共用变量）。
3. `Game.rng.seed/state` 在「有痕迹 vs 无痕迹」两种情形下的同帧快照**逐字相等**（证零 rng 消费）。
4. 反向刀：把痕迹塞进出卡池的实现变异，必须让「出卡内容与基线一致」这条断言报红（防假绿）。

### K2 · 「一口价」——所有伤害都从同一个池子里扣，包括你自己的血量上限

**一句话体验**：屏幕上只有一个数字。你砍人掉它、挨打掉它、买卡也掉它；它归零你就死。回血的手段不是「加血」而是「少花」。

**为什么只能长在这里**：`D:\大纲` 全书的骨架母题是**「皆代价」**，且修行体系明文分段：前五境只需「力量积累＋规则理解」，**中五境起每一步都要「代价支付」**（`角色资料库\22_人类十二境实力体系.txt` §二）。一个把「代价」做成唯一资源的 Roguelike，是这个题材的天然形状。现有系统也已经半只脚在里面：`purify_cost`（净化要付）、`SIGILS.cost`（印记开局预付）、残响货币——K2 是把这三条散钱**并成一条命脉**。

**实现代价：高**
- 要动：`player.gd`（hp 与货币合并）、`game_main.gd` 经济结算、`upgrade_panel.gd`/`shop_stand.gd` 定价语义、`meta.gd`（⚠️ `UNLOCKS` 不可改 ⇒ 局外层必须留在旧模型里，只有局内合并）、以及**几乎全部 19 条冻结断言**（受伤/回血/购买三条线的指纹都会漂）。
- 🔴 这条路必然要求**冻结表重定**（作者保留决策权④），不是我或编程侧能自便的。

**可机检验收口径**
1. 单一计数器守恒式：任意时刻 `池现值 == 池初值 − Σ支出 + Σ收入`，探针独立复算每一笔（含伤害、购卡、净化、拾取）。
2. 「回血卡」不再存在 ⇒ 断言池内**没有**任何条目使 `池` 增加以外的正向生命效果（即 `heal` 类效果要么删除要么改为「返还支出」）。
3. 归零即死，且死亡原因串必须记录最后一笔支出的类别（探针可读、可断言）。

### K3 · 「借一刀」——盾反成功后，你的下一次挥击用的是**对方**的兵器

**一句话体验**：挡下那只怪的一记横扫之后，你手上这半秒变成它的武器、它的花样、它的重量；用完就还回去。

**为什么只能长在这里**：直接接在作者本次点名的盾反上（§SPR40 弹幕交互实稿），并且题材侧严丝合缝——同一份 22 号文写第4境·聚炁「可**御物**」，19 号文写漏洞体质的两个方向是「**分流**」（力量流走、难以积蓄）与「**引导**」（把异常引向自身）。「借来的力量一定会还」正是「皆代价」的最小可玩单元。别的游戏做「偷取敌人武器」是战利品逻辑；我们做它是**负债逻辑**（借来的那一下若没打中，代价照付），这才叫咬合。

**实现代价：低—中**（本清单里性价比最高的一条）
- 要动：`player.gd`（一次性的「当前招式覆盖」旁路标志，写法照抄 S38 已验证的 `Game.main._melee_pierce_armor`——**同帧内置位、返回前清零、⛔ 写进持久字段**）、`weapons.gd`（借用表的 kind/reach/arc_deg 三项映射，⛔ 新增 DEFS 条目也行，用常量表更轻）。
- ⛔ 不新增 action（沿用 `shoot`）、⛔ 不改 `ACTION_DEFS`、⛔ 不破「每次有效挥击恒 1 次 `Game.rng.randf()`」（借用只换 `dmg/reach/arc_deg` 三个**参数**，抽取位置一字不动）。
- 依赖 S40-c 的 PARRY 窗口先落地。

**可机检验收口径**
1. 盾反成功后紧邻的第一次 `_swing()` 使用的 `reach/arc_deg/dmg` == 借用表里对应攻击类型的值（探针现读表比对，⛔ 硬编码常数）。
2. 第二次挥击起，参数**回落**为原武器（闩锁一次性，防跨回合残留——这正是 N9/V-B7 那类泄漏的标准验法）。
3. 借用期间 `melee_rng_draws == melee_swings` 仍成立（恒 1 次不被破坏）。
4. 未发生盾反时，借用标志永远为 false（反向刀：把清零那一行删掉必须报红）。

### K4 · 「站桩问事」——你不移动时，防御转化为「听」：静止越久，看得越清

**一句话体验**：站着不动，屏幕上的弹幕会变慢、敌人的意图会显形（提前画出它下一秒要打哪一格）；一动，全部消失。

**为什么只能长在这里**：`D:\大纲\统一大纲\角色资料库\22_人类十二境实力体系.txt` 第2境·定息的意境原文就是「**气定神闲，万邪不侵**」，第5境·凝神「**神识初成，可短暂窥见规则之线**」。这不是我给它找的包装——「静→视」是本作修行体系里已经写好的因果关系。市面上「站桩增益」多做成攻防加成（那是数值皮），我们做成**信息增益**（看见 incoming），恰好与 K 系列之外的盾反窗口（C1 那个 8 帧完美窗）形成互补：**不会弹反的玩家，可以用「静下来看」补偿**。这一条正是「给玩家一个必须重新学习的例外」。

**实现代价：中**
- 要动：`player.gd`（静止时长计时器，`FIXED_DT` 递减）、`bullet.gd` 或敌弹的**表现层**减速（⛔ 真减速会改变命中判定 ⇒ 裁定：只允许画预测线与描边，⛔ 改 `vel`；否则违反确定性）、`hud.gd`（意图提示）。
- ⚠️ 最大陷阱：任何「随时间变化的显示」都可能污染现有探针的时间敏感输出（残留日志 `[SMOKE-NAV]/[SMOKE-CAM]` 一类本来就有实时抖动）。⇒ 提示层必须挂在**探针不比对**的那一侧，并在验证口径里写明「不比对这些行」。

**可机检验收口径**
1. 静止累计时长 = 物理帧数 × `FIXED_DT`，探针独立复算（⛔ 读实现的秒数）。
2. 阈值分档（几档、每档多少秒＝数值待裁）对应的**可见元素数量**单调不减；一旦移动，档位立即归零（归零发生在同一拍，不留尾帧）。
3. 🔴 敌弹 `vel`/`position` 轨迹在「开启本机制 vs 关闭」两组下同 seed 逐字一致（证明它只影响显示、不影响模拟）。这条是最有力的一条，也是防「偷偷做成慢动作」的刀。

### K5 · 「六道轮转架」——双槽不够，六张面孔轮流上场，但同一刻只有一张是真的

**一句话体验**：你有六个姿态（对应六道），切换姿态不给你新武器，而是**改写当前这张卡的规则**（例如「饿鬼」姿态下所有拾取消耗生命但伤害翻倍）。

**为什么只能长在这里**：框架本身就是本作的名源——六道分位是项目既有的顶层框架（素材侧：`D:\大纲\统一大纲\剧情文件\01~06_*剧情分化.md` 的六卷结构，人间道/畜生道/饿鬼道/地狱道/阿修罗道/天道；战力曲线呈 V 字形，详见 `角色资料库\20_六道卷结构与人类实力境界.txt`）。把「六道」做成 HUD 上的六个格子是偷懒（那是名词复用）；做成**六种对同一套规则的读法**才是把框架变成动词。而且它天然回答了一个本项目已有的痛点：卡池深度靠堆条目（S33 实测含净化房比例 2/8~8/8 悬殊、池子规模一变全体错位），而姿态乘区让**同一张卡在六种语境下有六种意思**，不需要扩池。

**实现代价：高**
- 要动：新增一个全局「当前姿态」状态（⚠️ 持久状态新增＝E1 指纹与冻结串的风险源）、升级卡结算（`upgrades.gd`/`upgrade_panel.gd`）、切换输入（🔴 **撞 `ACTION_DEFS` 不加 action 红线**，除非复用 `swap` 的长按或用已有的 `card_1..3` 组合键 ⇒ 需专门裁定）。
- 建议：若被选中，先只做**两态**（人间道/阿修罗道）验证手感，不要一上来铺六格。

**可机检验收口径**
1. 同一张卡在两种姿态下的效果差异表由数据驱动（探针遍历卡 × 姿态矩阵，逐格核实际数值 == 声明值）。
2. 姿态切换本身**零 rng 消费**（前后 `Game.rng.state` 相等）。
3. 存档往返后姿态字段不丢失、不越界（未知姿态值必须回退到默认并 `Dev.err` 点名）。

### K6 · 「一句遗言」——每层结束时，本层杀死你的那件东西会留下一句话

**一句话体验**：死了不显示「你被哥布林杀死」，而是显示一句**那件东西的口吻**的话；攒够同一类的遗言，解锁它对世界的另一种读法（图鉴推进）。

**为什么只能长在这里**：项目已有「残响」这套以**遗留之声**为核心的语汇（`icon_resonance`、`s_echoheal`、拾痕者设定），S39 刚立了一份《手记只说玩家观测得到的事》的 flavor contract（`production/sprint-39/`）——K6 是那份契约的**自然延伸**：手记只能说玩家观测到的事，那么死者留下的话也必须只说**它观测到的事**（一只哥布林不知道你的 build，它只知道「他往左躲了两次」）。这条约束反而让文案质量可机检：**遗言文本⛔ 出现玩家未使用过的系统名**，可以写成断言。世界观侧同样闭合：19 号文写「历代被战胜的神＋漏洞体质者的集合＝万载污秽」——**被留下的声音会堆积**，这正是遗言系统的母题原型。

**实现代价：低**
- 要动：`meta.gd` 侧的图鉴/文案落点（⚠️ `UNLOCKS` 不可改 ⇒ 遗言收集走**只读展示层**，⛔ 当作解锁门槛），加上击杀者身份的传递（现在 `take_damage` 只吃 `from_pos`，需要在死亡事件里回查最近接触者或用 `enemy_bullets` 的来源标记——**这一步是唯一的技术不确定点**，请先做只读盘点再估工）。
- ⛔ 新增 rng、⛔ 新增 action、⛔ 新增持久状态（遗言集只增不减，可以并进现有 meta 存档的字典字段，但它**会不会动 E1 指纹**要先测）。

**可机检验收口径**
1. 同 seed 同死法 → 遗言文本逐字相同（确定性）。
2. 遗言文本经过 flavor contract 校验器（S39 那套 `SPR39_flavor_contract.py` 口径可复用）：⛔ 提及玩家本局未观测到的系统。
3. 遗言条数与死亡次数严格相等，⛔ 空槽、⛔ 重复计数。

## 3. 明确否掉的候选（防止下一轮又有人提）

## 5. Git 托管那句话的处置（不越权，只登记）

作者提到「完全可以把 GitHub 当仓库，上传分支和主体还有备份」。事实核对与边界：
- 本会话（主理人）**职权明令**：⛔ `git commit`、⛔ `git push`、⛔ 刷冻结表以外的仓库写操作。
- 已知网络事实（项目硬事实）：推送连通性**不看 HTTP 码**（内网中间层会返假 200），要用 `git push` 协议握手本身当探针，配 `--force-with-lease=refs/heads/main:<期望远端 tip>`；新证据是默认 HTTP/2 会被中途复位，**`-c http.version=HTTP/1.1` 一次通过**；用一次性内联 URL 推送后本地 `refs/remotes/origin/main` 不刷新，`ahead` 会虚高，⛔ 按它判队列。
- ⇒ 建议：把这事儿**单开一张工程单**（谁建远端、哪些分支进、`.gitignore` 与 `_backup/`/`.godot/` 的边界、冻结表是否入库），⛔ 混进 S40 的任何一批里做。需要我起草那张单子请直说。
