### B-2 但归因句要订正——这里有一条**免费的牙**没被咬

- **同时开一条最小补强（乙案里唯一有边际收益的那半）**：`s63_ev_l6_fourcell_falsify.py` 两 GREEN 态的 `hits` 增补逐字 `"checks_run=%d" % CHECKS_EXPECTED`。边际收益＝X3 从 GREEN 翻 BAD；成本＝零新代码路径、零新沙箱、零新 rng。

## §C 事项 2 细裁：churn 的 FP 面是**只哑不红**的闸——先把方向纠正，再决定动不动码

### C-1 盘上事实（本窗字节级复算，非转述）

- 本窗 python 判等：三份「去掉所有 `\r` 后 base == churn 前 after」**全 True**。⇒ 呈请 §C 的字节普查**成立**；台账 L208 的如实申报**在位**。

### C-2 但「只会假披露、永远不会假红」这句⛔ 入账——它把两面说反了

现读 `spr40_churn.sh`：

- **FP 面（`:58-62`）**：`cmp -s` 不等 ⇒ `echo "FP-$s RED 指纹漂移"; RED=1`。它**不经** `漂移≠0 ∧ okfalse≠0` 那个合取（那是 CHURN 面的 `:44-53`），行尾差**直接把 FP 面置红**。⇒ 行尾差的后果是**假红**，不是假披露。
- **CHK 面（`:66-74`）**：`cmp -s` 不等时打印的是「CHK … 漂移 ⇒（RED 判定=披露不置红…）」，**不置** `RED=1`。⇒ 这一面才是「只哑不红」：内容真变了也不红。

所以本轮那次「base=LF vs after=CRLF」的实际后果是**一次假红风险**（本轮侥幸没踩到，是因为 `:57` 在 `:58` 之前先把 after 重打了一遍，把行尾顺手抹平）。这个顺序**本身就是那道未登记的归一**——它不是「重跑一次把差异抹平」这么无害：`:57` 用 `$AFTER/spr38_g_fp$s.log` 现打 after，意味着**只要 that log 的编码／换行风格变一次，FP 面就自动跟 base 脱钩**，而这道闸既没有「谁写的／什么编码」的披露，也没有失败时的第二意见。

### C-3 裁定：**甲案与丙案同轮一起做，乙案不做**

- **甲（做）**：`cmp` 前两侧 `tr -d '\r'` 归一，FP 行披露「归一＝只掩行尾、⛔ 掩内容」。理由：行尾不是产品语义，把它当内容比＝把 Windows 记事本打开过一次文件当成 E1 指纹漂移，是**噪声置红**；而噪声置红的代价是下一窗学会忽略 FP 行。逐字改点见 §I-1。
- **丙（也做）**：把 FP 面口径成文为「**内容面**：比对去行尾再看」，并把本轮那次归一登记成一次**已发生**的盘上变更（现状即此，只差成文）。这条与本窗 §C-1 的复算合起来就是它的证据。
- **乙（不做）**：起手断言六份 `crlf==0`、否则整面记 `UNEXECUTED`。否决理由三条：①它把「行尾」从内容问题升级成**前提**，于是任何一次合法的产品日志换行变化都会让 FP 面整面失效＝把唯一的 E1 指纹复核降级成盲区；②它与甲案互斥（甲既然归一，断言 `crlf==0` 就成了永不点燃的第二把闸＝R51 §B-2 否决 D 案时用的同一条理由「造一条永不点燃的红，比不造更坏」）；③真要防「after 是被 `:57` 现打的」这件事，该加的是一条**来源披露**而不是断言——见 §C-4。
- **另立一条纪律（不入码，入册）**：⛔ 任何人再靠「重跑一次 churn」来抹平行尾／格式差异。要归一就走甲案的显式归一，并且**在归一之前**把两侧原始 md5 与字节数打在面上（§I-1 的改点已含）。理由：静默归一＝把一次盘上变更藏进门控的副作用里，本轮它已经被台账 L208 如实报出，但那靠的是操作者自觉，不靠机器。

### C-4 顺带修一处呈请没点到名的同类隐患

`spr40_churn.sh:66-74` 的 CHK 面「漂移⇒披露不置红」是 R48 §D-3 立的**有意**口径（机检件读数随产品面合法演变），本窗不动它；但它与 FP 面共用同一个 `cmp`，一旦有人为了 FP 改 `cmp` 就会连坐改变 CHK 面语义。⇒ §I-1 明确要求**只改 FP 那一支**，并在 CHK 面注释行加一句「本面⛔ 继承 FP 的行尾归一（口径＝披露不置红，两侧原样比）」。
