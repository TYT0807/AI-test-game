## §B 根因裁定（我的独立版本，比呈请多一层）

`_tools/spr38_evidence_verify.py:825` 现读：

```python
    _miss_self = [n for n, _s in TEETH_ARMS if n not in _by_sent and n != INCHAIN_AS]
```

豁免集合只有「**不等于本臂**」这一条，没有「**调度上晚于本臂**」这一维。于是三处判据在活链模式下对**任何晚于本臂的兄弟臂**恒假：

| # | 位置（现读行号） | 恒假的判据 | 现场值 |
|---|---|---|---|
| ① | `:825` → `:830-831` | `_miss_self` 把晚臂当缺臂 | `缺=['编译面逐档']` |
| ② | `:843` → `:852-854` | `m_expected = len(TEETH_ARMS) - 1` 只扣自己，没扣晚臂 | `承载臂数=5 != 期望 6` |
| ③ | `:878-886` | 逐臂唯一承载件循环只 `continue` 掉 `name == INCHAIN_AS`，晚臂走到 `len(holders)!=1` | `『COMPILE-ARM GREEN』…命中 0 份（应 1）` |

**这是死锁不是过渡红的证明**（呈请说「跑一趟链即收口」被证伪，我给结构证明）：
第 7 臂的承载件只能由第 7 次 `teeth()` 调用产出；那次调用的**起点严格晚于**第 6 臂自己的进程。第 6 臂在 `:825/:843/:878` 做判断的那一刻，磁盘上**不存在**、也**不可能存在**本轮的第 7 臂承载件。上一窗那份第 7 臂日志会被 `win_state()` 判成 `XWIN`／`STALE`（`:804-812`）而**不进 `tails`**，同样进不了 `_by_sent`。⇒ 只要「第 7 臂排在第 6 臂之后」这个调度关系不变，**无论跑多少趟链，teeth6 恒 RED**，`RUN-GREEN` 不可达。

姊妹件 `_tools/spr38_report_selfaudit.py:257-262` 已有正确解法（现读，逻辑我已核）：

```python
    order = sorted((a for a, _ in TOOTH_ARMS if a in sched), key=lambda a: sched[a][0])
    idx_miss = [i for i, a in enumerate(order) if a in missing]
    is_suffix = bool(idx_miss) and idx_miss == list(range(len(order) - len(idx_miss), len(order)))
```

即「缺的臂必须构成脚本调度序的**后缀**才豁免，前缀／中段缺臂一律红」，且它的开关**配合新鲜独占锁**（`:221-224`），脱离链设 env 也见红。**这套形状是经过反证的**（`:725-741` 一红一绿两态），可直接参照——但**不能整块复制**，见 §C-1 的两点差异。
