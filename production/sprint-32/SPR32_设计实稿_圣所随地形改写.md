## 1 现状与靶子

现行 `_shrine_offers_for(coord)` 两步：先按 `min_floor`（`:3289`）与「`purify` 需 `_calamity != ""`」（`:3291-3292`）过滤出 `pool`，再用 `stable_hash` 在 `pool.size()` 上抽 3 个不重复索引（`:3299-3304`）。抽法是「独立均匀 → 线性探查」，等价于**在 `pool` 上均匀取 3 子集**，因此任一张卡的命中率恒为 `3/N`，与地形、灾祸、玩家状态全无关。

`N` 的现值（实读表 + 门槛）：

| 楼层 | 主题 | `N`（无灾祸 / 有灾祸） | 单卡基线命中率 |
|---|---|---|---|
| 3 | 无 | 5 / 6 | 0.600 / 0.500 |
| 4 | vein | 5 / 6 | 0.600 / 0.500 |
| 5–6 | toxic / pressure | 8 / 9 | 0.375 / 0.333 |
| 7–11 | silent…vines | 9 / 10 | 0.333 / 0.300 |

> 上表是**理论基线 `3/N`**（仅在 hash 均匀假设下成立）。实测因 FNV-1a 在有限网格上并不均匀，单卡会明显偏离：N=8 实测从 `relic_suffix 0.1648` 到 `greed_pact 0.4182`。这不改变本节的结论（分布**只由 seed 与坐标决定、与地形无关**），但意味着 §5 的 expect 只能用实测值或区间，不能用 `1/N`。

问题不在数值，在于**选择空间不被环境改写**：

1. 岩浆层（0.5 秒一次全地板税，`:2061-2065`）与冰面层（`terrain_accel_mult = 0.3`，`:1987-1989`）给玩家的**压力形状完全不同**——一个是「待得久就掉血」，一个是「刹不住就撞上」——但圣所给的三张卡分布一模一样。
2. 玩家在圣所里的决策因此退化为「这个 seed 给了我什么」，而不是「这个地形里我该换什么」。跨主题的最优选择策略不变 → 圣所不进决策空间，只进补给链。
3. 唯一的主题反应是 `purify` 的灾祸门槛，但它读的是 `_calamity`（本层有没有灾祸），不是地形，而且是「有/无」二元，不构成倾向。

这是本项目当前的主矛盾在圣所上的具体形态：**Mechanics 已经过饱和（10 张卡各有代价与效果），Dynamics 贫乏（10 张卡在任何地形下都同分布）**。本批不新增第 11 张卡，只让已有 10 张卡按地形重新分布。

## 2 八个主题各倾向什么（全文核心）

判据只有三条，全部从主题**正在做什么**推出，不用「难/易」：**(甲) 成本相对性**——本层让哪种货币变便宜；**(乙) 伤害的时间形状**——本层伤害是「偶发命中」还是「连续税」；**(丙) 兑现前提**——这张卡要生效，需要本层是否还保留某个前提。

| rule（首现层） | 本层杠杆（实读） | 更常 | 更少 | 理由（一句） |
|---|---|---|---|---|
| `vein` 往生脉（4） | 每次击杀额外掉 1 残响（`:3068-3069`） | `ore_upgrade`、`ward_boon` | `greed_pact` | 本层把残响供给抬高 → 「花残响」（8 / 5）的相对成本下降，而「用血换残响 +10」在本层是拿稀缺资源换充裕资源（甲）。 |
| `toxic` 毒巢（5） | 每 3.0 秒 1 点全房间 DoT（`:2056-2060`、`:2069-2085`） | `heal` | `ward_boon` | DoT 走 `take_damage(1,…)`，而护盾在扣血之前就被消耗（`player.gd:1844-1851`）→ 护盾被一次**必吃**的 tick 烧掉，从「容错保险」退化为「3 秒延时券」；而 `heal` 的 +2 血恰好等于 6 秒税（乙）。 |
| `pressure` 高压层（6） | `enemy_speed_mult ≥ 1.3`、`diamond_mult ≥ 1.5`（`:1984-1986`） | `wind_dance` | `power_surge` | 本层压缩的是**相对速度**（敌人 1.3× 而你未变），+25% 移速直接把它拉回；而失败模式是「被追上」而不是「打不死」，用 1 点血上限换 30% 伤害是把唯一容错余量换成本层不解的题（丙）。 |
| `silent` 静默层（7） | 小地图隐藏（`:2000`）；`frail` 削减 0.4，全表最高（`:565-569`，死数锁在 `:686`） | `purify` | —（空） | 本层灾祸的绝对损失最大（血上限 −40%），所以「解除本层灾祸」的绝对收益最大（乙/甲）。**刻意不设 down**：地图被隐藏后玩家要靠**走**去找出口，移速的兑现渠道变**多**而不是变少 —— 与本主题杠杆同向，推不出「更少」。 |
| `magma` 岩浆灼烧（8） | 每 0.5 秒 1 点全地板 DoT（`:2061-2065`） | `power_surge` | `heal` | 税基是「你在这层待了多久」，+30% 伤害压缩战斗时长等于直接压缩税基；反之 `heal` 的 +2 只抵 1 秒火 tick，被时间稀释到近乎无意义（乙）。 |
| `ice` 冰面打滑（9） | `terrain_accel_mult = 0.3`，加减速同降（`:1987-1989`、`player.gd:294-296`） | `ward_boon` | `wind_dance` | 撞上不是判断错而是刹不住，一次性免伤正好对上这种「非操作失误」的伤害；而移速上限 +25% 抬高 `target_vel`、`move_toward` 速率仍 ×0.3 → 起步更久、停得更晚，本层净负（乙/丙）。 |
| `swamp` 毒沼减速（10） | `terrain_speed_mult = 0.7`（`:1990-1992`） | `wind_dance` | `blood_relic` | `0.7 × 1.25 = 0.875`，把被削的绝对移速拉回大半，本层唯一杠杆就是绝对移速（丙）；又因为跑不掉只能扛，血上限从「资源」变成「唯一缓冲」，削上限的卡在本层最贵（甲）。 |
| `vines` 藤蔓阻挡（11） | 3 处 `solid` 藤蔓（`:2902-2906`；`data.gd:486` hp2/solid） | `heal` | —（空） | 场地被切成走廊 → 接触从「偶发」变「连续」，一次性免伤被摊薄、持续补给才对上形状（乙）。**刻意不设 down**：绕开 `solid` 藤蔓让需要走的绝对路程更长，速度照样兑现 —— 推不出「更少」。 |

三条必须点明的横向事实：

1. **同一个 `heal` 在 `toxic` 判「更常」、在 `magma` 判「更少」**，因为 tick 间隔差 6 倍（3.0s vs 0.5s）：`+2` 在毒巢是 6 秒预算，在岩浆是 1 秒。若本批是「难 → 卖强的」，这两格不可能反向 —— 这是本方案不是惩罚倍率表的正面证据。
2. **`ward_boon` 在 `vein`/`ice` 判高、在 `toxic` 判低**，判据始终是同一条：免伤的形状（挡一次命中）是否与本层伤害的形状（偶发命中 / 连续税）对得上。
3. **`wind_dance` 在 8 个主题里出现 3 次（↑2 / ↓1：↑`pressure`/`swamp`、↓`ice`）**，因为它是表内唯一作用于位移的卡（`data.gd:322`）—— 只有杠杆直接压在位移上的主题才指向它，其余 5 个主题不指向。初稿曾给 `silent`/`vines` 也配 ↓，两格都被推翻：静默层关掉小地图后玩家靠**走**去找出口（兑现渠道变多），藤蔓层绕 `solid` 让绝对路程更长（速度照样兑现）。S27 立的规矩是「方向必须能从本主题杠杆推出」，推不出就删，不挂着当装饰。

未列入偏向的卡：`relic_suffix`（`min_floor 5`）、`shard_pact`（`min_floor 5`）在 8 个主题下**保持中性**——前者收益取决于「你手上有没有对应遗物」（`data.gd:185-209` 的 trigger 绑定），后者是局外货币，都不随本层杠杆移动；强行给它们编偏向会制造噪声而非动态。

## 3 实现机制（三案对比，选 C）

三案共同前提：`pool` 的过滤逐字不动（`:3287-3293`）、`pool.size() < 3 → return []` 不动（`:3294-3295`）、`key` 表达式逐字不动（`:3296`）。

| | 案 A 加权槽位（重复入池） | 案 B 首槽偏好子池 | **案 C 三段定向池（选）** |
|---|---|---|---|
| 做法 | 偏好卡在池里占 3 槽、中性 2 槽、低偏好 1 槽，仍走原 3 次抽取 | `#0` 只从偏好池抽，`#1/#2` 照旧从全池抽 | `#0` 抽偏好池；`#1` 从「池 − 首卡 − 低偏好」抽；`#2` 从剩余抽 |
| key | 不动 | 不动 | 不动（三个 hash 串 `#0/#1/#2` 与 `:3300` 逐字相同） |
| 确定性 | 是 | 是 | 是 |
| 「更少」可验 | 是（加权能压低，但需额外 id 去重） | **否**——低偏好卡与中性卡同值，无法区分 | 是（`down` 结构性不进 `#1` 候选池；N=9 实测 0.1077 / 0.1344） |
| 同卡重复风险 | 有：重复槽位会让同一 id 被抽两次，须额外 id 去重 | 无 | 无（三段池按 id 去重构造） |
| 池槽膨胀 | 2–3×，且 3:2:1 是新常量档位 | 无 | 无 |
| 可感知度 | 低（偏好卡约半数） | 高（1.0） | 高（1.0，偏好唯一时） |

**判 A**：需要 id 去重 + 引入新权重档位，且偏好卡只到 0.49，玩家在一次 run 的 5 个主题层里很难感到差别；「可判定」与「可感知」两头都不占。
**判 B**：实现最简，但「更少出现哪张」在机制上与中性卡同值 —— §2 剩下的 6 个「更少」全部不可验，等于没写。
**选 C**：`down` 通过「不进 `#1` 候选池」获得结构性压低，单点构造即可验；不需要重复槽位、不需要 id 去重、不新增权重常量；偏好唯一时首槽恒为该卡，可感知。

改动点（精确到行，示意，非最终代码）：

```
pool = 现行过滤（:3287-3293 逐字不动）
if pool.size() < 3: return []                                   # :3294-3295 不动
key = "%d_%d_%d" % [Game.run_seed, Game.floor_num, coord.x*1000+coord.y]   # :3296 不动
pref/down = _shrine_theme_pref() ∩ pool                         # 新增纯函数，见下
if pref.is_empty(): 现行 :3299-3304（逐字等价）
p0 = pref[stable_hash("%s#0" % key) % pref.size()]
p1 = (pool − p0 − down)[stable_hash("%s#1" % key) % 该池.size()]
p2 = (pool − p0 − p1)[stable_hash("%s#2" % key) % 该池.size()]
```

四点必须写进实施单：

1. **hash 串不变**：`"%s#0"`、`"%s#1"`、`"%s#2"` 与 `:3300` 的 `"%s#%d" % [key, i]` 逐字相同，变的只有被取模的池。这是本批「key 不动」的最严读法。
2. **载体**：`_shrine_theme_pref()` 用 `match Data.theme_for_floor(Game.floor_num).get("rule", "")` 返回两个 `Array[String]`，与 `_frail_ratio()`（`:565-569`）同型，**落在 `game_main.gd`、不碰 `data.gd`**（后者是冻结项，见 §7.1）。**禁止读 `_theme_rule` live**：它只在 `_apply_floor_theme()`（`:1965`、`:1977`）与读档还原（`:1522`）处赋值，而 `player.gd:859` 的探针只改 `Game.floor_num`、不走这两条链 → 读 live 会让探针与真实楼层不自洽；「经 `Data.theme_for_floor()` 派生、不直查 `FLOOR_THEMES` 表」是 `:604-606` 已立的唯一合法入口（直查在第 12 层拿空字典）。
3. **恒可解**：`|pool| ≥ 3` 且 `|down| ≤ 1` → 三段候选恒非空（最坏 `|pool|=3, |pref|=2, |down|=1` 时依次为 2 → 1 → 1），无 `while`、无死循环。
4. **零偏好等价路径**必须与现行 `:3299-3304` 行为等价（同一 `pool`、同一 `used` 探查语义），这是「1–3 层逐字不变」的唯一保证。

## 4 边界与已知取舍

1. **`purify` 门槛 × 主题偏好**：`silent` 的偏好是 `purify`，但 `purify` 只在 `_calamity != ""` 时入池（`:3291-3292`）。无灾祸的静默层 → `pref` 为空 → **整层退回完全无偏向**。**已裁定接受**（§7.4）：放宽 `purify` 门槛会改掉过滤语义（且让无灾祸层出现一张空卡），代价远大于「偶尔少一次偏向」。副产品是 `silent` 成为唯一「偏好存在但可能整层失效」的主题 —— 这是真实状态，不要用副偏好去掩盖。另需记牢：`purify` 的 `cost_kind` 是空串、`cost = 0`（`data.gd:316`），但**它不免费**——`_shrine_execute` 里 `Game.purified_run = true`（`:3351`）作废本局 ×1.5 结算加成。所以「静默层首槽 100% 出净化」不等于白送：平衡由代价守，不由出现率守。
2. **`min_floor`**：`pref`/`down` 与 `pool` 求交后自然受门槛约束。首现层可满足性逐条核过：4/vein ✔、5/toxic ✔、6/pressure ✔（`wind_dance` 门槛 5）、7/silent ✔、8/magma ✔（`power_surge` 门槛 7）、9/ice ✔、10/swamp ✔、11/vines ✔。`down` 为空共三种来源，必须分清：①**设计上为空**——`silent` / `vines`（§2，杠杆推不出「更少」）；②**门槛未解锁**——`pressure` 首轮（第 6 层）`power_surge` 尚未入池，该轮只有上行偏向，第 14 层起才双向；③**整层无偏向**——`silent` 无灾祸（§4.1）。②是「同一主题在不同层强度不同」，刻意保留、不做补齐；①③是语义正确，不是缺口。
3. **池被过滤到只剩 2 张**：现行 `return []`（`:3294-3295`）**保留**。房型门槛（`dungeon.gd:137`，`floor_num >= 3`）加上 6 张 `min_floor = 3` 的卡（其中 `purify` 另有灾祸门槛，实到 5 张），正常流程不可达；该分支只在探针/极端过滤下出现，本批不借机改「圣所不出现」的语义。三段池不新增任何空池。
4. **同层重进同一圣所必须同组卡**：`key` 含 `run_seed`、`floor_num`、`coord`（`:3296`），函数内无状态、无 rng、无时间 → 重进再派生必然逐字相同。`_on_shrine_chosen` 只回写 `cleared`（`:3397`），不重发。**不需要新增任何缓存或标记**。
5. **影响面（必须提前打招呼）**：1–3 层出卡逐字不变；4 层以上**所有**圣所三卡重排（约八成以上的圣所访问）。`_tools/qa_spr17_full.log:59` 记录的 `floor=5 offers=["ore_upgrade","wind_dance","heal"]` 会变 —— 历史 log 不是回归基线，只有 §5 的差分构造才是。
6. **key 冲撞提醒**：`coord.x * 1000 + coord.y` 在 `|y| < 1000` 内唯一；§5 的坐标网格必须守此界，否则会观察到「不同坐标同组卡」的假象（现状既有，不是本批引入）。
7. **已试过、更差的替代（别重走）**：为了压掉基线离散，试过把「候选子池」换成「全池定址 + 探查」，实测**更差**——`relic_suffix` 从 0.16 量级涨到 **0.624**，且 `down` 的结构性压低消失（探查会跳过被排除项，等于根本没有 `down`）。结论：三段池维持不变；离散不是靠改取模/探查能解的（病灶归因见 §5 末），动它只会把别处弄坏。

## 5 可判定的验证构造

两个靶，一律 **N=9**：

- **主靶 `ice`**（`floor = 9`，`_calamity = ""` → `pool` 9 张，`pref = {ward_boon}`、`down = {wind_dance}`）。选它是因为它同时保留 `pref` 与 `down` 两个面，且 `wind_dance` 是 §2 里**唯一保留的位移类低偏好**——验它等于验最容易被质疑的那一格。
- **副靶 `toxic`**（`floor = 5`，`_calamity = "frail"` → `purify` 入池，`pool` 9 张，`pref = {heal}`、`down = {ward_boon}`）。结构同型、卡不同，用来交叉；顺带验「池里有 `purify` 时偏向照常成立」。

坐标网格 `x, y ∈ [-20, 20]` 共 1681 点（守 §4.6 的 `|y| < 1000`），`Game.run_seed` 固定。

> **expect 只写实测值或区间，禁止写 `1/N`、`3/N` 这类理论值。** 实测（FNV-1a 逐字副本跑 1681 网格）：N=8 时中性卡从 `relic_suffix 0.1648` 到 `greed_pact 0.4182`（公平值 0.306）；同为 N=9 的同型结构，`down` 在 `ice` 量到 **0.1077**、在 `toxic` 量到 **0.1344**。理论与实测不是差一点，是差一档——N=8 若按理论 `1/6 = 0.167` 设 `≤0.24`，`toxic` 实测 0.2635 会把**正确实现判红**。

**副靶交叉**：`floor = 5` + `_calamity = "frail"` → `heal = 1.0000`、`ward_boon` 实测 **0.1344**，阈值 `≤ 0.20`。主靶与副靶结构同型却量出 0.1077 / 0.1344 两个数 —— 这正是「点值不可移植、只可移植上下界与方向」的实证。

**中性卡为什么不设点值断言**：N=8 实测 `relic_suffix 0.1648` / `greed_pact 0.4182`，散度 0.25；任何形如 `heal ∈ [0.23, 0.30]` 的窗口换 seed 就会误杀。判别力已由「`pref` 恒 1.0」与「`down ≤ 0.20`」两条拿走，中性卡只保留一条可移植的相对断言：**指定中性卡的命中率高于 `down` 卡**（方向性，不绑点值）。

**散度的正确归因**（别写成「线性探查让边际不均匀」）：现行实现各 N 的基线离散都很小（spread ≤ 0.04），**探查恰恰是把分布拉匀的机制**。真实原因是 `#1`/`#2` 两次派生同源相关，加上 `p1` 被取走后 `#2` 的索引→元素映射整体错位。病灶不在探查，动它只会把别处弄坏。

**双 `pref` 面（`vein`）的验法**：`floor = 4`，`pref = {ore_upgrade, ward_boon}`、`down = {greed_pact}`。断言用互补 + 宽带：`P(ore_upgrade) + P(ward_boon) = 1.0000`（结构性），且两张各自 `∈ (0.20, 0.80)`（不绑点值）。⚠️ 与「N=8」口径不一致：`vein` 首现第 4 层，池只有 5 张（无灾祸）/ 6 张（有灾祸）；第 12 层已到 9/10 张 —— **`vein` 面上 N=8 不可达**，故按可达的最小 N 档写。若必须凑 N=8，只能换到 `toxic`/`ice` 面，但那两面是单 `pref`，验不到分裂，故不换。

关于 #4 的适用范围：指纹只打 `rooms=` / `kinds=`，圣所出卡既不进 `_smoke_fingerprint`（`:333-348`），也不进 `_shrine_offers` 的落盘（`:3400` 注释明示抉择链不进指纹），且本批不动 `dungeon.gd` 的生成（`kind` 与坐标不变）→ **本批预期零重定**。但要把话说全：**如果哪天把圣所出卡写进指纹（或写进 `rooms`/`kinds` 的派生），这批就必须重定**，因为 4 层以上出卡全变。

既有探针影响：`player.gd:854-866` 的 `SMOKE_SHRINE` 断言「同 key 两次一致 + 大小 3」，改后仍绿（`ids_c` 只打印）；`:867-874` 走显式 `_shrine_entry`，不经池，不受影响。
