## 五 偏差裁定（交付列 5 条，我逐条判 + 自跑发现 2 条）

### 1｜刀三红集缺 M2 → **口径过度预测，M2 保持硬编码**

实读机理：`pref`/`down` 互换后，原 `down` 的 id（如 ice 的 `wind_dance`）变成 `pref` → **恒占首槽**；而 M2 检查的是「第二槽是否等于硬编码的 down id」，第二槽从此不可能等于它 → **结构性必绿**。

- 🔴 **不许把 M2 改成「动态读当前 down 集」**：那样 M2 就变成「实现自己和自己比」，任何错误的 down 集都不会红——**从「一处盲区」退化成「永久失效」**，比现在差得多。
- 互换本身已被 **11 条**（S1 S2 S3 S4 M1 M4 M5 M6 M7 M9 D4）抓住，无真实漏网。
- 裁定：**M2 保持硬编码 + 口径 §三 刀三的预测红删掉 M2**，并写明原因（见 §六 补注 1）。

### 2｜G2 行数不是稳定判据（我自跑发现，比偏差 1 严重）

交付报「300 帧 4 行」，验收侧基线也是 4 行。**我在本机跑 300 帧两次、900 帧一次，三次都是 6 行**（`det` / `floor=5` / `chose`×2 / `D flavors` / `done`）。

原因：该探针是 `await get_tree().create_timer(...)` 的**真实时间**异步链，而 `--quit-after N` 数的是**帧**。headless 下每帧耗时随机器负载波动 → 同一帧数下「跑到第几行」不确定。验收侧当时量到 4，是**截断快照**，不是完整基线。

🔴 **结论：任何以「恰 N 行」为判据的门都是随机器浮动的**。G2 判据必须改为「**出现 `[SMOKE-SHRINE] done` 行 + `[ERR]`=0 + 只允许指定行文本变**」，并把帧数提到 900 保证跑完。这条比预测错红更危险——**它会让同一份正确实现在不同机器上得出相反结论**。

### 3｜G2 `chose=` 一行变更 → **接受**

`chose=shard_pact → heal`：f=5 是 `toxic`、`pref=heal`，首槽恒为 `heal`，autopick 遂选 `heal`。这是本批设计的直接后果，不是回归。

### 4｜刀六用 proxy → **接受**

红集 `{S1,M1,M3}` ⊇ 预测 `{S1,M3}`，属低估方向的超集。proxy 与真·加权不等价，但**变异被充分捕获**，该刀目的（证明 M3 能抓重复 id）达成。

### 5｜刀九崩溃并连带 P1 红 → **接受**

删 `pr.is_empty()` 后无偏好时 `pr[hash % 0]` 越界 → D3/M8 红 + P1 连带。属该刀预期副作用；正向也证明 P1 不是空转。

### 6｜刀一额外红 S5 → **接受**

`pref` 全空回退基线，中性卡升到 ≈0.33 个别越上界 → S5（前提守卫）红。合理连带。

### 7｜`_S32_DECLARED` = 19（非 23）→ 已对齐

交付按实施单写 19，与口径「23 = 探针 19 + 门外 4」一致。我复核 `done checked=19 declared=19`。
