## 0. 结论速览

| 项 | 判定 |
|-|-|
| 三条 Story 与交接稿 §三「已完成的」 | **无重写型冲突**，均为增量扩展；但有 **3 个契约同步点** 与 **1 个必须防的实现误改点**（见 §0.1） |

| §七 六条遗留一致性 | **完全一致**：3 条覆盖 / 3 条未覆盖，未覆盖的 3 条正好是用户明确排除的 S-02/S-05/S-06（§6） |

### 0.1 三个契约同步点 + 一个防误改点（给主理人转达工程 / QA）

1. **防误改点（最高优先）**：现有普通秘密房的「夹在 2 间房之间」是**已完成设计**（交付稿 §二、玩法说明.md:34、代码 `dungeon.gd:130` 的 `cnt >= 2`）。S-01 的「只连 1 间房」应作为**并存的新类型**落地，**不得把 `_find_secret_cell` 的 `cnt >= 2` 改成 `cnt == 1`** —— 那会改写既有房间规则，并可能改变验收基线里的 `secret revealed` 计数。
2. 新增房间 `kind` 会牵动 8 处既有契约（§7 表格），其中 `validate.gd:7` 的 `KNOWN_ROOM_KINDS` 与 `data.gd:113` 的 `ROOM_META` 不同步会直接让开局自检打印 `✗` 清单；`hud.gd:375` 的小地图 mark 表、`hud.gd:330` 的 `set_room_info` 映射漏改会表现为「超秘房没标记 / 层数标签错」。
3. **自动验收覆盖缺口**：`game_main.gd:1044` 的 `_smoke_secret_tick` 与 `game_main.gd:516` 的 `autopilot_door_target` 都只认 `kind == "secret"`。若超秘用新 `kind`，SMOKE 挂具**不会自动炸超秘墙、也不会主动走进去**，即现有 6 条验收基线**不会覆盖 S-01**。需 QA 补验收手段（此点属跨成员，按分工只报主理人转达，不直接联系）。

## 2. 三条 Story 规格

### 2.1 S-01 超级秘密房

**验收标准（什么算做完）**

| # | 判据 |
|-|-|
| A1 | 每层可生成 1 间超级秘密房，其相邻房间数**恰为 1**（`dungeon.neighbors(cell).size() == 1`）；与普通秘密房格子不重叠、两者可共存 |
| A2 | 未揭示前小地图**不显示**（同 `hud.gd:353` 规则）；唯一入口方向生成**裂纹墙**而非可见门，且只吃炸弹、子弹无效 |
| A3 | 炸弹炸开后 `revealed = true`，重建出正常门；**门锁按 `room_state` 正确解锁**（复用交接稿 §五-6 的坑，超秘房同样适用），玩家可进入且不卡死 |
| A4 | 内含**明确可区分于普通秘密房**的稀有掉落（具体物件的选项见 §3.5，需用户拍板） |
| A5 | 找不到合法单连接空格时**静默跳过本层**，不崩溃、不强行放到非法格（不产生死内容） |
| A6 | 既有验收基线不退化：种子 4/5/6 仍 `0 SCRIPT ERROR` / 到第 2 层 / `secret revealed` 出现 / `use_door` 量级正常；纯净启动 0 报错；开局自检 `✗` 清单为空（房间数由 8 变为 9 需同步，见 §7） |
| A7 | 普通秘密房「夹在 ≥2 间房之间」「不贴 Boss」「固定 1 间/层」的规则**保持不动** |

**玩家可感知价值**：在既有「贴墙找裂纹」的探索循环上加一个**更隐蔽、单入口、高回报**的目标，把「探索 thoroughness」变成有差异化的收益；稀有掉落提供一次构筑跃迁感，形成「多花 1 颗炸弹换一次质变」的取舍。属于 Bartle 探索型 + 成就型动机。

**与交接稿 §三 已完成设计的冲突核对**

| §三 条目 | 判定 |
|-|-|
| 「房间：起点/战斗/精英/宝箱/商店/Boss + 秘密房 + 无伤挑战房」 | **扩展，非冲突**。但会改变「隐藏房只有 1 种 / 秘密房固定 1 间/层」的隐含约定 —— §七-3 自己把它列为「可扩展」，故方向一致 |
| 「工程：数据注册表、启动自检、分类日志、F3 面板」 | **契约冲突点**：新增 `kind` 必须同步 `validate.gd:7` 与 `data.gd:113`，否则自检报 `✗`（§7） |
| 「10 遗物 / 14 升级（含稀有度）」 | 若「稀有掉落」复用遗物或升级卡，**不得引入新稀有度层级**（会与 S-05 越界），只能在既有池内取值（§3.5） |
| 「秘密房夹在 2 间房之间」（交付稿 §二、玩法说明.md:34） | **必须保留**，见 §0.1 防误改点 |

**边缘情况（≥3 类）**
1. 地图过密 / 全被占用 → 无合法 `cnt == 1` 空格 → 静默跳过（A5）。
2. 唯一邻房是**另一个未揭示隐藏房**或不可达格 → 玩家永远找不到入口（死内容），选格阶段必须排除。
3. 一层同时有普通秘 + 超秘，而初始炸弹 2 颗、上限 3（`player.gd:23-24`）→ 至少一间炸不起；需检查炸弹补给是否够（§3.4）。
4. 炸墙重建后门重置为上锁 → 玩家被关（交接稿 §五-6），超秘房同样要补解锁。
5. 已揭示但未进入就下楼 / 死亡重开 → `revealed` 状态不得跨层残留，不得重复领奖。
6. 超秘房与 Boss 房同层相邻时，SMOKE 自动驾驶的「全图清完兜底走 Boss」不得被超秘房带偏（`game_main.gd:509-522`）。

### 2.2 S-03 HUD 护盾 / 连锁 / 淬毒状态显示

**验收标准**

| # | 判据 |
|-|-|
| B1 | HUD 显示三项：`shield_charges`（护盾层数）、`chain_chance`（连锁）、`poison_chance`（淬毒），数值与 `player.gd:51-53` 一致 |
| B2 | **实时刷新**：护盾受击 −1（`player.gd:459-461`）、升级 +1 / 概率 +0.25 / +0.3（`upgrades.gd:91-96`）后 HUD 同帧或下一帧正确，不显示负值、不滞后 |
| B3 | **未获得不占位**：三项全为 0 时徽标行整体隐藏；单项为 0 时单项隐藏 |
| B4 | 与血条 / 经验条 / 生命文字 / 炸弹 / 钻石 / 得分 / 时间 / 击杀 / 层数 / 小地图 / 横幅 / Boss 条 / 连杀 / 技能条 / 武器槽 / 操作提示 / toast / 暂停 / 结算 **无视觉重叠**（避让区见 §4.3） |
| B5 | 认知过载控制：常驻图标 ≤ 3 个、单个 ≤ 20px、**不新增常驻文字行**、不新增输入按键 |
| B6 | 数值表述与升级卡文案一致（升级卡写「命中 25% 概率弹射」「命中 30% 概率使敌人中毒」，`upgrades.gd:16-17`），不得同一属性出现两套说法 |
| B7 | `0 SCRIPT ERROR`；暂停 / 结算覆盖层（`hud.gd:37-38` 的 `PROCESS_MODE_ALWAYS`）显示时状态行不穿透抢焦点 |

**玩家可感知价值**：把「我选了什么 build」「还剩几层护盾」从靠记忆变成一眼可见。尤其护盾是**史诗级**升级（`upgrades.gd:18`），目前只有受击瞬时 toast，玩家很难感知它的持续价值；显示后能显著降低构筑认知负担，并让「要不要用护盾硬吃一下」成为可读的决策。

**与 §三 冲突核对**：完全**只读展示**既有字段，不改数值、不改升级表、不改受击逻辑 → 无冲突。唯一契约缺口：`game_state.gd` 全局信号里**没有**这三项的信号（现有 HUD 靠 `_process` 每帧读 `Game.main.player`，见 `hud.gd:396-402`），实现路径需与工程对齐（属可实现性，不替工程决策）。

**边缘情况（≥3 类）**
1. 三项全 0（开局）→ 整行隐藏，不留空白/占位框（B3）。
2. 升级获得护盾与受击消耗在相邻帧发生 → 刷新顺序不能出现「先显示再瞬间归零」或负值（B2）。
3. Boss 条 + 横幅同时出现（顶部中央）→ 状态行不得被推入该区域（B4）。
4. 升级面板三选一打开期间 `_process` 仍在跑 → 状态行刷新不得与面板抢焦点。
5. SMOKE 自动驾驶下字段高频变化 → 不影响 0 报错基线。
6. 死亡结算覆盖层显示时，状态行应随遮罩一起弱化/隐藏，避免"你倒下了"上方还挂着 3 个亮图标。

### 2.3 S-04 挑战房失败也给小奖励

**验收标准**

| # | 判据 |
|-|-|
| C1 | 挑战房**掉过血**结算时，在现有 3 颗钻石之外，给一个**明确可感知、有独立反馈**（掉落物 + toast/横幅文案）的小奖励 |
| C2 | 该奖励价值**显著低于**无伤额外奖励（遗物 + 大宝箱 + 200 分），**不倒挂**（§5.3） |
| C3 | **固定值、与掉血次数无关**（防「故意卖血刷奖励」主导策略） |
| C4 | **无伤分支完全不变**：3 钻石 + 遗物 + 大宝箱 + 200 分 + banner「无伤通过！」（`game_main.gd:313-320`）保持原样 |
| C5 | 文案区分「失败但给安慰」与「无伤通过」，**不得**沿用现文案「只有普通掉落」造成误导（该文案与代码事实也不符，见 §5.1） |
| C6 | 重进已清挑战房**不重复结算**保底奖励 |
| C7 | `0 SCRIPT ERROR`；SMOKE 下 `challenge failed` 分支可复现（`game_main.gd:311-312`） |

**玩家可感知价值**：消除「打完一波强敌却几乎空手」的挫败，保留「下次想拿无伤大奖」的进取动机 —— 属于自我决定论里「胜任感受挫后的软着陆」，而非奖励补偿。

**与 §三 冲突核对**：挑战房是 §三 已完成房间类型，本 Story **只改结算掉落分支**，不改进房、刷怪、锁门、无伤判定 → 无结构冲突。但 §七-5 措辞与代码有事实偏差（§5.1），且「小奖励」若选错物件会与稀有度体系 / S-05 越界。

**边缘情况（≥3 类）**
1. **护盾挡下伤害不算掉血**（`player.gd:459-464` 提前 `return`，未 emit `damaged`）→ 玩家可带护盾「免伤通关」，削弱无伤挑战难度，需拍板（§5.5）。
2. 重进已清挑战房 → 不再结算，保底奖励不得重复领（C6）。
3. 同一帧多次掉血 / 掉血后清场瞬间玩家死亡 → 保底奖励只给一次、结算顺序不产生重复或丢失。
4. 尖刺 / 爆炸桶自伤是否计入 `_room_damaged` → 判定来源需工程确认（`_room_damaged` 只由 `player.damaged` 置位，`game_main.gd:100-103`）；设计侧要求**所有 hp 实际减少**都一致计入。
5. 保底奖励不得是遗物 / 大宝箱 / 升级卡 / 武器 / 200 分（C2、C4）。

## 3. S-01 专项：连接数约束与地图生成的设计侧判定

> 本节只给**设计侧判定与约束**，不替工程做实现决策（选格算法、数据结构、`kind` 命名、是否改 `_makes_block` 均由工程定）。

### 3.1 现有机制实读（证据）

| 事实 | 位置 |
|-|-|
| 主游走随机走出 `count` 个房间，每步用 `_makes_block` 挡掉 2x2 密铺 | `dungeon.gd:35-50`、`dungeon.gd:136-142` |
| 死端 = 恰好 1 个邻居；被征用作宝箱房 / 商店房 | `dungeon.gd:64-97` |
| 秘密房在死端分配**之后**单独放置，每层最多 1 间 | `dungeon.gd:99-102` |
| 选格：遍历已有房间的四邻空格 `n`，要求 `cnt >= 2`（`cnt` = `n` 的相邻已有房间数）且 `not touches_boss` | `dungeon.gd:116-132` |
| **秘密房格子直接放置，未调用 `_makes_block`** | `dungeon.gd:100-102` vs `dungeon.gd:43 / 81` |
| 门豁口按「相邻有房间」双向开；相邻房 `kind == "secret"` 且未揭示 → 该面生成裂纹墙而非门 | `game_main.gd:619-621`、`game_main.gd:656-673` |
| 揭示 = 标 `revealed` + 重建本房间 | `game_main.gd:466-477` |

### 3.2 「夹在 2 间房之间」vs「只连 1 间房」的判定

两者是**同一套选格维度上的不同取值**，不是互斥概念：

- 普通秘密房 `cnt >= 2`：共享暗房，多面可炸入（交付稿 §二 借鉴以撒普通秘密房）。
- 超级秘密房 `cnt == 1`：单入口死端暗房（交付稿 §二 借鉴以撒超级秘密房）。

**设计侧判定**：`cnt == 1` 是合法且可表达的，与现有选格维度不冲突；但必须作为**第二次独立选格**存在，不能复用「改一个比较符」的方式（§0.1 防误改点）。

### 3.3 与 2x2 约束 / 死端特殊房是否冲突

**与 2x2 约束：不冲突，反而更安全。**
`_makes_block` 判定 2x2 需要「`c` 同时有水平邻居 + 垂直邻居 + 对角邻居」三者齐备（`dungeon.gd:139-140`）。`cnt == 1` 的格子只有 1 个正交邻居，**不可能**构成 2x2 块；反倒是现有 `cnt >= 2` 的普通秘密房更接近 2x2 成形条件，且它的放置路径**本来就绕过了 `_makes_block`**。

> ⚠️ 设计侧一致性约束（非实现决策）：隐藏房放置路径目前统一不做 2x2 校验。若工程决定给超秘补校验，应对**两种隐藏房采用同一规则**，不要只给新的补、造成同类实体两套约束。

**与死端特殊房：不抢占名额，但有语义副作用。**
死端征用发生在 `dungeon.gd:64-97`，超秘在之后放置且是 `d.rooms` 的**新键**，不是从 `dead_ends` 数组取 → 不会与宝箱 / 商店争抢已分配名额。但：超秘一旦挂上，它那唯一邻房邻居数 +1，该房可能**从死端变成非死端**。若该房恰好是宝箱 / 商店房，就与玩法说明.md:31-32「宝箱 / 商店 = 死端」的玩家心智模型不一致（表现为：死端房里多了一面裂纹墙）。这是**设计一致性问题，不是崩溃**。

**可达性红线（设计侧最高约束）**：`cnt == 1` 意味着唯一入口，必须保证
1. 唯一邻房是**玩家可达的正常房间**，不得是另一个未揭示隐藏房、不得是 Boss 房以外的不可达格；
2. 揭示后从超秘房能**走回**该邻房（门双向，`gaps` 天然双向，但需确认重建后超秘房侧也开了门）；
3. 炸墙重建时门按 `room_state` 解锁（交接稿 §五-6）；
4. 不成为 SMOKE 自动驾驶的卡死点（§0.1 第 3 点）。

### 3.4 生成优先级 / 共存 / 去重（需用户拍板的选项）

新增第 2 种隐藏房后，`dungeon.gd:100` 的单次调用 + 哨兵 `Vector2i(999,999)` 需要扩展为两次选格。存在**隐蔽耦合**：先放置的隐藏房会被计入后放置候选格的 `cnt`，可能把原本 `cnt == 1` 的合法格变成 `cnt == 2`，导致超秘找不到格子（A5 触发）。

| 选项 | 内容 | 取舍 |
|-|-|-|
| **P1（推荐）** | 每层固定 2 间隐藏房（普通 + 超秘），**先选超秘再选普通**，选格时互不计入对方的 `cnt` | 规则清晰、可达性最好；但每层固定 2 间会让「找隐藏房」从惊喜变成例行，略微稀释稀有感 |
| P2 | 普通秘固定 1 间，超秘按概率（如 0.5）生成 | 保留稀有感；但验收基线「秘密房 2」的语义会更模糊，QA 需固定种子复现 |
| P3 | 超秘倾向贴 Boss / 特殊房（以撒经典） | 高风险高回报；但需**改动现有 `not touches_boss` 规则**，与 §三 已完成设计冲突，不推荐本轮 |

**炸弹经济平衡检查（红线）**：初始 2 颗 / 上限 3（`player.gd:23-24`），两个隐藏房至少消耗 2 颗炸弹。现有炸弹补给来自普通怪掉落（`game_main.gd:881`）与炸弹升级。设计侧要求：**不得出现「发现两间隐藏房但炸不起」的系统性挫败**；若选 P1，需确认掉落里含炸弹补给或初始炸弹量级足够。此项列为平衡检查项，不擅自改数值。

### 3.5 「稀有掉落」的定义（需用户拍板）

现有普通秘密房掉落 = `chest_big + relic×1 + diamond×8`（`game_main.gd:394-399`）。「稀有」必须与既有 14 种升级稀有度（普通/稀有/史诗，权重 10/5/2，`交付稿 §三.4`）、10 遗物、大宝箱区分开。

| 选项 | 内容 | 取舍 |
|-|-|-|
| **R1（推荐）** | 复用既有池但提高价值：`chest_big + relic×2 + diamond×12`（或等价量级），**不引入新物件 / 新稀有度层级** | 改动最集中（符合用户偏好）、不碰经济表、不越界 S-05；但「稀有」体感靠量级而非独特性 |
| R2 | 从**史诗级升级**（护盾 / 其余史诗）中定向给 1 次 | 跃迁感最强；但会与 S-03 展示的护盾状态、以及升级面板三选一路径耦合，本轮不宜加耦合 |
| R3 | 新增专属掉落表 / 新稀有度 | **越界**（等同 S-05 的一部分），本轮排除 |

## 4. S-03 专项：状态图标的信息层级与可读性

### 4.1 字段语义澄清（**最重要的一条**）

三项不是一类信息，不能按同一优先级平铺：

| 字段 | 取值 | 性质 | 玩家何时需要看 |
|-|-|-|-|
| `shield_charges` 护盾层数 | `0..3`，受击 −1 / 升级 +1（`player.gd:53, 459-461, upgrades.gd:96`） | **动态消耗资源**（额外生命） | 战斗中实时、受击瞬间 |
| `chain_chance` 连锁 | `0..0.75`，每级 +0.25（`upgrades.gd:92`） | **静态构筑属性**（命中时概率触发弹射，`bullet.gd:90-91`） | 选卡后 / 想确认 build 时 |
| `poison_chance` 淬毒 | `0..0.9`，每级 +0.3（`upgrades.gd:94`，`bullet.gd:92-93` 施加到敌人） | **静态构筑属性** | 选卡后 / 想确认 build 时 |

> 注意：淬毒的作用是**给敌人上中毒**，不是玩家自身状态；连锁是**命中触发概率**，不是持续 buff。HUD 应显示「我拥有这个能力」，而**不是**显示「当前有几个敌人中毒 / 正在连锁」—— 后者是另一套系统，本轮不做（防 scope creep）。

### 4.2 优先级定义

- **P0 · 护盾层数**：与 `hp` 同属生存资源，必须紧邻血条，冷色（青/蓝系，区别于血条绿 `#6ab04c`，`hud.gd:67`），显示 `×N` 或 3 格点亮。它是唯一需要「战斗中高频扫视」的项。
- **P2 · 连锁 / 淬毒**：属于 build 概览，**不得进入战斗视野核心区**。建议与武器槽 / 技能条同组（能力区），且未获得时隐藏。

### 4.3 现有 HUD 占位盘点与避让区

| 区域 | 坐标 / 内容（`hud.gd`） | 可放状态行？ |
|-|-|-|
| 左上 | `pos(12,12)` HBox：头像 44 + VBox(血条 170×14 / 经验条 170×6 / 生命文字) + 资源行（炸弹/钻石/得分）(46-89) | **推荐**，护盾紧邻血条 |
| 左下 | `BOTTOM_LEFT`, `offset_left 12 / offset_bottom -44`：技能行 + 武器槽×2 + Q 提示 (246-299) | **推荐**，连锁/淬毒贴能力区 |
| 右上 | 时间/击杀/层数 `top 10` + 小地图 `top 92`, 130×96 (91-102, 233-244) | ❌ 禁放 |
| 顶部中央 | Boss 条 `top 14, ±170` + 横幅 `top 64` (104-133) | ❌ 禁放 |
| 右侧中部 | 连杀 `top 200` (135-146) | ❌ 禁放 |
| 底部中央 | 操作提示 `bottom -12` + toast `bottom -40` (148-162, 301-313) | ❌ 禁放（toast 与护盾受击提示共用，见 §4.5） |

**落位选项（UX 建议，非实现决策）**

| 选项 | 内容 | 取舍 |
|-|-|-|
| **L1（推荐）** | 三项合并成**一行紧凑状态徽标行**，放在左上 panel 内血条附近（如 VBox 末尾新增 HBox）；单项为 0 即隐藏 | 「改动集中」（用户偏好）、护盾紧邻血条、三者成组不散落；代价是左上 panel 变高，需确认不与资源行挤压 |
| L2 | 护盾贴血条（左上），连锁/淬毒贴武器槽（左下） | 语义分组最准确；但改两处、两处都要处理隐藏逻辑，改动分散 |

数值表述按 B6：显示百分比（与升级卡「25% / 30%」文案一致）并标单位 `%`；或显示 1–3 级点，**二选一，不得混用**。推荐百分比以保持一致。

### 4.4 认知过载红线

现有常驻 HUD 元素已约 **18 个**（血条/经验条/生命文字/炸弹/钻石/得分/时间/击杀/层数/小地图/横幅/Boss 条/连杀/技能条/技能文字/武器槽×2/操作提示/toast）。再加 3 个若做成常驻大图标 + 文字，直接触发认知过载。

**规格约束（B5）**：常驻图标 ≤ 3 个、单个 ≤ 20px、不新增常驻文字行、不新增输入按键、未获得不占位。三者必须**成组**出现，禁止分散到三个角。

### 4.5 与既有反馈的重复检查

`player.gd:461` 已有 toast「护盾抵挡了这次伤害（剩 %d 层）」，是**瞬时反馈**；HUD 徽标是**持续状态**。两者职责不同、可共存，但需确认：toast 出现在底部中央（`hud.gd:301-313`），状态徽标不得也放底部中央，否则同一信息两处同时闪（§4.3 已把底部中央列为禁放区）。

## 5. S-04 专项：保底奖励的激励边界

### 5.1 现状实读与交接稿的事实偏差

`game_main.gd:305-320` 挑战房结算实际为：

```
"challenge":
    for i in 3: drop_pickup(..., "diamond", 1)      # 无论成败都掉 3 颗钻石
    if _room_damaged:                                # 掉血
        toast("挑战失败：掉过血，只有普通掉落")        # 仅文案，无额外物件
        print("[SMOKE] challenge failed")
    else:                                            # 无伤
        relic×1 + chest_big×1 + banner + sfx + Game.add_score(200)
```

**偏差**：交接稿 §七-5 说「掉血时只有普通掉落」，代码里掉血分支**并非零奖励**（已有 3 颗钻石，与 1 层战斗房 `2 + floor_num = 3` 颗同量级），只是文案写「只有普通掉落」让人误以为是零。

**设计侧判定（关键）**：S-04 的「小奖励」必须定义为**区别于现有 3 颗钻石的、新增的、有独立反馈的物件/分值**，否则工程很容易做成「把 3 改成 5」（不可感知）或「只改一句 toast 文案」（无实际收益），两者都不满足 C1。

### 5.2 收益对照表

| 分支 | 现有收益 | 规格新增后 | 允许的新增量级 |
|-|-|-|-|
| 无伤 | 3 钻石 + 遗物×1 + 大宝箱×1 + 200 分 + banner | **完全不变**（C4） | — |
| 掉血 | 3 钻石 + 一句 toast | 3 钻石 + **小奖励** + 明确文案 | 显著 < 遗物 + 大宝箱 + 200 分 |

锚点：1 颗钻石 = 最小货币单位；`_room_cleared` 基础分 = `30 + 10 × floor`（`game_main.gd:286`）；遗物 / 大宝箱属**构筑级**资源；200 分是无伤专属。

### 5.3 倒挂红线（设计理论：杜绝主导策略 / 经济失衡）

保底奖励**不得**：
1. ≥ 无伤额外奖励的价值（遗物 + 大宝箱 + 200 分）—— 一旦接近，「故意掉血」成为省力的主导策略，无伤挑战设计意图被摧毁；
2. 是遗物 / 大宝箱 / 升级卡 / 武器 / 200 分（那是无伤专属，C4）；
3. 按掉血次数递增 —— 会诱导「卖血刷奖励」；
4. 是随机高价值掉落 —— 会让「掉血」的期望收益不可控，可能偶发超过无伤。

必须：**固定值、与掉血次数无关、可预期、价值可忽略但可感知**（C2/C3）。

### 5.4 选项与推荐（需用户拍板）

| 选项 | 内容 | 取舍 |
|-|-|-|
| **D1（推荐）** | 掉血给**保底分 +30**（与 1 层基础清场分同量级）+ 专属 toast「挑战失败 · 保底 +30 分」 | 不碰掉落表、不引入新物件、不与 S-01 炸弹经济耦合、改动最集中（符合用户偏好）、分值感知明确；且不改变无伤排序 |
| D2 | 掉血额外 +3 钻石（共 6 颗）+ 改文案 | 最省改动；但「多 3 颗钻石」在已有 3 颗旁边感知很弱，易被误读为没做 |
| D3 | 掉血给 1 颗炸弹补给 | 有战略价值，但会与 S-01「两个隐藏房炸不起」的炸弹经济耦合，本轮不宜引入跨 Story 耦合 |
| D4 | D1 + D2 组合 | 感知更强，但需严格控制总量级，且改动面变大 |

推荐 **D1**：单一保底分，量级 ≤ 一层基础清场分，远低于 200 分 + 构筑级掉落，**明确不倒挂**。

### 5.5 跨 Story 一致性发现（需用户拍板）

`player.gd:459-464`：护盾抵挡伤害时 `shield_charges -= 1` 后**直接 `return`**，未走到 `damaged.emit(dmg)`（第 469 行）；而 `_room_damaged` 只由 `player.damaged` 置位（`game_main.gd:100-103`）。

→ **当前语义：护盾挡下伤害不算掉血，仍算「无伤通过」**。

这与 S-03 形成张力：S-03 把护盾层数做成醒目的 HUD 状态后，玩家会更清楚地意识到「我有护盾，可以拿它硬吃一下还不破坏无伤」，护盾可能成为**无伤挑战的合法免伤手段**，从而削弱「掉一滴血就没额外奖励」的设计意图（进房 banner，`game_main.gd:376`）。

| 选项 | 内容 | 取舍 |
|-|-|-|
| **E1（推荐，本轮不动）** | 保持现状：护盾抵挡 = 不掉血 = 仍无伤 | 改动最小、不改受击语义；把它视为「护盾作为史诗级升级的合理回报」，本轮只记录、不调整 |
| E2 | 护盾抵挡也计入 `_room_damaged` | 挑战更纯粹；但需改受击语义 + 可能引发 QA 回归面扩大，且削弱护盾价值感知，与 S-03 目标相冲 |

本轮建议 **E1 并在文档留痕**，交由用户在后续冲刺决定是否收紧；**不建议在 S-04 里顺手改**（属 scope creep + 改动不集中）。

## 9. 已知风险与取舍

1. **S-01 是唯一有结构性风险的一条**：风险不在「只连 1 间房」，而在「新增第 2 种隐藏房」需扩展单次选格为两次，且牵动 10 处既有 `kind` 硬编码（§7）。若工程只改 `dungeon.gd` 而未同步 HUD / 自检 / SMOKE 挂具，会出现「房间生成了但看不见 / 炸不开 / 自检报错」的半完成状态。
2. **自动验收覆盖缺口**：现有 6 条基线不会覆盖超秘房（§0.1 第 3 点、§7 #7/#8）。建议 QA 补一条固定种子的超秘专项用例 —— 需主理人转达 quality-lead。
3. **S-04 的「可感知」是主观判据**：C1 要求有独立反馈，D1 靠「分值 + 专属 toast」满足；若用户希望更强体感，可升级到 D4，但需同步收紧量级以守住不倒挂。
4. **跨 Story 张力（E）本轮刻意不解决**：护盾免伤削弱无伤挑战是真实设计问题，但在本轮修它会扩大改动面、且与 S-03「让护盾价值被看见」目标相冲，故记为已知取舍、留待后续。
5. **炸弹经济未做数值验证**：§3.4 只标出「两个隐藏房 vs 初始 2 颗炸弹」的平衡检查项，未改任何数值；若选 P1 固定 2 间，建议后续冲刺实测「发现两间却炸不起」的出现率。

#### 10.2.3 D 保底奖励形式 —— 四条倒挂红线 + 可感知核对，**不判 FAIL**

实现为「掉血分支房中心 3 源石 + 专属 toast」（`game_main.gd:323-324`），而非阶段 A 推荐的「+30 分保底」。按主理人裁定（初始 T1 简报口径）**不按 D1 判分**。

**四条倒挂红线逐条核对：全部成立**

| 红线 | 判定 | 证据 |
|-|-|-|
| ① 掉血总收益不得超过无伤 | ✅ | 掉血 = 3（散落）+ 3（保底）= **6 源石**；无伤 = 3 源石 + 遗物 + 大宝箱 + **200 分**。遗物 / 大宝箱属构筑级资源，200 分远超 3 源石，总体收益差距未被压缩到倒挂 |
| ② 不新增稀有度 | ✅ | 只掉 `diamond`，复用既有 pickup 类型；未新增遗物 / 升级 / 稀有度层级 |
| ③ 不能故意掉血刷分 | ✅ | 保底固定 3 颗、与掉血次数无关（`_room_damaged` 为 bool）；`Game.add_score(200)` **仅在无伤分支**（`game_main.gd:334`），掉血分支**不加分** → 故意掉血净损失 200 分 + 遗物 + 大宝箱，是严格劣势策略，**无主导策略** |
| ④ 无伤奖励不回退 | ✅ | `game_main.gd:328-334` 与改动前逐字一致 |

**「玩家可感知」核对：✅ 满足，且优于 D1 推荐** —— 房中心独立掉落物具备视觉实体（纯加分只有数字变化）+ 专属 toast 明写「保底奖励 3 源石」，比阶段 A 推荐的 +30 分更易被玩家注意到。

**两项遗留观察（不阻断）**：
- **G-6 源石维度局部倒挂感知**：掉血 6 源石 > 无伤 3 源石。总体不倒挂（红线①成立），但在「源石」单一货币上无伤玩家反而更少，可能引发「我无伤怎么源石还少？」的困惑。这正是 D1 选「分数」而非「源石」的原因（分数维度无伤 +200 > 掉血 +0，不会局部倒挂）。当前 toast 已有「保底奖励」字样，部分缓解。
- **G-7 注释漂移**：`game_main.gd:318` 注释仍写「掉过血则只给普通掉落」，与 `:322-324` 实际给的保底掉落不符 —— 正是 §5.1 指出的那个事实偏差，代码改了但注释没跟，违反交接稿 §九「注释写逻辑不写废话」。**一行注释、零风险，建议本轮收尾顺手带上**。
