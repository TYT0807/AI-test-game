## §〇 一句话锁定
Sprint 21 = **C · 深渊难度档**：通关（击败第三 Boss / 抵达终局层）后解锁的高难模式，以**纯乘算因子**叠加既有敌人参数（血量/伤害/速度/受创），**零新增 rng 消费、零 rng 顺序变化**，补一条通关后的长线重刷目标。

## §一 方向裁定（为何 C 而非 B / D）
- 项目自身诊断（MEMORY「明确不做」段）：**Mechanics 过饱和、Dynamics 贫乏，优先系统间关系**。
- **B · Boss 专属机制**：给三 Boss 各加签名机制 = 继续堆 Mechanics，违背诊断；且「Boss 战 rng 消耗变化需登记」触碰 E1，风险中。**否决**。
- **D · flash_toast 队列**：清一条在册观察（同帧覆盖）的小修，规模 S、需设计裁定，够不上 sprint 级增量；留作后续技术收敛批。**暂缓**。
- **C · 深渊难度档**：富集 Dynamics（长线目标）+ 系统是「难度与进程的关系」而非新机制，纯乘算因子不动 rng 顺序，风险低-中。**采纳**。

## §二 范围与不做（Scope）
**做：**
1. 通关解锁：新增平行只读的「深渊模式」解锁标记（沿用 meta 解锁范式，不碰 `meta.gd UNLOCKS` 与 `Meta.STATS_KEYS`）。
2. 难度阶梯：`ABYSS_TIERS` 常量表（tier 1..N → 各乘算因子），每层叠加，给玩家重刷理由。
3. 乘数注入：在敌人实例化处**确定性**地把因子乘到既有 enemy 属性（hp / damage / speed / 玩家受创），不引入任何新 rng。
4. UI：主菜单难度选项（平行只读）+ 局内 HUD 深渊 tier 指示。

**不做（红线）：**
- 不新增实体 / 资源 / 输入动作；复用既有敌人池，仅缩放数值。
- 不新增 `ACTION_DEFS` 动作（保持 18 条）；不扩 `CODEX_KINDS`（S19 刚修过漂移，绝不新增 kind）；不碰 `FLAVOR` 覆盖门（深渊 tier 非「可发现 id」，不进 `FLAVOR`）。
- 不碰 `FLOOR_THEMES`（F1 红线 8→12 永不接）；不碰 `CODEX_BOONS` 第五档；不碰圣所/武器淬炼。

## §三 设计要点
- **纯乘算，零 rng**：难度只改变「数值大小」，不改变「随机数序列」。乘子在 `start_run` 按当前 tier 一次性算定，注入敌人属性走确定性乘法，**不新增 `Game.rng`/`fx_rng` 调用**。
- **E6 合规**：若对敌人速度类属性缩放，仍走 `FIXED_DT` 计时链路，禁 raw `delta`。
- **平行只读**：深渊解锁标记与 tier 选择落盘走既有 meta/cfg 平行字段，不进 `STATS_KEYS` 白名单（否则被静默丢弃）。
- **长线目标形态**：tier 阶梯可设计为「每升一档，敌人三围 ×(1+k·tier)」，并提供「最高通关 tier」记录，形成「再打一次冲更高档」的回环。
- **可见效果断言**（登记三件套③）：必须验**数值**——同 seed 下，深渊 tier = t 时敌人实际 hp/damage 是 baseline 的既定倍率（验数值，不验标志）。

## §四 红线与铁律（沿用）
1. **E1**：核心循环零新增 rng 消费 / 顺序变化。`ABYSS_TIERS` 乘子应用是确定性乘法，rng 流（地图生成 / 刷怪 / 掉落）原样不动。
2. **E6**：计时/DoT/冷却走 `FIXED_DT`，禁 raw `delta`。
3. **冻结规格 v2.10**：`meta.gd UNLOCKS` 与 `Meta.STATS_KEYS` 不动；局外内容一律平行只读派生。
4. **登记三件套**：①写入 ②注册表/白名单/UI 分母/显示名 ③**可见效果断言**（验数值或验渲染，不能只验标志）。
5. **零新增实体/资源/输入动作**；`ACTION_DEFS` 18 条不动；`CODEX_KINDS` 六类不动；`FLAVOR` 不动。
