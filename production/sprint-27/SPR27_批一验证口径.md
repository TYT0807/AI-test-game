## 二 三段式强制要求（本批核心风险）

### 2.1 铁律

> 🔴 **只验第 1 段不算通过。** 施加端改对、还原端没跟上，玩家换层后带着 debuff 走完整局——S21 已踩过（`:595-596` 原文「frenzy 曾跨层固化整局」）。

| 段 | 验什么 | 构造 | 期望 |
|---|---|---|---|
| **1 施加后** | 通道值 == 变体期望 | `floor_num` 定目标层 → `_calamity=X` → `_apply_calamity()` | 语义表字面量 |
| **2 换层后** | 通道值 == 基线，**精确相等** | **先**把 `floor_num` 改成下一层，**再** `_clear_calamity_effects()` | 施加前进场值（逐字段原值回填） |
| **3 再施加** | 不叠加、不残留 | 段 2 后再 apply 一次、再 clear 一次 | 与段 1 / 段 2 完全相同 |

**② 组常数格（4 基线 + 6 变体）期望值**：frail 见 §〇 公式（old=10 起算：#1 cut=1→max_hp 9｜#2 cut=4→max_hp 6｜基线 cut=2→max_hp 8）；frenzy `1.25 / 1.40(#6) / 1.45(#5)`；scarce_ammo `0.5 / 0.65(#4) / 0.70(#3)`；scarce_ore `0.7`。**构造一律先把四通道拉到同一基线**（`max_hp=10, mag_cap_mult=1.0, diamond_mult=1.0, calamity_speed_mult=1.0`），否则断言随楼层顺序漂移（`player.gd:746` 注释已实证此类假红）。

### 2.2 时变格（#7 / #8）改为 **5 段**——3 段不够

时变格的「段 1」不是一个初值而是一条序列，只断初值等于 0.5 会漏掉「递减根本没发生」。

| 段 | #7 toxic×scarce_ammo | #8 magma×scarce_ore |
|---|---|---|
| 1 施加初值 | `mag_cap_mult == 0.5` | `diamond_mult == 0.7` |
| 2 递减单调 | 1 tick → `0.40`；2 tick → `0.30` | 1 tick → `0.65`；2 tick → `0.60` |
| 3 下限钳制 | 再 3 tick → 仍 `0.30`（下限 0.3，不得穿底） | 累计 4 tick → `0.50`（到下限）；再 2 tick → 仍 `0.50` |
| 4 换层还原 | 换层后 `== saved(1.0)` 精确 | 换层后 `== saved(1.0)` 精确 |
| 5 再施加幂等 | clear 后再 apply，段 1/2/3 结论不变（不得从 0.3 续减） | 同左 |

**tick 驱动方式**：实施单把钩子插在 `_theme_damage_tick()`（实测 `func` 在 `:954`，body `:955` 起；实施单写 `:952`，差 2 行）开头、`is_instance_valid(player)` 之后、SMOKE 分支（`:957`）之前。探针**直接同步调用 `_theme_damage_tick()`** 逐次推进，不靠真实计时——它同时会让玩家掉 1 血（`:962`），故每次调用前后必须存取 `player.hp`（`_immortal` 下不掉，但仍要验）。**该函数不消耗 `Game.rng`**，与 ⑤5 不冲突（已核）。

### 2.3 时序陷阱：clear 运行时 `floor_num` 已是新层

`next_floor()` 顺序 = **`Game.floor_num = nf`（`:1505`）→ `_clear_calamity_effects()`（`:1507`）→ `_calamity = ""`（`:1508`）→ `_apply_floor_theme()`（`:1509`）**。

> 🔴 任何在 clear 里用 `Data.theme_for_floor(Game.floor_num)` 现查主题选还原分支的写法，会拿**新层主题**还原**旧层变体** → 静默错还原。
> **纪律（= 实施单 §4.2/§4.3）**：`_apply_calamity()` 开头快照 `_calamity_theme_rule = String(Data.theme_for_floor(Game.floor_num).get("rule", ""))`；clear **只读该快照**，禁读 `Game.floor_num`、**也禁读 `_theme_rule`**（后者在 clear 时恰好还是旧值，能用纯属调用顺序巧合）；重置收拢进 `:597-601` 的 `if _calamity != "":` 块，一并置 `""` 与 `0.2`。
> 🔴 快照**必须经 `theme_for_floor()`**，禁 `FLOOR_THEMES.get(Game.floor_num, {})`——`theme_for_floor` 内部回卷 `key = 4 + ((n-4) % 8)`（`data.gd:494`），**12 层回卷到 vein(4)**；直查表拿空字典 → 12 层被判无主题 → 变体永不生效且不报错。全仓禁止项见 §六。

**段 2 构造铁律**：换层增量**必须让 rule 真的改变**（4→5 / 6→7 / 8→9 / 10→11）。🔴 **禁用 4→12**——回卷后 rule 相同，写错的实现照样蒙过、变异测试假绿。

### 2.4 证据要求：怎么证明断言真的执行过

`Dev.check()` 只在失败时 `err()`（`dev_log.gd:29-32`），成功时一个字节都不打印 → **`[ERR]=0` 不证明跑过**。三条强制：① 入口无条件打 `[SMOKE-CAL-THEME] entry floor=%d calamity=%s`；② **每条断言后无条件打印实测值行**（`#NN` 前缀，见 1.3②的分流）；③ 末尾无条件打 `done checked=%d declared=%d` 并 `Dev.check(checked == declared, ...)`。
**核验方判 PASS（两条同时成立）**：`grep -c "^\[SMOKE-CAL-THEME\] #"` == 66/76；`grep -c "\[ERR\] cal_theme"` == 0。只做第二条 → 一个提前 `return` 的探针能拿满分。

## 三 差额断言（证明「复合真的生效」）

### 3.1 同进程构造（做得到，同帧、不跳层）

`_calamity` 是实例字段（`:117`），主题由 `Game.floor_num` 经 `Data.theme_for_floor()` 派生 —— 两者都可写。步骤：① 快照现场（四通道 + `_calamity` + `floor_num` + 三个 saved + 两个新字段），结束逐字段回填；② 四通道拉到同一基线；③ 定 `floor_num` + `_calamity` → `_apply_calamity()` → 记值 → `_clear_calamity_effects()` → 复位基线；④ 换主题重复一次；⑤ `Dev.check(v_a != v_b, ...)` + 无条件打印两值。
**🔴 ⑤3 的对比对必须选 `scarce_ammo`：magma(0.70) vs ice(0.50)** —— 两格初值即不同、都是字面量。
**⚠️ 实施单 §5.4 写的「scarce_ore 在 magma ≠ 在 ice」在 A 组阶段会假红**：#8 的差异来自 **tick 累积**而非初值，apply 瞬间 magma 与 ice 都是 `minf(1.0,0.7)=0.7`，两值相等。要用它必须等 B 组且先驱动 tick；A 组阶段请用上面的 `scarce_ammo` 对。
**差额反（⑤4）**：同主题两灾祸通道不同，如 magma 层 frail 削减(max_hp) vs frenzy 加速(`calamity_speed_mult`)——通道正交，不得互相等于。

### 3.2 禁止用 `SMOKE_JUMP_FLOOR` 构造差额

`start_run` 是 **`_roll_calamity():381` → `_apply_floor_theme():385`**，`next_floor` 是 **`_apply_floor_theme():1509` → `_roll_calamity():1516`**，两者**相反**。跳层走 `start_run` 那条 → 6 层 stress 场景 `minf(1.0,0.7)=0.7`（`:577`）被随后 `maxf(...,1.5)`（`:871`）覆盖成 1.5 → 读到「变体无效」，其实是探针顺序错了。
**生产不可达**：`FLOOR_THEMES` 只覆盖 4–11 层（`data.gd:102-119`），开局恒 1 层无主题。**故不修代码，只作探针纪律**（改顺序=改 E1 基线），已入册实施单 §二 陷阱 2 / §七。
**推论要写进期望值**：压力层 + 残响枯竭，生产路径是 `minf(1.5, 0.7) = 0.7`、saved = 1.5，**不是「1.5 压过 0.7」**（⑥4 按此写）。

### 3.3 弱点（如实写进交付）

① 绕过 `_roll_calamity()` 的 15% 判定与 `calamity_floors` 登记（`:532-538`）——由 ⑤ 组登记断言独立承担。② 绕过 `_fade_to` tween（`:1524-1533`）：能抓「读新层主题还原」的逻辑错，抓不到「回调里被二次改写」的时序错 → 补端到端兜底 `SMOKE=1 SMOKE_SEED=12345 SMOKE_CALAMITY=1 --quit-after 1800` 跑满多层（弱证据，不计覆盖）。③ 若变体编码进 `_calamity` 字符串则差额退化为字符串比较=只验标志（实施单 §一.4 已禁）。
