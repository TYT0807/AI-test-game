## 一 判断

S19–S26 八批里，有六批在**加东西**（第六类发现集、手记扩容、深渊档、聚合播报、连绩、视听/语义/显示三层换血）。系统的**数量**早就够了，缺的是**系统之间互相改写**。

所以 S27 的验收标准不该是「又多了什么」，而是——

> 玩家能不能说出「同样是残响枯竭，在毒巢和在岩浆层不是一回事」这类话。

如果说不出来，加多少内容都是并列的抽屉。

## 二 三条候选（均已实读落点）

### C1 · 主题 × 灾祸复合（推荐主项）

**现状实读**：灾祸在 `game_main.gd:536` 用 `Game.rng.randi_range(0,3)` 从四种里抽一个，`:556 _apply_calamity()` 施加，`:581 _clear_calamity_effects()` 还原。**全程不看当前楼层主题**——同一个「残响枯竭」在毒巢和岩浆层表现完全一致。

**提案**：灾祸落在某主题上时改写为变体。8 主题 × 4 灾祸 = **32 种组合，全部由 12 条既有条目派生**。

| 项 | 评估 |
|---|---|
| 新增实体 / 新 id / 新图鉴分母 | **零** |
| 新增 `Game.rng` | **零**（灾祸已抽过，复合只是查已抽的值） |
| 新增"表" | 不建 32 条常量表，写成**规则派生**（按 rule 分支覆盖几条），避免变成新注册表 |
| 可感知度 | **最高**——玩家每层都能感到「这层的灾祸不一样」 |
| 主要风险 | 🔴 施加/还原必须**成对**改写。S21 踩过同型坑：倍率被覆盖或还原不全 → 换层后 debuff 永久固化。`_clear_calamity_effects()` 必须逐分支覆盖到变体，不能只改施加端 |

### C2 · 誓约回流（推荐附项，成本极低）

**现状实读**：`oath_fulfillment()`（`:2302`）返回 `{id,name,desc,done,cur,need}`，结果只写进 `Game.codex["last_run"]["oath"]`（`:2349`、`player.gd:2056` / `:2077`），**纯展示，对下一局零影响**。印记页那句「上局誓约 · XX（未兑现 12/30）」是这条链的终点。

这是全项目最典型的「系统只进不出」：一条花了很久做的跨局记录，最后只换来一行字。

**提案**：上局兑现 → 本局开局一个**确定的小值**（不抽签、不随机）。

| 项 | 评估 |
|---|---|
| 新增实体 / 新表 | **零**（读既有 `last_run` 字段） |
| 新增 `Game.rng` | **零**（局外存档常量） |
| 可感知度 | 中高——第一次让「誓约」不只是纪念章 |
| 主要风险 | S23 已实读结论：`set_codex_last_run()` 是**覆盖式**且末尾自带 `save_codex()`；平行字段必须在覆盖之后赋值、再 save 一次，**别新增第三次写盘**；复用既有 `_write_codex_replay()` 写盘位点 |

### C3 · 圣所代价随主题/印记浮动（建议缓议）

**现状实读**：代价扣减是**单点**——`_shrine_execute()` 尾部 `game_main.gd:2244-2253` 的 `match cost_kind`（diamonds / max_hp / score 三支），可用性检查在 `:2185 _shrine_affordable()`，两处都直接读 `offer["cost"]`。

技术上最好改：加一个派生乘子，两个读点共用即可。

| 项 | 评估 |
|---|---|
| 可感知度 | **中偏低**——纯数值浮动，玩家容易只感到"变贵了"，没有叙事 |
| 主要风险 | 两处必须同源，否则「显示能付、实际付不起」；`cost_kind=""`（净化）不能乘 |
| 判断 | **本批不做**。它和 C1 同批会同时动"代价"与"灾祸"两条数值链，出问题难定位；且它的收益主要是数值层，不是关系层 |
