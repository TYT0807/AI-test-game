## 二 回流规则（三态映射）

| 上局状态（`last_run`） | 开局状态 | 一格血/一颗子弹都不改 |
|---|---|---|
| `oath` 为空（未立誓） | **T0**：不回流，且连绩按 `:2984` 的 `H=0` 分支**保持不变**（不断绩） | 残响 +0 |
| 立誓未兑现（`done=false`） | **T0**：不回流（连绩已归 0，见 §五） | 残响 +0，**不追加惩罚** |
| 兑现（`done=true`） | **T1**：残响 +3 | 残响 +3 |
| 兑现且连绩 2 局 | **T2**：残响 +5 | 残响 +5 |
| 兑现且连绩 ≥3 局 | **T3**：残响 +8（封顶） | 残响 +8 |

**一句人话**：上局把誓约兑现了，这局推门时口袋里就已经有几颗残响——连着兑现几局，垫得越厚，最多 8 颗。

**为什么"未达成"只归零、不扣东西**：立誓未兑现的玩家当局面本来就输了，再扣血/扣残响会形成"越弱越难"的负反馈螺旋（设计红线）。所以 **未达成 ≡ 未立誓 ≡ 基线**——它唯一的可感知性是"从 +5 掉回 0"的落差，这已够（损失厌恶），且不制造第二重惩罚。

## 三 载体选型：6 个候选，只留 1 个（本节是本文的核心论证）

| 候选 | 判定 | 结构性理由（行号级） |
|---|---|---|
| `Game.diamonds` 直写 | ✅ **唯一采用** | 复位点在 `Game.reset()` → `game_state.gd:136 diamonds = 0`，是 `start_run()` 第一段（`:342`），**永远早于注入**→ 天然幂等（见 §六 boot 双击） |
| `Game.add_diamonds(n)` | ❌ 绕开 | ① `:151 run_diamonds_earned += n` → 进 `_run_stats():3126` → `Meta.payout` 按 0.10 折算（`meta.gd:171`）= 局外累积（红线 6）；② `:154 oath_count("diamonds_picked", n)` → 白送「满载而归」（`need 40`，`data.gd:360`）进度 → **兑现→回流→更易兑现的自激环**（主导策略） |
| `player.max_hp` | ❌ | ① boot 双击双写 → 开局 +2 血（§六）；② 改绝对值 `= BASE+1` 则被 `_apply_sigil_contract():1505` 的 vigor 与 `_apply_codex_boons():3006` 吃掉 → **越是老玩家（印记/图鉴齐）越拿不到**，激励倒挂；③ 3 血盘子里 +1 = 33%，等于白送一枚 vigor 印（`:1505` 同值），对"条件温和的誓约"过强 |
| `player.mag_cap_mult` | ❌ | ① 同上 boot 双写；② 该通道被灾祸**覆写**（`:607-611` 写死 0.7/0.65/0.5，`_clear_calamity_effects():628` 只按 saved 还原）→ 12 层里 4 个弹药荒层回流静默消失，教不会玩家；③ 1.0→1.15 在 8 发弹匣里 +1 发，不可感知 |
| `player.sigil_ward` | ❌ | bool 幂等，但与 ward 印 `:1529` 完全重叠 → 对"净化誓约"玩家**零收益**（又是激励倒挂）；且 pause→开始游戏 同节点路径无复位点 |
| `Game.main.diamond_mult` | ❌ **结构性死** | `_roll_modifier()` 在注入段后 8 行（`:371`）执行 `:1213 diamond_mult = 1.0` → 注入被无条件抹掉；另 `:2992` 注释与 `data.gd:341` 已明文禁用该载体（S12 #2 实害） |
| `_roll_modifier` 对冲 | ❌ | 效果取决于本局抽到的 modifier → 同一连绩"有时有有时没有"，违背"不许掷骰子决定给不给"；且改判会污染 `[SMOKE] modifier=` 打印行，直接动 E1 片段 |

**取舍陈述**：残响是唯一"没人抢、且每次开局都被清零"的通道（`barren` 的 +10 是加法共存，不冲突）。代价是：回流只能改**钱包厚度**，改不了战斗强度——这是五载体约束下能拿到的上限，我不硬凑第二通道。

## 四 数值表（今天 / 改后 / 锚点 / 上限）

| 档 | 触发（`last_run`） | **今天** 开局残响 | **改后** 开局残响 | 增量 | 这笔钱在既有经济里的等价物（不给新解释） |
|---|---|---|---|---|---|
| T0 | `oath` 空，或 `S = 0`（上局立誓未兑现） | 0 | 0 | 0 | — |
| T1 | `done=true`，S=1（含旧档 S 缺键） | 0 | **3** | +3 | 不足一次护盾祝福（5）——钱包垫底 |
| T2 | `done=true`，S=2 | 0 | **5** | +5 | = 护盾祝福（`SHRINE_OFFERS` cost 5，`data.gd:317`） |
| T3 | `done=true`，S≥3 | 0 | **8** | +8 | = 残响淬炼（cost 8，`:315`）；**< 共鸣契约 12**（`:323`） |

**上限（防滚雪球）**：S≥3 全部按 8 计，**逐局不累加**。任何玩家单局开局残响 ≤ 8（`barren` 叠加则 18，见 §八）。上限取 8 而非 10/12 的理由：**8 < 12 = 共鸣契约门槛**，回流本身单靠自己换不到 6 颗地窖碎片（局外货币），不算"白拿局外进度"。

**今天 vs 改后的对照句**：今天连输三局和连赢三局，开局一模一样（都是 0 残响）；改后差 8 颗 = 一次圣所交易的量级。

## 五 连绩语义（照 `:2980-2986` 既有规则，不另立）

`next_oath_streak(prev,H,D)`：`H=0 → prev`（未立誓不计入、**不断绩**）；`H=1,D=1 → prev+1`；`H=1,D=0 → 0`。

| 项 | 口径 |
|---|---|
| 档位派生（纯函数，零 IO / 零 rng） | 若 `last_run["oath"]` 为空 → **不发**；否则 `tier = clampi(S, 1, 3)`（S≤0 时由上游守卫拦掉）。**不读 `done`**：`next_oath_streak()` 在局末已把 done 折叠进 S（`game_main.gd:2967`），再读一次是重复判定 |
| 🔴 为什么**不**用 `maxi(S,1)`（主理人裁定，推翻了本文初稿） | 两个理由：① `_read_oath_streak():2973` 已经定下「旧档无键 → 读侧 0」这一既有口径且**已随 S23 上线并核验过**，在本文件另一处再补一个 `maxi(S,1)` 会让同一个字段在同一文件里有两个读数，是典型的埋雷写法；② `maxi(S,1)` 把「S=0」与「S 缺失」抹成同一个值，等于主动放弃区分能力——B02/B04/B05 三条类型守卫断言会全部退化成同一个期望值。<br>**代价如实写**：S23 前的老档、兑现过但无 `oath_streak` 键的，**首局拿 T0 丢一次回流**；该局末 `_write_codex_replay()` 就会把 S 写成 1，下一局恢复，**一次性自愈，不做迁移**。 |
| 为什么要 `mini(...,3)` | 封顶。S=7 与 S=3 同档 → 连绩只奖励到第 3 局，之后不再滚雪球 |
| 未立誓那局 | `H=0` → S 原封不动；但 `oath` 为空 → 该局 **T0**。语义自洽：回流永远描述"**上一局**"，上一局没立誓 = 没有可回流的东西。<br>🔴 **这条同时是防棘轮的守卫**：S 在 H=0 时**永不衰减**，若照发，玩家达成 3 连后永不再装印记即可每局白拿 +8 且零风险 → 最优解变成退出誓约系统。所以「不断绩」（S 保留）与「不发放」（本局 T0）是两件事，必须分开实现。 |
| 换印记 | 连绩是**全局**（非按印记），换印记只要新誓约兑现就 S+1，不因换印断绩 |

## 九 风险与边界（含必刷自评）

| # | 风险 | 评估与处置 |
|---|---|---|
| 1 | **回流会不会让连绩变成必刷项？**（自评） | **不会到"不敢正常玩"，但会带来一个真实收敛**：九条誓约难度不等（`残影连闪 15 次冲刺` vs `并肩清扫 30 杀`，`data.gd:357-359`），回流值**不分难度**（全档 3/5/8）。想保 S 的玩家会倾向选"最容易兑现的那条" → 印记从"每局决策"退化为"一次选定"。反向论述：保 S 的收益固定且小（≤8 残响 ≈ 一次护盾祝福），而放弃合适印记的代价在整局战斗上 → 收益 < 代价，收敛不会成为主导策略。**红线监测项：任何"按誓约难度给不同回流值"的后续提议，会立刻把这个收敛变成主导策略（易誓约 × 高回报），批二明确否掉。** |
| 2 | boot 双击双写（`_ready():200 start_run()` + `menu.gd:1094 Game.main.start_run()`，**同一 player 节点、不重载场景**） | 残响因 `Game.reset():136` 前置而幂等（§六）。**顺带发现的既有隐患（本批不动，另案登记）**：`_apply_codex_boons():3006 player.max_hp += 1`、`_roll_modifier` 的 `overload`（`:1223`）在双击下会对同一节点叠加；仅调用点实读推定，**未实机验证**，需一条运行时探针确认后另开单 |
| 3 | E1 指纹 | 注入零 rng；`flash_toast` 不 print，不进指纹行。**实施侧约束**：若加探针，只在 `SMOKE_ECHO=1` 时打印，禁止无条件新行——否则 E1 的 8 行片段被改成 9 行，等于隐性重定 |
| 4 | 收益兑现点偏远 | 残响的真实用处在第一次圣所（`min_floor 3`）与商店（`:2062` 价格 15+5×层），开局第一秒只能看到 HUD 数字 → 回流靠 §七 那行字获得"当下可感知"，靠圣所获得"实际收益"。这是小值附项的固有代价，接受 |
| 5 | 载体单调 | 只改钱包、不改战斗 → 与"关系层"目标有距离。若主理人要求更强手感，唯一不违规的加码是**提高上限**（8→10，仍 <12），但这会削弱 §八#3 的说明，且接近"白拿一次商店治疗"，不建议 |
