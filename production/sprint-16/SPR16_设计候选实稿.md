# Sprint 16 设计候选实稿（design-strategist · 文策渊）

> 定位：Sprint 16 的命题是「真正的系统增量」，不是同类内容补齐。本文 4 个候选一律以**加耦合（关系）而非加实体（内容）**为轴。
> 基线核对：实读 `data.gd` / `game_state.gd` / `game_main.gd` 与 Sprint 13–15 草案；最新提交 `38535f3`、34 个 `.gd`、冻结 34/34、`production/sprint-16/` 原为空目录。本文为唯一新增文件，**未修改任何现有文件**。
> 所引表名 / 函数名均为实读已有项；标「拟新增」者为设计提案，非既有 API。按约束不写行号。

## 〇、设计诊断（为什么必须换轴）

- **支柱漂移（标注）**：Sprint 13 定下「决策深度 + 局外沉淀」，14/15 实际交付图鉴 + 第三 Boss，属**内容补齐**。目前的「决策深度」是决策点**数量**（圣所 10 条、三选一），不是决策之间的**依赖、权衡与跨局后果**。Sprint 16 应回轴，而非沿数量轴继续走。
- **自我决定论分布**：现有系统几乎全压在**胜任**（数值、层数、分数、发现度四档被动）；**自主**只到「即时状态交换」层，玩家无法表达「这一局我要走什么路」；**关联**近乎为零 —— 印记 / 圣所 / 主题 / Boss 只有名字，彼此无意义联系。三个候选分别补这三块。
- **MDA**：Mechanics 已过饱和（11 房型 / 10 圣所 / 9 印记 / 8 词缀 / 4 遗物 / 8 主题 / 7 编队 / 3 Boss）；**Dynamics 贫乏** —— 各系统是并列孤岛，彼此不读取对方状态；Aesthetics 因此停在「收集 + 变强」。真正的增量空间在 Dynamics 层：把已有系统接成因果链。
- **结论**：加关系 = 组合级收益（N 个系统互读产生新决策情境），且零新增 rng / 计时 / action / 资源 / kinds；加实体 = 线性成本 + 边际递减 + 每个新实体都要过登记三件套。

## 一、候选 A · 地窖誓约（联动型核心增量｜推荐）

① **动机与 MDA**：补**自主**（局外选定的印记第一次在整局里持续产生意义，而非开局注入一次就消失）与**胜任**（兑现度是可读的能力反馈，不是又一个分数）。MDA 落 **Dynamics**：把「局外选择 → 局内事件 → 局末复盘」接成一条链；Aesthetics 偏 Challenge + Narrative。
② **一句话循环**：本局装备的印记即「誓约锚点」→ 局内用圣所交换 / 词缀触发 / 净化灾祸 / 跨主题清场去兑现它 → 局末复盘看到兑现画像 → 下局换一枚印记走另一条路。
③ **挂接点**：`SIGILS` 的 `equipped`（**不新增选择界面**）、`SHRINE_OFFERS` + `_shrine_execute`、`RELIC_SUFFIXES` 的 `ON_*` 触发点、`ACTIVE_RELICS`、`_calamity` / `_calamity_name`、`FLOOR_THEMES.rule`、`CODEX_BOSS_NAMES`（仅作加分项）、`MILESTONES` / toast 通道、`codex["last_run"]` + `set_codex_last_run`、`menu.gd` 图鉴复盘页。拟新增只读派生表 `OATH_CONDITIONS`（9 条，一一对应 `SIGILS` 的 key，**只定义「读哪些已存在事件」，不定义任何新事件**）。
④ **风险与 E1/E6**：**E1** —— 条件判定必须纯状态读取、零 `Game.rng`；写入落在 `_settle_meta` 之后的局末，`_smoke_fingerprint` 只含 rooms 坐标 + kinds → **指纹不变、零重定**。**v1 只做只读展示 + 局末结算，兑现度不回注局内数值**，否则会变成第二条 `CODEX_BOONS` 式「局外→局内」注入，须登记为预期代价。**E6** —— 进度是离散事件计数、无计时；若有进度动画走 `Game.FIXED_DT`；不触碰 `player._tick_buffs(delta)` 与 `toxic_cloud` 的在册豁免，**不顺手统一**。**坑 5** —— 不新增 `ACTION_DEFS`、不新增资源则不触 `GEN_NAMES`（若加誓约图标，必须同步登记）。**冻结规格** —— `UNLOCKS` 不碰，全部平行只读派生。**红线**：兑现度**不得**调用 `mark_codex`（否则复刻 P0「发现度上升 → 更多 boon」自激），不扩 `CODEX_BOONS`、不碰其 `kind`，`variant="boss"` 不动。**主导策略红线**：兑现奖励刻意**不给数值**（只给复盘 / 叙事层），且 9 条誓约须各配互斥可达路径；条件一律用每局可达事件（进圣所 / 触发词缀 / 净化 / 跨主题），不把周期性主题 Boss 设为必要条件，避免不可达与「选某枚必优」。
⑤ **规模 M**（本批唯一系统级增量）。
⑥ **前置 / 不做理由**：需经主理人向程基岩确认 `_settle_meta` 后允许向 `last_run` 追加一个**平行字段**（不扩 `Meta.STATS_KEYS`），以及 toast 通道能否承载进度显示；若不接受任何持久字段，退化为「纯局内 HUD、局末不落盘」的 S 级版本。若用户认为立约加重开局认知负荷，可改为默认关闭、图鉴页内自选。

## 二、候选 B · 抉择回声（低风险 S 级｜推荐顺手清）

① **动机与 MDA**：补**胜任**（「我这一手决策被系统看见」）与轻微**自主**（下局有意换路线）。MDA 落 **Aesthetics**（Narrative / Submission 的轻叙事）与跨局 Dynamics 的自我对照；**不改 Mechanics**。
② **一句话循环**：进圣所三选一 → 局末复盘看到「本局抉择链」（依次选了哪些 offer、代价类型分布）与一句由数据派生的构筑标签 → 下局换一种活法。
③ **挂接点**：`SHRINE_OFFERS`、`shrine_panel` 的 `_pick`、`_shrine_execute`、`set_codex_last_run` / `codex["last_run"]`、`menu.gd` 的 `_build_codex` / `_codex_section`。**不新增表**。
④ **风险与 E1/E6**：全零 —— 纯事件记录 + 只读展示，不进指纹、无计时、无新 action / 资源、`UNLOCKS` 不碰。**唯一落点**：`set_codex_last_run` 现按 `Meta.STATS_KEYS` 白名单过滤 + 负数钳制，追加字段**不要扩 `STATS_KEYS`**（会动统计源与分母），走完全平行的另一个 key；这正是登记三件套 ②（分母 / 显示名）要核的地方，③ 的可见效果断言须验「复盘页确实渲染出抉择链」而非只验字段存在。
⑤ **规模 S**。
⑥ **前置 / 不做理由**：几乎无，可与任何阶段同批。**它是 A 的数据地基**（A 的兑现度同样往 `last_run` 写平行只读字段），故推荐与 A 同批、共用一套断言与一次登记三件套。若主理人判断复盘页已满、再加一行造成**认知过载**，则缩为只保留进层一句 toast、不进图鉴。

## 三、候选 C · 层签（联动型 · 随机性可读化）

① **动机与 MDA**：补**胜任** —— 把随机性从「不可知的惩罚」变成「可预判的约束」，让「要不要进圣所 / 要不要省资源」有依据。MDA 落 **Dynamics**（信息流改变路线选择）→ Aesthetics 的 Challenge。
② **一句话循环**：进层时看到一行「本层组合签」（主题规则 + 灾祸 + 挑战因子 + 编队倾向）→ 据此定本层打法与资源取舍 → 清层。
③ **挂接点**：`FLOOR_THEMES` 的 `rule` / `mark`（色盲标记）、`SQUADS`、`_roll_calamity` / `_calamity_name`、`MODIFIERS`、`_apply_floor_theme` 的 banner、`hud.gd` banner、`apply_ui_settings` 字号档。**纯显示，不新增任何生成逻辑**。
④ **风险与 E1/E6**：**E1 关键** —— 层签必须挂在「所有 roll 完成之后、`_enter_room` 之前」**读取已确定状态**；若为凑显示提前触发任何抽取，会改 `Game.rng` 顺序 → 全量重定，此路禁止。**E6** 零（无计时）。**坑 5** 零（复用既有 `mark` / 图标，不新增资源）。冻结规格零。**认知过载红线**：一行塞 4 项会冲掉 HUD 字号档与色盲 `mark` 已建立的可访问性口径 → 必须**默认只显 2 项、可展开**，且颜色不得为唯一编码通道。
⑤ **规模 M**（含 UI 分层；退化为只显主题 `rule` + `mark` 则 S）。
⑥ **前置 / 不做理由**：需经主理人向程基岩确认「所有 roll 完成」的确切时序位置（本文不写死行号）；若时序不允许，取 S 级退化版。若用户偏好「不预告、靠临场反应」的紧张感，整体不接 —— 这是手感取舍，交用户拍板。

## 四、候选 D · 地窖低语（关联 · 叙事钩子，S–M）

① **动机与 MDA**：补三者中唯一空缺的**关联** —— 单机肉鸽的关联感来自「世界在意我、事物之间有意义联系」。MDA 纯落 **Aesthetics**（Narrative / Fantasy），**不动 Mechanics**。
② **一句话循环**：首次遇到某印记 / 圣所 / 主题 / 主题 Boss 时播报一句条目文案 → 图鉴已发现条目展开可见 → 收集从「打勾」变成「读懂地窖」。
③ **挂接点**：`MILESTONES`（已有「每条只播报一次」的复用通道）、`CODEX_KINDS` 五类 + `codex` 发现集、`menu.gd` 的 `_codex_section`、`SIGILS` / `SHRINE_OFFERS` / `FLOOR_THEMES` / `CODEX_BOSS_NAMES` 的 `name`（纯只读查表）。拟新增只读文案表 `FLAVOR`。
④ **风险与 E1/E6**：E1 / E6 / 坑 5 / 冻结规格全零（纯文本、纯只读派生）。**登记三件套是主要风险**：新增 `FLAVOR` 须同时 ① 写入条目 ② 核对白名单 / 显示名 / 图鉴分母（分母由 `codex_bosses_total()` 等派生，文案**不入分母**）③ 可见效果断言（首次确实播报、重复不播报）。Sprint 14 的 `icon_codex` 漏 `GEN_NAMES` 静默白框、`bulwark` 表里有但 `match` 漏分支零效果，都是「表写了没接上」的同款根因，不可只验中间状态。
⑤ **规模 S–M**（由文案量决定；只给 3 位主题 Boss 各写一行即 S）。
⑥ **前置 / 不做理由**：**项目当前无世界观 / 视觉锚点文档，我不臆造设定** —— 须先由用户从 3 个基调选项（「废弃矿窟的实用主义」/「低语信仰的神秘」/「黑色幽默的冒险日志」）中拍板再动笔。若用户希望保持纯抽象数值游戏、不引入任何叙事调性，整体不接。

## 五、推荐阶段划分

| 阶段 | 方向 | 理由 |
|---|---|---|
| **一 · 核心增量** | **A 地窖誓约 + B 抉择回声** | B 是 A 的数据地基（同往 `last_run` 写平行只读字段），同批可共用一套断言 + 一次登记三件套，零耦合风险。A 是唯一系统级增量，且严格零 E1 / E6 / 坑 5 / 冻结规格影响 —— 在「冻结 34/34 OK、工作树干净」的收官态上，是唯一不付重定代价就能拿到 Dynamics 增量的路径。 |
| **二 · 沉淀** | **C 层签 + D 地窖低语**（D 依基调拍板取一或全取） | 两者都是把阶段一建立的「玩家开始在意自己的决策」放大为**可读（C）/ 可感（D）**，不引入新状态、不动 rng 流。晚一步铺可避免单批跨过多 UI 面，也便于按阶段一的复盘数据决定 C 默认显示几项。 |

**给用户的选择项**：① 只做阶段一（最稳，零 UI 面扩张）；② 阶段一 + 二全取（完整「决策 → 可读 → 可感」闭环）；③ 只做 B + D（纯沉淀小批，系统增量留到 Sprint 17）。**推荐 ②，但锁定权在用户。**

## 六、为什么比「再加一把枪 / 再加一个房型」更值得做

1. **回支柱，不是继续漂移**：A/B 把「决策」从决策点数量升级为「决策之间有依赖、有跨局回响」，正面兑现 Sprint 13 未完成的「决策深度」。
2. **组合级 vs 线性级收益**：内容已过饱和，认知负荷接近上限；再加同类内容只会**稀释每个系统的可辨识度**，且每个新实体都要过登记三件套（分母 / 显示名 / 断言），成本线性涨、收益递减。加「关系」不新增任何实体，却让 N 个孤岛互相读取，产生新的决策情境。
3. **红线成本差异**：新枪走 `weapons.gd` 开火路径（rng 密集 + `meta_content_unlocked` 门控）；新房型改 kinds → `_smoke_fingerprint` 重定 + `dungeon.gd` 死端分配 + 两处 `_enter_room` 分支（Sprint 13/15 两度列为「中风险备选」未接）。A/B 是**零重定批次**：指纹不变、34/34 不变、`assets.gd` / `meta.gd` / `.tscn` 零改动。
4. **主导策略**：更强的枪 / 更好的房型会立刻产生「选它必优」，需重做平衡；A 的兑现奖励刻意不给数值，从机制上规避主导策略。

## 七、明确不建议做（防范围蔓延）

1. **第 12 房型 / 房间事件池**：改 kinds → 指纹须按预期代价重定；与 `shrine` 三选一骨架高度同构，属**同类内容堆叠**，与 Sprint 16 定位直接冲突。Sprint 13/15 已两度列为备选未接，不建议第三次翻案。
2. **`FLOOR_THEMES` 8→12 / 第四位主题 Boss**：前者是硬红线（四处周期来源不一致 → 双轨错位 + E1 全量重定，永不接）；后者第三 Boss 刚在 Sprint 15 落地，再来一位边际递减，且 Boss 战 rng 消耗不同会令掉落 / 编队序列漂移、需登记重定基线。
3. **武器淬炼 / 词条、每日挑战加固定词缀**：前者改 `weapons.gd` DEFS 与开火路径（rng 密集 + 解锁门控）；后者改 `start_run` 的 rng 顺序 → 基线重定。两者均为高 E1 风险的重构级工作，且与「局外沉淀」支柱无关，建议单独成批、不与本批混。

## 八、待用户 / 主理人拍板项

- A 的兑现度**是否允许落盘**（`last_run` 平行字段）—— 决定 A 是 M 还是退化 S。
- C 的「预告随机性」是否符合期望手感（不预告 = 临场紧张 / 预告 = 可规划）。
- D 的世界观基调三选一；无基调则不启动 D。
- 经主理人向程基岩确认两处时序：`_settle_meta` 后追加只读字段、进层「所有 roll 完成」的位置。**本文不臆造 API，实现前须重新实读挂接点行号。**
