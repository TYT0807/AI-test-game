## 0. 这批在管什么（一句话）

**手记是本作唯一成体系的「玩家可读到承诺」的文本层。**它一旦吹出去没人验，玩家就按它做决定，做错就死——这比数值错更伤，因为玩家会以为是自己理解错了。作者早就点过这个病根，原话：

> 「注意游戏内部是肯定有动作帧那些的，不是一个纯粹的摇一摇就算数了」

——批评的就是「说的比做的多」。本批不再犯第二次：**文案的每一句必须能指回一个磁盘上存在的字段或一次可复现的行为**。

⛔ 本批不是「给文案建一套系统」。AGENTS §4 的红线照守：只做 **一张表 + 一条静态门**（§5），不建解析器、不建 DSL、不做运行时校验框架。

## 1. 错位逐条处置（五条）

判据用我自己那三问：①这是情节/台词/章名吗？②这是人物/世界/道具的**属性**吗？③游戏内是否已有同名或同意象？
下面每条都附**本轮实读证据**（函数名为主，行号只在当场 `grep -n` 坐实时才写）。

### ① `bosses/third_boss`「比熔潮慢半拍，比守望者狠」——✅ 保留，并升格为写法范本

实读（本轮坐实）：
- `boss.gd` `var skill_interval := 3.0`；`boss2.gd` `setup()` 内 `skill_interval = 2.2`；`boss3.gd` `setup()` 内 `skill_interval = 2.6`。
- hp：`boss.gd` `setup()` `max_hp = 320.0 * (1.0 + (floor_num - 4) * 0.12) * Game.main.abyss_hp_mult`；`boss2.gd`／`boss3.gd` 同式但基数 **360.0**。

⇒ **「慢半拍」**＝2.6 > 2.2（脉冲间隔确实比熔潮长）；**「狠」**＝360 > 320（血确实比守望者厚）。两句都是**同一量纲上的可比陈述**，且比较对象都在同一张表里可读。这条是全仓目前唯一逐字成立的 Boss 手记，所以把它当**范式**立起来：

> **诚实文案的形**：`<名字>。<道属短语>，<可测的比较级>，<可测的第二项>。`
> 比较级允许，但**两侧必须都是磁盘上的数**；不许拿"感觉"当比较级。

顺带一句：这句里的「地狱旧客」是调性描述不是事实承诺，不违反口径（它不引导任何操作决策）。

### ② `bosses/prism_warden`「别站在光缝里，砸它的核」——❌ 两处空承诺 ⇒ 改文案（默认）+ 拆出待办 #8

实读：
- **「光缝」作为危害实体不存在**。全仓 `scripts/*.gd` 扫 `光缝` 只命中 `data.gd` 这一行文案本身。`boss.gd` `_pulse_theme(rule, k)` 的分派只有 `magma / ice / vines / toxic|swamp / vein / pressure / silent` 七个分支，**没有 `prism`／`seam`／`light` 任何东西**；`silent` 分支做的是 `Game.main.player.relic_suppress_t = 2.0` + `apply_slow(0.8, 2.0)`，不是"缝"。
- **「核」不是可分部位**。`boss.gd` `_ready()` 里 `core = Sprite2D.new()` 只是视觉节点；伤害入口只有一个 `take_damage(amount, from_dir, crit)`，里面 `hp -= amount` **不分部位**，也没有第二块 hitbox（碰撞体外形是 `_ready()` 里那个 `CircleShape2D radius = 16.0`，覆盖全身）。
- 代码里**真正**能被玩家观测到、且和这句话意象同源的两件事：
  1. **阶段切换**：`_tick()` 里 `hp <= 0.66 * max_hp` → `_enter_phase(1)`，`hp <= 0.33 * max_hp` → `_enter_phase(2)`，注释自己写着「阈值只下不回退」；`_enter_phase(k)` 会把三枚碎片的 `modulate` 切成 `_phase_tints[k]`——**碎片变色是玩家读招的唯一前置信号**（规格注释原话「玩家读色预判机制」）。
  2. **高压阶段真会把你打飞**：`_pulse_theme("pressure", …)` 分支 `pd < 200.0` 时 `player.apply_blast_push(...)` + `Game.shake(0.5)`。这才是那句「别站进去」在代码里的真身。

⇒ **处置**：文案改写为只讲这两件可观测事实（见 §3）。同时把「一只怪分不同部位打」**正式拆成独立机制待办（#8）**，代价写清（§4），不在本批偷偷实现。

> 作者当初正是拿「别站在光缝里，砸它的核」这句质疑「那还有一个怪物分不同部位来打」——那个质疑是对的，但它是一张**施工票**，不是一句可以靠改文案糊过去的瑕疵。本批把两件事分开：文案先诚实，部位伤害另立项。

### ③ `themes/pressure`「子弹会拐弯，贴墙打」——❌ 主语互换（最严重的一条）

实读：
- **「子弹会拐弯」在这个游戏里只有一处实现**：`weapons.gd` DEFS 的 `mw_swarm` 条目带 `"homing": true, "meta": "u_mw_swarm"`；`bullet.gd` `var homing := false`，注释「蜂群导弹 mw_swarm：自动追踪最近敌人」，行为在 `_process` 的 `if homing and friendly:` 段。它是**玩家武器属性**，与楼层主题零耦合。
- **高压层真正的效果**在 `game_main._apply_floor_theme()` 的 `match _theme_rule: "pressure"` 分支：`enemy_speed_mult = maxf(enemy_speed_mult, 1.3)` 与 `diamond_mult = maxf(diamond_mult, 1.5)`。
- 而「贴墙打」恰好**押反**：`_pulse_theme("pressure", …)`（Boss 的高压阶段技）是 `pd < 200.0` 就把你推开——贴墙等于把自己钉在射程圈里挨推。

⇒ 这就是任务书说的**主语互换**：值钱的那条（残响 ×1.5）没说，说了的那条（拐弯）不存在，而且顺手给了个反向走位建议。
⇒ **处置**：文案改为讲 `enemy_speed_mult ≥ 1.3` + `diamond_mult ≥ 1.5` + 被脉冲推开这三件实测事实（§3）。`homing` 那句话归位到武器自己的 `desc`——它本来就在那儿（`mw_swarm.desc`「子弹自动追踪最近的敌人」），不需要搬。

### ④ `bosses/pyrothalassian`「弹匣留一半」——❌ 全仓无实现，且已被三个地方引用两个不同实现 ⇒ 冻结措辞 + 一次性对齐

实读：
- 全仓 `scripts/*.gd` 扫 `留一半`／`half` 类弹匣规矩：**零实现**。既不是玩家侧约束（`player._start_reload()` 的条件只有 `if _reload_t > 0.0 or mag() >= mag_cap(): return`，即"满弹不许换弹"是**现状行为的副产物**，不是惩罚式规矩），也不是敌怪机制（`boss2.gd` 全文只覆写 `_theme_offset / boss_name / variant / codex_id / max_hp / skill_interval / core.modulate`，没有任何弹匣相关字段）。
- **撞车面确认**（这是本条最要紧的部分）：
  | 引用处 | 引的是哪个实现 | 状态 |
  |---|---|---|
  | `data.gd` FLAVOR `bosses/pyrothalassian` | **无**（空头支票） | 本批改写 |
  | S35 §5 `hungry` 饿鬼道规矩「满弹匣不得换弹」（`check: "reload_full"`） | 违例即 `Game.diamonds += 4` | S35 在册 |
  | S36 §6.3 `bw_slack_half`「半 slack 铳」——「『弹匣留一半』那条玩家规矩，反过来做成『留一半才打得响』」 | 未开工（T-B 挂闸） | S36 在册 |
- ⇒ **同一句自然语言现在挂着两个语义相反的候选实现**（一个是"满弹不许换"，一个是"留一半才打得响"），外加一张空头支票。第三批再引就是第三个。

**处置（我裁，不问作者）**：
1. **FLAVOR 那句删掉「弹匣留一半」**，换成熔潮自己可测的事实（§3）。空头支票不留货里。
2. **立措辞归属规则**（本批硬产出）：`弹匣留一半` 这五个字**冻结为 `bw_slack_half` 的专属说法**，⛔ 不得用作 S35 `hungry` 规矩的自然语言描述。
   理由：`hungry` 的正典措辞在 S35 实稿 §5 已写成**「满弹匣不得换弹」**，那是**禁止式**（满弹时按 R 才违例）；`bw_slack_half` 是**许可式**（留一半才打得响）。两者语义相反，共用一句必然让玩家读错。以后文档一律用各自的正典措辞，⛔ 用「留一半」指代 `hungry`。
3. **给 S36 加一条免费护栏**：`bw_slack_half` 若将来落地，它的 `desc` **不得含「留一半」三字**（否则又是"文案说有、机制是另一套"）；要表达许可式语义就直写阈值（例如「弹匣剩不到一半才打得响」）。这条写进对照表的 `forbidden_substrings`，由 §5 的门 G-4 拦住。

### ⑤ `themes/silent`「听不见脚步，多看小地图」——❌ 反向建议（优先级最高的一行）

实读：
- `game_main._apply_floor_theme()` 末尾：`hud.set_minimap_hidden(_theme_rule == "silent")`；非主题层早退分支另有 `hud.set_minimap_hidden(false)` 复位。
- `hud.set_minimap_hidden(v)` 的实现是 `_minimap_panel.visible = not v`。
⇒ 静默层**恰恰把小地图关掉**，文案却叫玩家"多看小地图"。玩家照做会在最需要空间信息的那一层找不到面板，还怀疑是自己设置坏了。

**处置**：改文案（一行）。这条是五条里**唯一"作者自己打开游戏就会立刻看见矛盾"的**，所以我判断它是**该立刻改的文案行**（详见文末自报）。

另外「听不见脚步」这半句要不要留？——**留**，但要给它一个可证伪的落点：静默层的可观测事实是「小地图整块消失」＋「池子收窄」（`FLOOR_THEMES[7].pool = 2`，八主题里最小，与 `ice`/`vines` 同档）。新文案把这两件写实，"听不见脚步"降格为调性短语而非操作指令。

## 2. 为什么默认路线是「改文案」而不是「补机制」

| 维度 | 改文案 | 补机制 |
|---|---|---|
| 触到的东西 | `.gd` 里的字符串字面值 | 新实体／新 hitbox／新计时／新随机流分支 |
| E1 指纹风险 | 零（文案不进 rng 路径，也不进 `[SMOKE-META] fingerprint`） | 光缝危害牵动 E6 计时与 E1 随机流；部位伤害改受伤分支即动冻结串 |
| 冻结面 | 只 `data.gd` 一个文件变（今天已是 FAILED 态，收官统一刷） | `boss.gd`／`boss2.gd`／`game_main.gd` 多点 |
| 玩家侧收益 | 立刻停止误导 | 立刻停止误导 **+** 多一个真机制 |
| 谁有权拍 | 主理人（本批即裁） | 需作者点头排期（方向级：战斗深度） |

结论：**②③④⑤ 四条走改文案，本批落地**；「部位伤害」「光缝危害」作为**机制票**留在 §4，等作者排期，不塞进本批也不塞进 S35/S36/S37 现有批次（理由逐条写在 §4）。

### 3.1 关于「比 X 密 / 厚一档」这种比较级怎么写才不会变成新的坑

比较级本身合法（①就是范本），但有两条附加要求，我直接固化进对照表：
1. **比较两侧都必须是对照表里的数字字段**（`interval` vs `interval`、`hp_base` vs `hp_base`），⛔ 拿数字比形容词（"狠"就是这一类的软着陆——它有 hp 360 兜底，所以我没改 ①）。
2. **比较对象必须在同一局内真的可达**。守望者／熔潮／玄渊之主分别在 warden 层（`(n-4)%8==7`）、主权层（`(n-4)%16==15`）、第三层（`(n-4)%32==23`）出现，一只怪的手记提另一只，玩家可能在同一局没见过——①已经这么写了并且成立，我不为它回头改；但**新增**的比较级不许扩大这个面（这也是我把 `pyrothalassian` 的新文案写成"跟守望者比"而**不是**引入第三个未知对象的原因：守望者是玩家最先遇到的主题 Boss）。

## 4. 机制票（不塞进现有批次的判断）

### M-A 部位伤害（「砸它的核」的真身）＝ 待办 #8

**能不能塞进现有批次：不能。** 代价清单（这就是为什么它值一个独立批次）：
1. **新 hitbox**：`boss.gd` `_ready()` 现在只有一个全身 `CircleShape2D(radius=16)`。分部位要么加子 `Area2D`（新物理节点＝新 collision 层规划，AGENTS §4 里没有空闲层可用需先裁），要么在 `take_damage` 里按 `from_dir`／命中点做伪分区。
2. **受伤分支**：`take_damage(amount, from_dir, crit)` 现在是单一路径 `hp -= amount`。加部位倍率＝在该函数里加分支，直接改变**所有**打到 Boss 的伤害来源（子弹、爆炸、毒云 DoT、词缀）的实际结算。
3. **重录冻结串**：`boss.gd` 在 `SPR21-FROZEN.md5` 内（34 个 `.gd` 全文件字节快照），改了 md5 必变；更要命的是**行为基线**——E1 指纹 `[SMOKE-META] fingerprint` 与 `_smoke_abyss_check()` 的基准值都建立在"伤害入口单一"的前提上（`_smoke_abyss_check` 的 dmg 动态验伤那段注释明写「制造纯净单一入口语境」）。
4. **`_smoke_abyss_check` 基准重算**：该探针用 `player.take_damage(test_dmg, Vector2.ZERO, null)` 验 `round(base × abyss_dmg_mult)`；Boss 侧一旦引入部位倍率，同类断言需要新的期望表。
5. **UI**：HUD 现在只有一条 `Game.boss_hp_changed.emit(hp, max_hp)` 总量血条；分部位要么显示合成后的总量（那玩家看不见部位，机制白做），要么新增分段显示（那是 UI 批）。

⇒ **建议排期**：单独一批（暂记 **S40+**），且在 S36 专武批**之后**——理由：S36 §6.3 已经把 `bw_core_hammer`「敲核槌」当成"抢了『砸它的核』那一下"来设计。若 M-A 落地，`bw_core_hammer` 的"抢的是哪一下"才第一次有了真所指；若不落地，那把武器的出处注释要跟着改（见 §5 的 D-2 依赖声明，门会替我们盯着这件事）。

### M-B 光缝危害（「别站在光缝里」的真身）

**能不能塞进现有批次：不能，但它可以搭 M-A 同一批。** 代价：
- **新实体**：一条持续存在的"缝"要么是新节点类型，要么复用 `toxic_cloud.gd`（`_tick_enemy()` 里 `distance_to < radius` 就 `p.take_damage(1, global_position)`）。复用省一个新类，但云的计时/E6 口径要按 `fixed_step = true` 置位（`boss.gd` 的 magma 分支已经是这么做的，有先例）。
- **牵动 E6**：任何新计时/DoT 一律 `Game.FIXED_DT`（AGENTS §4.1），豁免只有两条且不许"顺手统一"。
- **牵动 E1**：如果缝的位置走 `Game.rng`，整条随机流位移——`_pulse_theme` 现在的六个分支里，**只有 magma/toxic/swamp/vines/vein 走固定角度环**（`Vector2.from_angle(TAU * i / n)`），刻意避开 rng；增援 `_call_reinforcement()` 才是走既有 rng 流的。新危害必须沿用"固定环"范式才能零 rng。
- 好消息：**它不需要新伤害出口**——`player.take_damage()` 是唯一入口，深渊乘子在那里生效，历史上那里踩过双重计数坑（`slug.gd` 注释「避免与接触伤害路径双重计数（base × abyss_t² 违例）」），照 slug 的路径走就行。

⇒ 判语：M-B 比 M-A 便宜一个数量级（不改受伤分支、不动血条、不必重录 `_smoke_abyss_check`）。**如果作者只想批一个机制票，我要 M-B 不要 M-A。**

### M-C 「弹匣留一半」到底要不要做成真机制？

**不要为本句做。** 它已经被 S36 `bw_slack_half` 认领为武器机制（许可式），把它再做成玩家规矩就是同一个创意点子造两份实现。本批只做措辞归属（§1④）。

## 5. 机检：一张表 + 一条静态门（我的裁定）

**裁定：做，但严格限定成「一张数据表 + 一个只读扫描器」。** 不建解析器、不做运行时 UI 校验、不加新 action、不新增探针类别。理由与红线：

- AGENTS §4 那条「别为文案建复杂系统」我照守。但 §5 那张表（断言有效性四类）里本项目反复吃过「只验标志不验数值」「前提守卫型恒过」的亏——**文案恰是"吹出去没人验"的重灾区**，一条静态门的成本远低于下一次作者质问「游戏里真有这个东西吗」。
- 盘上已有**同型先例**，不是我发明的新架构：`validate._check_daily()` 用 `FileAccess.get_file_as_string("res://scripts/menu.gd")` + `_slice()` 锁挂接字符串（注释写明原因：「探针用脱离树 holder 直调 → 删掉挂接行四门控与断言仍全绿」）；`_check_apply_ids()` 用源码回读验「池 id 有没有 apply 分支」。**本批的门就是这两个的第三次复用。**

🔴 **G-2 的一条实现纪律（本轮踩过后写死）**：锚点 needle 必须落在**非注释行**。第一版我用 `"rusher": {` 这类表键当锚点，结果 `data.gd` 的 FLAVOR 块自己就含这些 key——扫描器把文案块当成"机制存在"的证据，**七十四行全绿、零信号**。同理，needle 若命中另一条 needle 所在的那行注释也会假绿。所以扫描前先剥整行注释，并且每条锚点都要现场核一次命中数（本轮实测：98 条锚点全部在剥注释后命中 ≥1）。

### 5.1 表是什么

`production/sprint-39/SPR39_对照表.json` —— 每句 FLAVOR 一行，字段：

| 字段 | 含义 |
|---|---|
| `key` | `themes/<rule>` ／ `bosses/<codex_id>` ／ `shrine/<id>` ／ `enemies/<id>` …（共 74 条全覆盖） |
| `text` | **应然文案**（本批：四行为改写后的终态，其余 70 行＝磁盘现值）。门 G-3 拿它和 `data.gd` 做全等比较 ⇒ 改前必红 4 条，改后转绿 |
| `prev_text` | 磁盘旧值（逐字），给编程侧做搜索替换与事后对账用；⛔ 让新文案与它相同 |
| `claim_type` | `numeric`（含数字/比较级）／`spatial`（教走位）／`entity`（承诺某实体存在）／`tonal`（纯调性，无可证伪内容） |
| `anchors[]` | 该句赖以为生的**代码锚点**：`{file, needle, min_hits, supports?}`，needle 必须是函数名/字段名/语句片段（⛔ 行号）；`supports` 写"这个锚点撑住句中哪半句"——**半句配一锚，配不上的半句删掉**（本轮就删了两处，见 §3） |
| `forbidden_substrings[]` | 该句⛔ 出现的串（如 `光缝`、`砸它的核`、`多看小地图`、`弹匣留一半`）；跨作品专名与主角同框禁忌放顶层 `forbidden_global`（`索拉尔`／`太阳骑士`／`苏瑾`） |
| `max_len_override` / `len_note` | 仅既有长句需要（当前只有 `shrine/purify` = 31）：不为凑统一数字去改一条没毛病的文案 |
| `status` | `verified`／`pending_gate`（门还没跑）／`deferred:<票号>`（对应机制票未落地）。机制票本体放顶层 `mechanism_votes`，⛔ 塞进 `status`——那会让 G-1 的键集比较失真 |

### 5.2 门是什么

`production/sprint-39/SPR39_flavor_contract.py`（纯标准库，落 production 目录、⛔ 落 `_tools/`——`_tools/` 是 gitignored 的临时件，这张表要被后人跑到，不能藏在忽略区）。六条判据（G-5／G-6 是写完扫描器后补的：**光有 G-1～G-4 拦不住"改成了另一句同样没根据的话"**）：

| # | 判据 | 红了意味着什么 |
|---|---|---|
| G-1 | `FLAVOR` 键集 == 表行集，条数 == 74 | 有人加了手记没登记，或删了手记表没同步 |
| G-2 | 每行的 `anchors[].needle` 在指定文件的**非注释行**里命中 ≥1 | 文案吹了一个磁盘上不存在的东西（②③⑤ 当年就是这种） |

### 5.3 要不要把它做成 `.gd` 里的常驻启动门？——**不要**（本批裁）

理由三条，都落在既有纪律上：
1. `validate.gd` 的 `problems=0` 是七件套第 1 门，往里加 74 条文案比对，会让**每次改文案都要动 validate.gd**（也在冻结面里），摩擦反而大；而 python 侧扫描器不受 `.gd` 冻结约束。
2. AGENTS §5 的分类学警告：把「表内容与表自身一致」式的检查塞进启动门，容易长成**常量自比较**（不计入断言数的那种）。放外部脚本，判据是"跨两种语言的两个来源交叉"，性质更干净。
3. 文案漂移不是运行期故障，不需要玩家打开游戏就吼一声；它需要的是**提交前有人跑一次**。

⇒ 落地形式：`SPR39_验证口径.md` V-E 把 `python production/sprint-39/SPR39_flavor_contract.py` 列为**本批门禁第 8 项**（只对改动过 FLAVOR 的批次强制），并把三条变异刀写进验收。将来若要转正为常驻门，须按 AGENTS §5 的新机检四条规矩重新走一遍，不在本批偷跑。
