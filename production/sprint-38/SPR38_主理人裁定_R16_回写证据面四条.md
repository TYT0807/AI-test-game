## R16-2 取证卫生三条

**(a) `--archive` 吃流水行引文（二手见证）→ 允许，但降档标注，⛔ 升格成一手等价物。**
依据：`spr38_proof_edits.py:10` 已把 `--archive` 定位成「只在**没有**写后快照时兜底」，其证据力天然低于
快照／输出原件——它验的是「引文串在不在活台账按序在」，不是「当年真绿过」。故：凡 `--archive` 喂的是
**流水行抄文而非当年输出原件**，报数必须用专名 **`PROVEN(archived-ledgerquote+subseq)`**，⛔ 裸报
`PROVEN(archived+subseq)`（那是输出原件档）。R30c 本轮**恰属此档**：一手见证已毁于 R16-2(c) 的同名覆盖，
`--after` 走快照路线报 `PROVEN@write` 才是正报，`--archive` 只作旁证。
**实现方式约束**：口径名区分**不得**为此改 `spr38_proof_edits.py` 的 PROOF 判定结构（该件不在 faces PROTECT
字典、改动无收官背书必要）——最小落地＝调用方在 tee 输出行尾追加口径注记（`ARCHIVE_SOURCE=ledger_quote`），
机检面比对注记不比对件内字符串；若将来要把它做进件内，走 R16-3 转正通道另议。

**(b) 写后快照 `_wb_after_rNN/` → 升成回写件模板固定段。**
这是本次修复的**结构性正确**：一手见证从此由「靠人记得 tee」变成「apply 自己落笔即产证」，且下一轮
before 只是复用（`spr38_proof_edits.py:8-10` 的取件约定已成文）。R33 apply 已带（`:12` `AFT=` 行实读坐实），
即刻起每轮回写件模板必备此段；缺该段的包 ⇒ 该笔 edits 回写直接记 `UNPROVEN`，不许拿「下轮 before 会救回来」
推脱（下轮 before 存在与否不该赌）。

**(c) A51 §1 的 tee 纪律 → 裁订正，补一句「⛔ 与取证件同名」。**
原纪律被自己的产物破坏（`_r31_proofs.txt` 现 29 行、含 `TAG=APPLY`、「逐字节=True」0 命中——本窗复核一致），
属实证破口，不是假想风险。订正文（追加进 A51 §1 末尾，搭 (a) 所述同一顺风车，⛔ 回改原句）：
「tee 落盘之证明件**分名**：取证件 `_rNN_proofs.txt`／回写件 `_rNN_apply_proofs.txt`；apply 落笔前 grep
自身源文本、含取证件同名即拒绝（R33 已立自防，范式 `_tools/spr38_r33_wb_apply.sh:27-28`）」。
**生效范围**：即刻；R34 起 apply 件模板照此。
**落点**：`_tools/AUTORUN_LEDGER.md` A51 §1 追加句（随 R33 包）＋ 本裁定件存档。
**验收判据**：①R33 及以后各轮，`_rNN_proofs.txt` 与 `_rNN_apply_proofs.txt` 两文件并存且前者不含
`TAG=APPLY`；②变异刀反证已在盘：不给 `--after` 正确降级 `CONSISTENT(subseq-only)` rc=1、payload `new`
串改成盘上没有的 ⇒ 按序在=False rc=1（R33 报数，引用即可）；③自防闸本身的可证伪性——人工造一份
含取证件同名的 apply 副本跑一次，必须 ABORT（一次性件，落 `_tools/`，命名带 `selftest` 子串入
CHAIN_EXCLUDE 族，防污染链原件选取）。

## R16-3 「mk 内汇总判据必有本地重算＋互校」转正 → 不占新格，收编为回写件模板固定段 + falsify spec 必含项

**裁定**：⛔ 升第 58 格。理由三条：①封顶条款（`AUTORUN_LEDGER.md:825`）的例外通道是「抓到真 bug 才**立新面**」，
本题抓到的缺陷属**回写件自身**的，它的自然归宿是回写件模板的内建纪律，不是给 `spr38_r8_verify.py` 再加一格
跨件审计；②候选格的实际内容＝「每个 mk 都自带本地重算＋互校闸」，而这已由通用反证件对**现存全部 mk**
给出逐闸变红证据（R31 19 态／R32 20 态，合计 39，与 `_r33_gist.json` `falsify_total_states=39` 现值吻合，
两份 `_r33_falsify_r3{1,2}.txt` 尾行 VERDICT GREEN 本窗实读）——证据强度足够，但对象是模板质量而非盘上新缺陷面；
③第 58 格若做成「抽查某 mk 有无重算」，对没被抽到的 mk 是前提守卫型恒过面，§5 教训重来一遍。
**转正形态（即刻生效）**：自 R34 起，任何新 mk 的 falsify spec **必含**「汇总判据被 drop／被漂」两类变异态
（`drop_*` 与语义闸态，参照 `_r31_falsify_spec.json`／`_r32_falsify_spec.json` 形状），无 spec 的回写包
⇒ apply 拒绝落笔。A52 §1③ 那句「⛔ 我自封格」至此解除：**格不封，纪律入模板**。
**R16-2(b)(c) 两条自防是否一并入格**：同样⛔ 入 `spr38_r8_verify.py`；(b) 已是模板固定段（R16-2b）、
(c) 已是纪律＋自防闸（R16-2c），各自的机检证据走 R33 已交的那把刀，⛔ 重复立格。
**验收判据**：R34 起的回写包若 mk 无配套 spec 而 apply 仍落了笔 ⇒ 本条 RED（可证伪点在前不在后）。

## R16-4 `_falsify/` 变体件卫生 → 立归档口径，执行归编程侧，本窗零删除

**现状实读**：`_falsify/` 149 件（含 gist/out/proof 子类，与 `falsify_dir_n=149` 吻合；R33 报「148 变体」
为计数口径差，⛔ 追平、以现值报数）；顶层历史 `_r3*_falsify_*` 17 件（`stray_falsify_top_n=17` 吻合）。
**裁定**：立口径如下——
1. **判据先行**：先证实/证伪「mtime 最新污染」假设——`is_chain_artifact()`／`latest_chain()` 判据是
   「头部链标记 ＋ `RUN-` 行 ＋ mtime 最新」（AGENTS §7），纯变体件若无链标记则**本来就不入围**。
   R34 取证件跑一条现算：`_falsify/` 与顶层变体中「含链标记者」计数；为 0 ⇒ 污染风险＝不存在，处置只有
   「整洁」一种动机，节奏可以松；为非 0 ⇒ 那些件**立即**按 CHAIN_EXCLUDE 命名族规则处理（见 3）。
2. **滚动归档**：每轮 falsify 开跑前，把上一轮变体移入 `_falsify/_archive_r{N-1}/`（`mv`，字节不动）；
   `_falsify/` 顶层只留当轮工作集。归档不删——⛔ 拿释放空间当动机删证据件。
3. **顶层 17 件历史 `_r3*_falsify_*`**：名字已含 `falsify` 子串、已在排除族内，⛔ 删、⛔ 改名，原地留着即合规。
4. **执行归属**：编程侧（工具面自治区，`_tools/` 全 gitignore）；主理人只裁口径，不动手。
5. 🔴 **本窗重申硬规**：任何处置只有「移动／改名」，⛔ 删除盘上既有证据件（AGENTS §7 末段同款纪律）。
**验收判据**：R34 后 `_falsify/` 顶层文件数 ≈ 当轮 spec 态数×2＋对照（可从 `_r34_gist.json` 直读）；
归档目录存在且其中件 md5 与移入前登记值一致（`_tool_edits.md5` 顺路记一笔即可）。
