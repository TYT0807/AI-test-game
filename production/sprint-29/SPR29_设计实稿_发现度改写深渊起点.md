## 二 核心判断（一句话 + 定名）

**发现档数（玩家以前做的事）第一次成为深渊开局（玩家当下选的档）的只读输入**：探索得越全，同一深渊档下开局越从容；反过来，同一份图鉴积累，在不同深渊档下兑现成不同厚度的缓冲。这是两个系统各用自己的既有语言互相改写——发现度输出「一次性起始状态」、深渊档提供「需要缓冲的上下文」，不是同一个难度旋钮的两个方向（守 S27 定名原则）。

| 定名维度 | 口径 |
|---|---|
| 功能名 | **起点缓冲**（本稿通用名，非面向玩家文案） |
| 面向玩家措辞 | 建议用「拾痕」语义（如「拾痕余荫·开局护身」），只说「更从容」不写「必须/建议先集齐」——**最终文案归叙事层，本稿不擅定稿** |
| 语义红线 | 缓冲是「长期探索的兑现」，不是「冲高层的准入门槛」；不得出现解锁/置灰/推荐档位式表达 |

## 三 「起点缓冲」是什么、改什么、什么量级

| 维度 | 口径 |
|---|---|
| 改哪个字段 | **只改 `player.shield_charges`（环盾层数）**——一次性、可消耗、已有 HUD 显示；不改 `abyss_hp_mult`/`abyss_speed_mult`/`abyss_dmg_mult` 三乘子本体，不改 `max_hp`/`diamonds`/`suffix` |
| 为什么是 shield | 它就是「缓冲」的语义本身；不动伤害基线基线、不动经济（避开圣所/R1/R2 净化）、不动 frail 灾祸的实际削减分母（S28 刚修过 frail 读实际值，max_hp 载体会牵动它） |
| 为什么不改乘子本体 | 三乘子直接进 `slug.gd`/`boss*.gd` 敌人 max_hp/speed 与验伤路径，改它等于改 S21 `SMOKE_ABYSS` 的「受创=round(base×dmg_mult)」映射与 `validate._check_abyss` 单源自检，半径大；且「发现度高→敌人弱」与「tier 低→敌人弱」是同方向踩一脚，不产生新 Dynamics |
| 量级（推荐） | **每高一个发现档 +1 层盾**：0/1/2/3/4 档 → 0/1/2/3/4 层，仅深渊局生效，上限 4 层；量纲与 `CODEX_BOONS.enemies_5` 的 shield value=1 一致，映射 1:1 心智最简 |
| 为什么这个量级 | t10 敌人 dmg ×1.70，4 层盾约等于多扛 2 次命中——是「从容」不是「免死」，不抹平深渊档；1:1 让玩家能直接说出「图鉴越全，开局盾越厚」 |
| gate 条件 | **仅 `abyss_tier > 0` 生效**；tier=0 的普通局缓冲恒 0（否则会动普通局起始盾基线，牵连普通局既有探针期望，且稀释「发现度×深渊」的交叉语义） |
| 与 enemies_5 关系 | 不重复计数：enemies_5 是「无条件发现度被动」（任意局），起点缓冲是「仅深渊局的额外叠加」，语义与生效域都不同；满档深渊局最多 1（被动）+4（缓冲）=5 层（见 §八 风险 R6） |

**档位映射速查（本稿定死的数值口径，tier>0 生效）**

| 发现档数（`codex_boons().size()`） | 0 | 1 | 2 | 3 | 4 |
|---|---|---|---|---|---|
| 起点缓冲盾层数 | 0 | 1 | 2 | 3 | 4 |
| 满档被动 enemies_5 叠加后（仅当该档已达成） | 1 | 2 | 3 | 4 | 5 |
| tier=0 普通局缓冲 | 0 | 0 | 0 | 0 | 0 |

> 映射为线性 1:1、无查表、无 tier 相乘；「满档被动叠加」一列只是说明与既有被动共存时的上限，不是本批新增数值。

## 四 发现档数的读数口径

| 维度 | 口径 |
|---|---|
| 读哪个刻度 | `Game.codex_boons().size()`——现有只读派生（`game_state.gd:406-413`），遍历 `CODEX_BOONS` 按 `codex[kind].size() >= need` 得出 0..4，纯只读零 rng |
| 为什么不用新字段 | 档数是局外发现度的既有派生，不落盘、不新增 `last_run` 平行键、无旧档兼容成本；同档 + 同 seed 双跑仍逐字一致（既有交付口径） |
| 为什么不用发现集进度 | 条目进度是「原始量」、档数是「已兑现奖励刻度」；HUD 已按 `boons.size()/CODEX_BOONS.size()` 显示「发现度 N/4 档」（`menu.gd:394`），缓冲对齐同一口径，玩家看得到、对得上 |
| 档位映射 | 直接用档数当盾层数（0→0 … 4→4），不查表、不引入第二输入维度，避免破坏 `validate._check_abyss` 的单源自检 |

## 六 三档验证面 + 验数值断言口径

| 发现档 | 深渊局（tier>0）表现 | 普通局（tier=0）表现 | 玩家能否说出「我以前做过的事改变了这次」 |
|---|---|---|---|
| 低（0–1 档） | 0–1 层，近乎裸上 | 0 层（不变） | 能（反面）：「图鉴空着，冲高层就是裸着上」 |
| 中（2–3 档） | 2–3 层 | 0 层（不变） | 能：「捡了些图鉴，开局多一两层盾」 |
| 高（4 档） | 4 层（+被动共 5） | 0 层（不变） | 能：「图鉴全清，t10 开局也有盾打底」 |

**验数值断言口径（只给口径，断言编号/探针由 QA 侧另写）**

| 项 | 口径 |
|---|---|
| 验什么值 | 深渊局开局 `player.shield_charges` 的**实际起始值**（验效果型，不是标志位、不是文案），对比不同发现档数 |
| 什么档位 | 至少覆盖裸（0 档）与满（4 档）两端；建议含中间 2 档形成梯度；并必须有 `abyss_tier=0` 对照局证明普通局不加缓冲 |
| 为什么不是恒过 | 必须在**同一 abyss_tier 下做差分**：构造发现档数不同的两局，若实现只读了档数却没真正加盾、或各档加同样盾，盾值相同 → 断言红；不能只验「有盾」（enemies_5 本就给盾，恒过）——这是 S28 H01/H04「必须构造名义与实际不等的局」的同型纪律 |
| 与 E1 分工 | 指纹零重定只保证 rooms/kinds 不变；这条数值断言补上「映射真的生效」的守卫，缺它则本 Dynamics 只有声明没有守卫（上一稿已承诺，必须兑现） |
| 反向守卫 | tier=0 时任意发现档盾值都不含缓冲——防止 gate 写错导致普通局基线被污染 |

## 七 若不做会怎样 + 支柱漂移防护

| 项 | 口径 |
|---|---|
| 若不做 | 图鉴继续只是被动收藏、深渊档继续只是孤立乘子，「长期积累→当下选择」链仍断；诊断「Dynamics 贫乏」本批不缓解，但**无结构性回退**（两系统各自都好玩，不增加流失） |
| 防护 1·措辞 | 只说「更从容」，禁「必须/建议先集齐图鉴再冲高层」；无解锁、无置灰、无推荐档位 |
| 防护 2·选择权 | 低发现档仍可正常选任意 tier，不加锁、不弹提示；缓冲是奖励不是门槛 |
| 防护 3·UI | 只沿用既有环盾 HUD 层数显示，不新增「发现度推荐」类引导通道（避免认知过载） |
| 防护 4·语义域 | 仅深渊局生效，普通局零差异，防止发现度奖励泛化到全局、沦为又一个被动数值 |
