## 三、阶段一规格（A 层签形势层 + B 手记回转）

### A · `floor_situation()` 纯只读静态派生

位置：`scripts/game_main.gd`，`update_floor_sign()`（`:1010`）之前新增。

**规则 v2（2026-11-08 修订，v1 已作废）**

> v1 作废原因（工程侧实算 + 主理人复核）：`SQUADS.tide` 权重 12、`min_floor=3`，在 3–7 层恒为最大权重项且 7 近战 / 3 远程 → 任何基于权重占比的主倾向派生**输出恒定**（恒为「近战冲锋」），且 `defuser` 占比最高仅 14%，在 30% 阈值下**永不浮现**。v1 产出的是每层同一句话的死文案，无法支撑「进层前准备决策」。

派生规则（纯布尔、零权重、不改 `data.gd`）：
1. `Game.floor_num < 3` → `""`。
2. 遍历 `Data.SQUADS`，`min_floor <= floor_num` 的进候选，**不使用 weight**。
3. 对每个候选的 `members` 求布尔特征：
   - `"回响"`：存在 `id == "echo"` 的成员
   - `"拆弹"`：存在 `defuser == true` 的成员
   - `"治疗"`：存在 `affix == "mender"` 的成员
   - `"护盾"`：存在 `affix == "shielded"` 的成员
   - `"远射"`：`front == false` 的成员 `count` 之和 `>= 2`
   - `"冲锋"`：`front == true` 的 `count` 之和 `>` `front == false` 的 `count` 之和
   - `"成群"`：该编队成员 `count` 总和 `>= 8`
4. 本层特征集 = 所有候选编队特征的**并集**。
5. 固定优先级排序：`回响 > 拆弹 > 治疗 > 护盾 > 远射 > 冲锋 > 成群`，取前 3，`" · "` 连接。
6. 空集返回 `""`。

现行表下的预期实值（探针按此自验）：

| 层 | 输出 |
|---|---|
| 1–2 | `""` |
| 3 | `远射 · 冲锋 · 成群` |
| 4 | `护盾 · 远射 · 冲锋` |
| 5 | `治疗 · 护盾 · 远射` |
| 6 | `拆弹 · 治疗 · 护盾` |
| 7 及以后 | `回响 · 拆弹 · 治疗`（候选集恒定，恒等型断言） |

标签措辞与优先级顺序的**设计终审权在 design-strategist**，已同步复审；若其调整，仅替换字符串表，不返工结构。

红线：**不得出现任何推荐语**（建议/推荐/带/优先），只描述性质，从机制上杜绝主导策略。

## 五、与设计实稿的偏差（已在派单中固化）

| 偏差 | 原设计 | 本批落地 | 理由 |
|---|---|---|---|
| A/B 的呈现形态 | 「可展开层」（需按键展开） | **双行常驻**（第二行小一号灰字） | `ACTION_DEFS` 零新增是坑 5 护栏；按键展开必须注册新动作。且展开态需记忆键位，反增认知成本。 |
| D 覆盖数 | 建议只覆盖 3 位主题 Boss | 覆盖全部 10 条 | 用户裁定。代价：需新写 10 句文案，且三卡下方行数增加，靠「未发现不显示」自然节流。 |
| C 实现 | 可新增 `last_run` 平行字段 | 退化为只读 | 规避 `set_codex_last_run()` 覆盖式写盘风险，且用户未要求跨局计数。 |
