# Sprint 18 设计候选实稿（design-strategist · 文策渊）

> 定位：延续 Sprint 16「加关系不加实体」的换轴路线。Sprint 16 四方向零 E1 落地后，剩下一处结构性空白，本批 4 个候选全部是**联动型**（让已有系统互相读取），无一是新实体。
> 基线核对：实读 `data.gd` / `game_state.gd` / `game_main.gd` / `hud.gd` / `menu.gd` 与 SPR16 两份交付文档；最新提交 `9b6568b`、34 个 `.gd`、冻结 34/34、`production/sprint-18/` 原不存在。本文为唯一新增文件，**未修改任何现有文件**。
> 所引表名 / 函数名均为实读已有项；标「拟新增」者为设计提案，非既有 API。按约束不写行号。已封方向（第 12 房型 / 房间事件池、武器淬炼、`FLOOR_THEMES` 8→12 与第四位主题 Boss、每日固定词缀）不重提、不翻案。

## 〇、诊断：链是单向的，复盘数据是死胡同

- Sprint 16 把「局外印记 → 局内事件 → 局末复盘」接成了一条链，但 `last_run.oath` / `last_run.echo` 落盘后**只被 `menu.gd` 复盘页展示一次**，不回注下一局任何决策；`FLAVOR` 也只在首发现播报一次后永不复用。→ **跨局闭环缺一环**。
- 各系统**横向不互读**：`SQUADS`（编队）不读 `FLOOR_THEMES.rule`（主题规则），层签不读编队，`SHRINE_OFFERS` 三卡不读 `codex` 发现集，`FLAVOR` 不读 `OATH_CONDITIONS`。Sprint 16 补的是「纵向串联」，本批补「横向互读 + 跨局回环」。
- **自我决定论**：Sprint 16 主要补胜任（兑现度）与关联（手记）；本批 A 补胜任（可预判的准备）、B/D 补关联（世界持续在场）、C 补自主（上局的我影响这局的我怎么打）。
- **MDA**：Mechanics 已过饱和且零新增空间（红线锁死）；增量只在 **Dynamics** —— 制造「进层前的准备决策」「跨局的路线自觉」两类新决策情境；Aesthetics 落在 Challenge / Narrative。
- **支柱守线**：所有候选的产出一律是**信息 / 叙事层**，不给数值、不给最优推荐，从机制上规避主导策略与 P0 boon 自激。

## 一、落盘口径（跨批硬约束，涉及 `last_run` 的候选必读）

- `set_codex_last_run(stats)` 是**覆盖式**（整个 `last_run` 被 `clean` 替换）且末尾**自带一次 `save_codex()`**；`clean` 只收 `Meta.STATS_KEYS` 内键，越界键被静默丢弃。
- 因此**任何往 `last_run` 加字段的设计，必须在 `set_codex_last_run()` 之后追加、并再 `save_codex()` 一次**，且**不扩 `Meta.STATS_KEYS`**、不改该函数本体。Sprint 16 的 `_write_codex_replay()` 正是这个既有形态（写 `oath` / `echo` 后第二次写盘），**直接复用该位点，不要新增第三次写盘**。
- **读旧值须在覆盖之前**：跨局字段（如 C 的连绩）依赖上一局的值，而 `set_codex_last_run()` 会先清掉整表；故须在调用它之前把旧 `last_run` 快照到局部变量，再于 `_write_codex_replay()` 中写回。这是纯读取，零 rng、零计时。
- 新字段须同步 `save_codex()` / `load_codex()` 两端、沿用未知键过滤与负数钳制、验「写 → 读回一致」；**不调 `mark_codex`**、不碰 `UNLOCKS` / `CODEX_BOONS` / `STATS_KEYS`。

## 二、候选 A · 层签「本层形势」可展开层（联动型核心增量｜推荐）

① **动机 / MDA**：补**胜任** —— 把「进门才知道打什么」变成「进层前可准备」。Dynamics 新情境：**进层前的准备决策**（本层编队偏近战冲锋还是远程压制 → 决定是否留源石给圣所、是否敢进诅咒房）。不是预告最优解，只给性质信息，判断权留给玩家。
② **一句话循环**：进层读层签 → 展开一层看「本层编队倾向」→ 据此定本层资源 / 路线取舍 → 清层。
③ **挂接点**：`SQUADS` 的 `min_floor` / `weight` / `members`（`front` / `defuser` / `affix` 标记）、`FLOOR_THEMES.rule`、`pool_for_floor()`、`RELIC_SUFFIXES` 的 `effect=theme_hazard` 与 `ACTIVE_RELICS.effect_kind`（仅作呼应，不产推荐）、既有 `update_floor_sign()` / `hud.set_floor_sign()` 常驻标签与 `apply_ui_settings` 字号档、`FLOOR_THEMES.mark` 色盲通道。**拟新增**一张只读派生表（编队性质 → 一句提示），不新增实体。
④ **风险与 E1/E6**：**E1 关键** —— 只读 `SQUADS` **静态表定义**（按当前层 `min_floor` 过滤后按 `weight` 派生「倾向」），**绝不读实际抽中的编队、绝不提前触发任何抽取**；沿用 Sprint 16 C 已验证的 `update_floor_sign()` 刷新挂点（所有 roll 完成之后），`_smoke_fingerprint` 只含 rooms 坐标 + kinds → 指纹不变、零重定。**E6** 零计时。**坑 5** 零新增 `ACTION_DEFS` / 零新增资源（复用既有 Label 与字符串，不触 `GEN_NAMES`）。冻结规格零。**认知过载红线**：层签默认仍 2 项、新内容只在**可展开层**，字号档与色盲 `mark` 口径不得破坏，颜色不得为唯一编码通道。**主导策略红线**：提示只描述性质，不得写「建议带 X 遗物」。
⑤ **规模 M**（含展开层 UI；退化为只读静态一句提示则 S）。
⑥ **前置 / 不做理由**：需经主理人向程基岩确认「编队抽取发生在战斗房、层签刷新在其之前」这一时序，以及 `SQUADS` 候选集与真实抽取的语义差异可接受（文案用「倾向 / 常见」而非「本层就是」）。若用户偏好「不预告、纯临场反应」，沿用 Sprint 16 C 的裁定整体不接。

## 三、候选 B · 手记回转（低风险 S 级｜推荐顺手清）

① **动机 / MDA**：补**关联** —— 现在 `FLAVOR` 是「初见说一句就消失」的一次性消耗品；改为主题切换时在层签旁复用，世界从「只在第一次露面」变成「持续在场」。Dynamics 新情境：轻量的场所感（不改变数值，只改变玩家对「这层是什么地方」的注意）。
② **一句话循环**：进新主题层 → 层签可展开行显示该主题既有手记 → 读一眼 → 打本层。
③ **挂接点**：`data.gd FLAVOR` 的 `themes/*` 8 条、`mark_codex()` 既有首发现播报、`_apply_floor_theme()` / `update_floor_sign()`、`hud.set_floor_sign()`、`hud.flash_toast()`、`menu.gd _codex_section()` 手记行。**零新增表、零新增资源**（复用既有字符串与 Label）。
④ **风险与 E1/E6**：E1 / E6 / 坑 5 / 冻结规格**全零**（纯只读查表 + 既有显示通道）。**节流不得用计时**：以「本层 `theme.rule` 与上一层不同」的纯状态比较控制，不引入任何 `delta` / 冷却。**双播红线**：首发现已由 `mark_codex()` 播 toast，回转只走层签常驻行，避免同层两句重复。
⑤ **规模 S**。
⑥ **前置 / 不做理由**：几乎无，可与任何阶段同批；它是 A 展开层的文案地基（同一容器、同一口径），故推荐与 A 同批。若主理人判断层签已是 HUD 最挤的一行，则退化为只在图鉴页 `_codex_section()` 把手记行常显（零 HUD 改动）。

## 四、候选 C · 誓约连绩（跨局闭环｜自主）

① **动机 / MDA**：补**自主** —— 让「上局没兑现的誓约」成为下局选印记 / 定路线的依据，把 Sprint 16 的死胡同数据接成回环。Dynamics 新情境：**跨局的路线自觉**（继续这枚印记补齐，还是换一枚换打法）。
② **一句话循环**：局末复盘看到「连绩」→ 下局开局（印记页 / 层签）只读提示上局兑现状态与连绩 → 玩家决定续约或换向 → 本局按新选择计数 → 局末再落盘。
③ **挂接点**：`codex["last_run"]["oath"]` / `["echo"]`、`set_codex_last_run()`（**覆盖前快照旧值**）、`_write_codex_replay()`（**在其后追加并再 `save_codex()` 一次**）、`OATH_CONDITIONS` / `oath_fulfillment()`、`SIGILS` 的 `equipped`、`menu.gd` 印记页与复盘页。**拟新增**一个 `last_run` 平行字段（连绩计数），**不进 `Meta.STATS_KEYS`**。
④ **风险与 E1/E6**：E1 零（纯局外读写，不进指纹）、E6 零计时、坑 5 零新增、冻结规格零（`UNLOCKS` / `STATS_KEYS` 不碰）。**红线**：连绩**只作展示**，不回注任何局内数值、不调 `mark_codex`、不改 `CODEX_BOONS`、不碰 `variant="boss"`；否则复刻「兑现 → 变强 → 更易兑现」正反馈（P0 boon 自激）。**登记三件套**：① 写字段 ② 显示名 / 复盘分母核对（连绩**不入任何分母**）③ 可见效果断言（真调 `menu._build_codex()` 验渲染，不只验字段存在）。
⑤ **规模 M**（含跨局读旧值时序 + 复盘页渲染）。
⑥ **前置 / 不做理由**：需经主理人向程基岩确认「覆盖前快照」的挂点位置与 `codex.cfg` 双档隔离不被污染；**必须先按 §一 口径落地**。若不接受任何新增持久字段，退化为只读既有 `oath.done` 的「上局是否兑现」一行提示（S 级，不新增字段、不触覆盖式风险）——**推荐先走这个退化版验证手感**。

## 五、候选 D · 圣所熟客呼应（关联 / 胜任，S–M）

① **动机 / MDA**：补**关联**（我见过的内容会在抉择里被提起）与轻微**胜任**（辨识度提高，决策不再是纯读数值）。Dynamics 新情境：三选一时「这张牌我认识」的熟悉感，降低长文案的认知成本。
② **一句话循环**：进圣所 → 三卡中已见过的条目附一句既有手记呼应 → 做交换 → 抉择链照常落 `last_run.echo`。
③ **挂接点**：`SHRINE_OFFERS` / `_shrine_offers_for()`（**不动 `stable_hash` 派生 key**）、`shrine_panel` 三卡渲染、`codex` 五类发现集 `_codex_id_valid()`、`FLAVOR`、`menu.gd` 图鉴页。**纯只读查表，零新增表 / 资源**。
④ **风险与 E1/E6**：E1 零（只读发现集，不改三卡抽取顺序）、E6 零计时、坑 5 零新增、冻结规格零。**认知过载红线**：三卡 `desc` 已较长，呼应句只作可选灰字小行、不进主文案；不改变卡的代价与效果（否则动 `SHRINE_OFFERS` 平衡）。**登记三件套**：呼应显示名 / 白名单 / 「已发现才显示」的可见效果断言；Sprint 14 `icon_codex` 漏 `GEN_NAMES`、`bulwark` 表里有了但 `match` 漏分支，都是「表写了没接上」的同款根因。
⑤ **规模 S–M**（由呼应的条目数决定；只覆盖 3 主题 Boss 即 S）。
⑥ **前置 / 不做理由**：不臆造设定，沿用 Sprint 16 已拍板的「废弃矿窟的实用主义」基调。若用户希望圣所保持纯数值抉择、不掺叙事，整体不接。

## 六、推荐组合与阶段（延续「一核心 + 一顺手 + 一沉淀」）

| 阶段 | 方向 | 理由 |
|---|---|---|
| **一 · 核心增量** | **A 层签形势层 + B 手记回转** | B 是 A 展开层的文案地基，同一容器同一可访问性口径，同批共用一套断言与一次登记三件套；A 是唯一「制造进层前新决策情境」的 Dynamics 增量，且严格零 rng / 零指纹重定。 |
| **二 · 跨局沉淀** | **C 誓约连绩（先走退化版）+ D 圣所呼应**（依用户拍板取一或全取） | 两者都只读既有数据、不引入新状态；C 需先过 §一 覆盖式口径这道门，放在阶段二可避免与 A 的 UI 改动同批叠加。 |

**给用户的选择项**：① 只做阶段一（最稳，零持久字段）；② 阶段一 + 二全取（完整「横向互读 + 跨局回环」）；③ 只做 B + C 退化版（最小闭环，A 留到下批）。**推荐 ① 或 ②，锁定权在用户。**

## 七、明确不建议做（防范围蔓延）

1. **第 12 房型 / 房间事件池、`SHRINE_OFFERS` 再扩容到 12 条**：前者改 kinds → 指纹按预期代价重定、与 `shrine` 三卡同构，Sprint 13/15/16 三度列为备选未接；后者是典型「加实体且同类」，10 条已按 `min_floor` 分层、抉择链标签只有 4 类，再扩只会稀释辨识度并要同步 `SMOKE_SHRINE` 期望值 / 显示名 / 分母。两者都与「加关系」定位直接冲突。
2. **把誓约兑现度 / 抉择标签做成数值加成，或扩 `CODEX_BOONS` 到第五档**：会形成「兑现 → 变强 → 更易兑现」正反馈（P0 boon 自激同型），且 `CODEX_BOONS[*].kind` 若为 `suffixes` 是硬红线；任何数值奖励都会立刻产生「选某枚印记必优」的主导策略，需重做平衡。Sprint 16 定下的「兑现只给叙事 / 复盘层」边界不因跨局闭环而放宽。

## 八、待用户 / 主理人拍板项

- A 的「预告编队倾向」是否符合期望手感（同 Sprint 16 C 的「预告但克制」口径）；A 展开层是否会挤爆层签。
- C 是否允许新增 `last_run` 平行字段；若否，走「只读 `oath.done`」退化版。
- D 是否接受圣所掺叙事调性（沿用既有基调，不新造设定）。
- 阶段组合 ①/②/③。
- 经主理人向程基岩确认三处时序：`update_floor_sign()` 与编队抽取的先后、`set_codex_last_run()` 覆盖前快照旧值的挂点、`_shrine_offers_for()` 派生 key 不受 D 影响。**本文不臆造 API，实现前须重新实读挂接点行号。**
