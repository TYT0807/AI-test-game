## 二、语感对齐依据（引既有条目 + 为什么这么写）

**1. 结构范本**：既有 11 条里 8 条是 `【对象名】。+ 一至两个短句`，只有 `玄渊之主` 一条是 3 句（26 字）。本批 10 条**统一取最短范式**「名。事实／操作」，向这三条看齐：
- `"冰面。刹车提前半秒。"`（9 字）—— 最短、纯操作细节、不带评价 → 本批 4/6 号（"挡一下，就散了"／"刻上去的，抠不下来"）用的就是这种「一个动作 + 一个后果」的极简结构。
- `"岩浆层。地板本身就是敌人。"`（12 字）—— 纯事实判断、无建议 → 1 号「地窖里最不缺的就是血」同型：只陈述世界是什么样，不评价你好不好。
- `"毒沼。慢是慢了点，稳当。"`（10 字）—— 承认代价、但只作客观描述 → 10 号「手重了，人也就薄了」同型：承认 -1 上限这个代价，但不说"值不值"。

**2. 口语词取自已有条目**：`矿里人`（近 `矿脉层`）、`地窖`（`地窖图鉴`/`地窖碎片` 既有）、`石头`（`源石` 的口语化，既有 `源石淬炼` 名内即用「源石」）、`碎片`（`地窖碎片` 既有）、`规矩`（`毒沼` 的 `稳当` 同级的方言调）。**没有引入任何既有表里不存在的人/地/组织/器物名。**

**3. 「不给推荐语」的逐条自查**：
- 1「最不缺的就是血」= 世界的丰度事实，不指向"所以选它"。
- 2「矿里人管这叫喂石头」= 纯民间叫法，零褒贬。
- 3「散得掉」= 能力事实（能不能），不是"该不该"。
- 4「挡一下，就散了」= 时长事实，反而不美化。
- 5「缝两针，血就回来了」= 操作事实。
- 6「抠不下来」= 持久性事实（对上 -1 上限的不可逆），零评价。
- 7「老规矩了」= 惯例陈述，不说"划算"。
- 8「坑还是那些坑」= 地形事实（移速上去了，危险没少），既不捧也不踩。
- 9「地窖的账，只记碎片」= 记账规则（碎片才是地窖认的货币），是世界观事实不是选购理由。
- 10「人也就薄了」= 代价的直白说法。

**4. 明确没用的写法**（避坑记录）：
- 没用「血是自己的，东西是捡的」「石头下去，手艺上来」这类 A-B 对仗 —— 违反项目文风禁忌。
- 没用「建议 / 优先 / 最划算 / 别选」任何评价词。
- 没有把 desc 里的数值（-8 / -5 / -60 / 120 秒 / +30%）抄进文案 —— 数值留给卡面 desc，文案只给「待久了的人会知道的事」，避免与 desc 重复并在三卡下挤成第二行数字。

## 四、口径裁定与定性（已由主理人拍板，2026-11-08）

**1. 走恒显，因为「已发现」这条路在实现上不成立。**
本轮实读证据：`game_state.gd:279` `CODEX_KINDS := ["enemies","relics","suffixes","themes","bosses"]` 不含 `shrine`；`:293 _codex_id_valid()` 的 match 也只覆盖这五类；`:318 mark_codex()` 在 `:319` 有 `codex.has(kind)` 守卫。而 `SHRINE_OFFERS` 的 10 个 id 与这五类 id 全集无交集 → 「已发现才显示」对圣所选项**恒为假**，照原设计实现的结果是「表写了但一行都不出」（Sprint 14 `icon_codex` / `bulwark` 同款根因）。
另两条口径已否：**(b) 映射代理**等于主观发明一张「圣所选项 → 六类领域」的表，十件选项与「敌人/遗物/词缀/主题/Boss」对不上，写出来是硬凑，且形式上仍是「加实体」；**(c) `shrine_visits >= 2`** 会让第一次进圣所的玩家看不到任何一条，而首见恰是世界观传达最有效的时机，为一句「熟客」的措辞让掉不值，且它是本局计数、跨局语义弱。

**2. D 的价值主张据此改写：D 不参与发现度体系，它是独立的叙事层——「场所的持续性在场」。**
即：手记不是解锁奖励，而是**圣所这个场所一直有话说**——像矿工手记贴在墙上，你看或不看它都在。**D 与发现度之间零耦合**：`CODEX_KINDS` 五类不含 `shrine`，恒显路径不读任何发现状态、也不写任何登记。
**⚠️ 措辞红线**：**不得**写成「D 让原本无回报的发现度有机会变得有回报」或任何暗示 D 接上了发现度闭环的说法 —— 那会让人以为 D 有发现回报，而 `shrine_panel` 侧根本没有发现判定，核验时即构成**文档与实现不一致**。正确表述是：**发现度回路本轮仍未闭合，那是 C 的职责范围（且 C 走退化版后同样不闭合）。**
定性归入 **关联（Relatedness）**，不承担「胜任 / 发现度」的 KPI；也不声称它是「发现解锁系统的新分支」。这一条必须同步写进派单与交付文档，避免核验时按「发现度回报」的口径验收而判不达标。

**3. 恒显 ≠ 每次一样：内容仍随圣所变化。**

## 五、评审方法论沉淀（候选 A v2 → v3 复盘，供后续 HUD 类增量复用）

> 这段不是 D 的内容，是按主理人要求把本轮评审的三条结论固化下来，避免下批重犯。

**1. 静态派生表做不进 HUD 常驻位。**
数据源是常量表（`SQUADS` 的 `min_floor` / `weight` / `members`）→ 输出只由层号决定、跨局恒定 → 玩家跑两局就背下来，之后 HUD 那行等于噪音。**HUD 常驻信息必须每局可变**；恒定信息应放进图鉴 / 复盘页这种"玩家主动去查"的位置。判据：若它同一层每局输出都一样，就不该常驻 HUD。

**2. 选择序 ≠ 展示序。**
「挑哪几个」按稀有度/新颖度（唯一能挤掉恒真背景的排法），「谁排前面」按**实际遭遇概率**降序。两者混成一个 list，结果就是"最显眼的词 = 最不可能发生的事"（v2 里 7 层把 ≈50% 的 `回响` 排第一，而 100% 的 `远射` 被挤掉）。若只有一个字段（v3），此条不适用，但方法要留着。

**3. 层数触顶问题由数据源决定，不由排版解决。**
`SQUADS` 最大 `min_floor=7`，所以任何编队派生在 8 层以后必然与 7 层同值、永远撞顶。房型计数随房间数 `7+nf` 增长（`game_main.gd:360` / `:1420` 的 `generate(nf, frng, 7+nf)`），8/9/10 层各不相同，**天然绕开天花板**。选维度时先问：它的取值会不会在某层饱和？

### 本批落定口径（v3，已定死，不再补逐层示例文案）

- `floor_situation()` 整条删除 → 换成 `floor_layout_hint()`。
- 输出：`精英 3 ｜ 有诅咒房` / `精英 2` / `无精英`。
- 层签第二行：`本层 · 精英 3 ｜ 有诅咒房 ｜ <主题手记>`（房型在前、主题手记在后）。
- **只报数量不报位置**：返回值**不得**出现坐标或括号（硬断言，保"哪一间"的发现乐趣）。
- **无需节流**：`theme_for_floor()` 是 `4 + ((n - 4) % FLOOR_THEMES.size())`（`data.gd:403`），每层换主题、8 层一循环，不存在同主题连续多层，手记可直接显示，少一个状态变量。
- 时序：两处 `DungeonClass.generate`（`game_main.gd:360` / `:1420`）均早于对应的 `update_floor_sign()`，纯读可算；零 `Game.rng`。
- 信息依据：`ROOM_META` 里 `start` / `combat` / `elite` / `cursed` 的 `mark` 全是空串（`data.gd:297` / `:298` / `:299` / `:306`），小地图只靠 `mark` 字母编码房型 → 精英房与诅咒房玩家侧本就不可辨识，本项是补空白而非重复。
